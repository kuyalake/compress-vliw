1. 这四种方案到底是什么

E0（不压缩）：每个 PC 存一条 140-bit 完整指令，任何空槽也占位。

E1（纵向压缩）：D0…D4 各有自己的 bank，只保存该 slot 有效时的 20-bit 内容；另存 CTRL、长立即数和每条指令 7-bit config。为了核能替换任意程序，5 个 data bank 使用同一个深度，该深度由最拥挤的 slot 决定。

E2（等宽条带化）：先读 config 得到本周期哪些原始 slot 有效，再把这些有效内容依次分配到 N 个物理 lane。lane 不再永久属于 D0 或 D1，因此总事件能被均匀摊开。恢复时用 config 把 lane 内容送回原 slot，仍输出完整 5 槽指令。

E6（Multanen 风格并行字典）：每个 move slot 有独立可编程字典，命中字典的指令只保存各槽索引，多个压缩指令打包到一个 140-bit 字；不命中则保留原字。这里是根据论文机制独立实现，不是作者 artifact 的逐位复现。

E1 逻辑量 = 所有有效槽内容 + 每 PC 7-bit config；E2 逻辑量 = 同样的有效内容 + 同样的 config + 很小的程序描述符。E2 的优势主要发生在“映射到 SRAM 宏”之后，而不是凭空减少有效信息。

5. 为什么还要给 E1-RA / E2-RA 两行

这是本次复核发现的关键硬件风险。7-bit config + 压缩事件流足以按静态顺序恢复，并已 bit-exact 验证；但 CHStone/Embench 有分支和循环。若 PC 突然跳到任意指令，解码器还必须知道各压缩流应读哪个地址。只报告顺序流数字，会低估通用 TTA 的开销。

E1-RA 的保守直接方案在每个 PC 旁存 D0…D4、CTRL、limm 七条流各自的前缀地址。CHStone/Embench 池的 config 从 7 bit 变成 104 bit，宏容量达到 E0 的 124.9%，说明朴素随机访问会吃掉纵向压缩收益。

E2-RA利用条带的全局顺序，只需保存一个 data-lane 基址与 phase，再加 CTRL/limm 地址；config 为 52 bit。第 r 个有效槽的物理位置可用下面两个小运算得到，不需要五套独立地址：

lane = (phase + r) mod N；address = base + ((phase + r) ≥ N ? 1 : 0)

该直接方案的两个程序池均为 6.414 Mbit，即 E0 的 69.9%；CACTI 面积 1.925 mm²，比 E0 的 3.918 mm²低约 50.9%。它是保守、容易解释的上界，不等于最终最优设计：checkpoint + 小范围 popcount/rank 可能继续压缩地址元数据，但必须做 RTL 时序与分支气泡实验后才能声称更优。

7. SRAM 宏与 CACTI 细表

CACTI 7 使用 HP 32 nm、RAM、1R/W、1 GHz。所有宏 cycle time ≤1 ns。对很小的字典，CACTI 至少按 32 行/64 byte 建模；对 20/39/140 bit 行，实际阵列分别向上对齐到 32/64/256 bit。这使绝对面积偏保守，因此论文应同时报告逻辑 bit、2 次幂宏 bit 和 CACTI 三种口径。

  • 功能：14/14 通过；失败的第一版 ADF 已隔离。
  • 压缩恢复：每个程序和两个池的 E1/E2/E6 编码—恢复断言全部通过。
  • 时序代理：所有 CACTI SRAM 宏满足 1 GHz cycle time；这不代表解码组合逻辑已经满足 1 GHz。
  • trace 形式：计划写的是 bus trace。实际采用 SQLite instruction_execution 的逐周期 PC，再逐 PC 映射回 TPEF 的完整 move/limm；信息上足以重建每拍指令。曾生成的文本 bus trace 在 Mips 错误运行时迅速超过 3 GB，因此最终关闭，避免重复保存同一信息。
  • Mips：上游 CHStone 把 8 元素 A 越界读到 64，LLVM -O3 可合法优化出错误程序；最终使用 OpenASIP 自己回归树中将循环修为 8 次的版本。
  • Embench 名称：Multanen 论文实际列表是 Tarfind，不是原计划误写的 Tarjan。
  • Primecount：原作者的确切 Primecount artifact 未获得，本报告使用 BEEBS prime 代理并始终标注 proxy。

9. 对论文方向的判断

可以保留，而且切入点应调整。不要把跨平台贡献写成“稀疏所以 N 从 5 降到 4”；这批通用 TTA 程序不支持该断言。更稳健的主张是：等宽 slot 的纵向 bank 会因固定 slot 热度不均和 2 次幂深度量化而浪费容量；slot/lane 解耦的条带化即使保持 N=M、完全不损失性能，也能均衡 bank 深度。当某个平台进一步证明 N<M 不影响性能时，再把减少 lane 数作为第二级可选优化。
尚未达到可投稿硬件证据。E2-RA 已给出分支可用的保守存储组织，但 base/phase 解码、config 与 data SRAM 的流水、跳转重定向延迟、CTRL/limm 同步、综合面积和 1 GHz 时序仍需 RTL。当前 CACTI 不能替代这些逻辑结果。
  1. 第一优先级：实现 E2-RA RTL。输入 PC，第一拍读 52-bit config，第二拍并行读 5 lane + CTRL/limm，组合 crossbar 恢复 D0…D4；连续取指保持每拍一条。验证顺序、taken branch、loop back-edge、程序池切换。
  2. 做公平 E1 随机访问 baseline。至少比较：朴素 7 前缀地址、每 16/32 PC checkpoint + rank/popcount、以及不压缩但按 PC 直接读。否则不能只挑 E1-RA 的最差实现。
  3. 单独做 N=4 重调度。把机器改成最多 4 data move/拍重新 tcecc 编译，测真实周期，不用本报告的乐观拆分下界代替。当前动态下界已显示 CHStone +10.64%、Embench +4.02%，不能预设“几乎无损”。
  4. 综合逻辑并替换代理。用目标工艺综合 config 解析、base+phase、lane→slot crossbar、有效门控；SRAM 用真实宏或 compiler 数据。报告 critical path、门数、面积、动态功耗。
  5. E6 保持 baseline 身份。若要精确对齐 Multanen，需向作者索取 ADF、trace、压缩/地址重排代码；在此之前不要把机制级数字称为 reproduction。
