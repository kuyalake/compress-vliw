1. 先把“1/2/4-slot自适应”定义说准确

1.1 它不是三个离散mode之间切换

原始设想是1、2、4三种发射容量，但最终实现已经主动取消独立mode字段。真实硬件是四个物理共享payload Lane，由每周期5-bit mask决定本拍有0、1、2、3还是4个有效操作，并对没有使用的Bank关闭读使能。因此，更准确的技术名称是：

0–4槽占用自适应、逐Bank门控的四共享Lane确定性指令供给
“1/2/4”可以保留为方案简称，但论文正文必须说明3操作周期也被直接支持，否则容易被审稿人质疑名称与实现不一致。

1.2 编码和恢复过程

Config[4:0] = {LOAD, STORE, VECTOR, SCALAR, SFU}有效槽mask 00000 = 空周期 11111 = EOP（因此禁止同拍五槽全有效） active_slots = 按功能槽号升序排列的有效目标 physical_lane = (phase + payload_rank) mod 4 phase_next = (phase + popcount(mask)) mod 4

→

每个原始周期固定一项，不做变长bit解析。
→

这种设计没有FIFO、动态依赖判断或运行时发射仲裁。所谓“自适应”体现在：同一套硬件每拍根据mask只访问需要的1/2/3/4个payload Bank，状态只在ready/valid接受时前进。

2. 它解决的不是“少一个Lane”，而是一个一般性矛盾

Candidate A的普通纵向压缩为五类功能槽各设独立Bank。虽然删除了NOP，但容量仍按槽类型隔离：VECTOR Bank可能接近满载，SCALAR Bank却大量空闲；程序替换时不同槽的剩余容量不能互借。

自适应四Lane把问题重新定义为：

逐周期发射的超长指令具有低平均槽占用，但有效操作又分散在不同功能槽。如何在不引入变长取指停顿、且精确保持周期语义的情况下，让不同功能槽共享指令存储容量，并使实际SRAM访问数随每拍占用变化？

四共享Lane的价值有三层：

  1. 容量共享：五类槽的有效事件进入同一组四Bank，避免按功能类型产生的容量碎片。
  2. 性能保护：最多四发射覆盖当前全部关键schedule，不承担双Lane的平均周期损失。
  3. 访问自适应：物理上有四Bank，但平均每拍只读约一个payload；未选Bank必须具备独立read-enable。

因此，论文主张不应写成“从5个Bank减少到4个Bank”这么浅，而应写成容量虚拟化 + 占用自适应访问 + 确定性恢复。

3. 已有实验与本次重新核验

3.1 原plan已完成的有效证据

  • MAX_ISSUE=4下对6个函数、X=32/64、合法FUV mode和13种优先级执行364次调度搜索。
  • 12个选中schedule全部生成5-bit Config和4条34-bit流，并逐周期、逐槽bit-exact恢复。
  • 目标池5,766个有效事件分到1,442/1,442/1,441/1,441，满足4×2048固定容量。
  • 现有四Lane结果19,962周期，与当时的五槽参考逐测例相同；目标池5,456周期。
  • CACTI+GE模型包含四个独立Bank使能、mask/phase、4-to-5路由和从真实流统计的逻辑翻转率。

3.2 本次发现并修正“发射宽度超集”问题

最多四发射硬件必然可以执行任何合法三发射schedule。但原MAX_ISSUE=4贪心搜索在LayerNorm X64得到1,424周期，而新三发射搜索得到1,417周期。差异来自启发式搜索，不是架构能力。

本次把已有2/3/4/5发射候选schedule合并，先按周期选最短；周期相同时优先选择峰值发射宽度较小的schedule，再重新编码到四Lane。结果如下：

4.1 13.05%面积收益是否足以写论文

单看面积百分比，证据还不够稳。相对A-symmetric为13.05%，低于原plan给出的“真实SRAM+RTL仍下降至少15%”继续条件；相对A-compact更只有5.28%。但论文价值不应只押在一个面积数字上：

  • 相对双Lane，它用8.13%面积换回全部当前性能并减少约22%的SRAM读能量。
  • 相对A，它在更小总payload容量下反而显著提高域内程序池接纳能力。
  • 相对分组四Lane，在统一物理配置口径后面积/能量接近，却消除双发射schedule的性能限制。

因此论文应呈现面积—能耗—周期—池接纳率四维Pareto，而不是只写“面积降低13%”。RTL后若面积收益掉到5%以内，且接纳/能耗优势也不稳定，就不值得单独成文。

6. 创新性重新判断：可以成立，但必须避免两个错误说法

6.1 不能说“首次动态调节VLIW发射宽度”

Brandon与Wong，DATE 2013已经研究2/4/8 issue-width动态适配和generic binary；Brandon等，ReConFig 2015还实现了稀疏VLIW、stop-bit、dispatch routing和FPGA验证。本方案也并没有在运行时把四Lane物理核重构成1/2/4个核，而是每拍按占用门控Bank。

所以“动态发射宽度”既不准确，也会把论文带入已有工作最密集的区域。

6.2 不能说“首次纵向压缩和单周期恢复”

Li等，IEEE Access 2020已经提出VLIW子字段纵向删除NOP、Banked instruction memory和每Bank地址生成器，并给出65 nm综合。Candidate A是直接且必须认真对比的先例。

6.3 可以争取的创新边界

固定周期配置流下的跨异构功能槽Bank共享：把五种等宽功能操作循环条带化到四条物理事件流；用target mask前缀计数和phase确定性散布；每拍按实际占用独立门控Bank；在真实SRAM宏块深度、程序池替换和周期SLA共同约束下选择组织。

与变长VLIW不同，它不需要跨cache-line拼接或顺序解析变长bundle；与A不同，它允许不同功能槽借用同一物理Bank容量；与动态issue-width generic binary不同，它不拆分同一bundle跨多拍，而是让编译器生成最多四发射schedule并保持一Config项对应一个执行周期。

这个组合有一定新意，但“mask+共享payload+crossbar”仍可能被老专利或工业DSP覆盖。投稿前要继续检索mask-word instruction storage、instruction dispersal network、silo/flexible-silo、bank folding和compressed bundle dispatch。

Sidecar相对四Lane面积低约19.1%，但接纳子集几乎减半，而且第四事件总容量被限制为128。它适合形成论文中的“容量受限优化”或消融：当工作负载分布已知且四操作周期极少时，可以用浅尾部Bank换面积；当强调未知程序替换时，应保留完整四Lane。

对上一版推荐的撤回：在没有先定义程序替换合同、也没有比较接纳集合之前，把三Lane+Sidecar直接列为主方案是过早的。重新实验后，主方案应仍是自适应四Lane；Sidecar只是Pareto上的面积优化点。

9. 建议的小论文问题、标题和贡献

9.1 推荐标题方向

Bank-Shared Occupancy-Adaptive Instruction Supply for Deterministic VLIW Accelerators
中文可写：面向确定性VLIW加速器的共享Bank占用自适应指令供给方法

不建议把“1/2/4”放在论文主标题里，因为它容易被理解成动态issue-width核心重构，而真实贡献是四Bank的逐周期占用自适应和容量共享。

9.2 建议的四项贡献

  1. 问题建模：揭示普通纵向压缩删除NOP后仍存在“按功能槽隔离的Bank容量碎片”，并将周期、宏块面积/能耗和程序池接纳率共同纳入目标。
  2. 架构：提出5槽到4共享Lane的固定配置流、phase条带化与4-to-5确定性散布结构；每拍只激活popcount(mask)个Bank。
  3. 编译协同：限制最多四发射，使用跨issue-width候选并集保证搜索单调性；以周期为第一目标、宏块/高宽度占用为第二目标。
  4. 系统评估：与A、双Lane、分组四Lane及容量受限Sidecar比较面积、周期、能耗、峰值时序、池接纳和控制流状态。

9.3 与前三篇串联

第三篇给出逐周期超长指令驱动的可编程非线性加速器；第四篇直接解决该架构的指令存储面积、访问能耗和程序替换问题。第二篇提供非线性负载来源，第一篇作为更早的VLIW/可编程架构基础被保留但弱化。大论文主线可以是：

非线性计算需求 → 可编程VLIW执行 → 低利用率超长指令瓶颈 → 共享Bank、占用自适应的确定性指令供给。

1/2/4自适应是否比双Lane更接近论文主方案？是。它保留当前最佳性能、降低深Bank能耗，并具有更强的池接纳一般性。
当前是否已经足以投稿？否。CACTI+GE和12条同源trace不足；缺RTL、真实宏、外部负载和控制流。
面积只有约13%是否太小？若只写面积，偏弱；若RTL确认并同时证明能耗/周期/接纳率四维Pareto，则足以构成小论文。
三Lane+Sidecar是否应替代它？不应。Sidecar是面积优先、容量受限派生点；四Lane是可替换池的通用主方案。
