OpenEdgeCGRA：四lane条带化＋外部phase_q的程序池鲁棒性、已有压缩方案与CACTI复核

日期：2026-09-14。实验固定OpenEdgeCGRA官方仓库commit 4a179fcf6faee18765f66baa0a30af91e3840728，保持4个逻辑row槽与4条物理lane，不限制并发、不改变原始调度。CCF不再作为论文实验平台。

1. 结论先行

建议保留OpenEdge扩展实验，但必须把论点从“总能得到接近50%的SRAM收益”改成“在不改变调度和吞吐的条件下，消除固定row之间的容量不均衡；跨过宏深度档位时收益很大，没有跨档时仍有较小的容量收益”。
  • phase_q不占配置存储。它与程序起始addr一起由启动接口输入，只初始化一个2-bit运行态寄存器。因此E1与E2的有效逻辑信息完全相同：都是每个context 4-bit mask，加上全部非NOP的32-bit row word。12池二者均为34,032 bit。
  • 12池的正结果仍成立：E1固定row负载为266/255/244/255，最深266；E2经phase后为255/255/255/255，达到理论下界255。若Bank补到2次幂，payload从4×512降为4×256，E2相对E1面积下降37.73% 。
  • 保守口径：不强制2次幂、直接用CACTI建266深和255深宏时，E2相对E1的SRAM面积下降3.69%，一次池能量下降1.00%。论文应同时报告这组数字。
  • 不是挑一个有利池：穷举全部4095个非空mapping子集，E2最深lane在4095/4095个子集中均不超过E1最热row；216个子集跨过2次幂档位，3879个同档，0个更差。12折leave-one-out中6个仍跨档。
  • 程序到达顺序也不破坏结果：穷举全部479,001,600种到达顺序，loader每次只根据当前四个bank占用选择q，100%顺序都能装进256深Bank；93.27%达到255/255/255/255，其余为256/255/255/254。
  • 必须正视完整context字典：12池只有114种不同128-bit context，静态字典的SRAM数字显著优于E2。但它是封闭池、值相关、两级读取的乐观上界；新程序若出现新context，需要更新字典并重编码索引。E2则只看NOP位置，程序值和程序池变化不改变解码规则。

2. E2到底保存什么：修正phase_q口径

每拍先读取4-bit mask。mask指出原来四个row中哪些有效；有效word按row编号从小到大得到rank=0、1、2或3。第rank个有效word来自：

lane = (phase + rank) mod 4
phase_next = (phase + popcount(mask)) mod 4

程序启动时，上层控制器已经要告诉CGRA“从哪个addr启动”。本方案把2-bit phase_q作为同一次启动命令的另一个输入，并装入phase寄存器。这里的addr接口必须足以初始化四条lane各自的读指针——它可以是四个lane基址，也可以是能无损推导这四个基址的统一编码；这部分按用户给定的现有程序启动信息处理，不另计Config RAM。phase_q既不逐拍保存，也不放入Config RAM。因此：

E1逻辑bit = E2逻辑bit = 4 × context数 + 32 × 非NOP word数

硬件并非绝对“零开销”：仍需要2-bit输入端口/控制字段、2-bit寄存器和phase更新逻辑。但这些是组合逻辑与状态位，不是程序池配置SRAM容量。后续RTL综合必须计入逻辑面积，软件容量表不应每程序加2 bit。

本轮假定程序装载/启动软件已经持有addr与phase，并采用与E0/E1一致的口径，不把主机或软件中的程序目录计入Config RAM。动态删除程序后产生的Bank空洞、free-list与是否压实尚未建模；论文若强调运行时任意替换，需要把“只在整池重装时重排”或“支持在线空闲块管理”二者说清楚。

4. 五类压缩方法在OpenEdge上怎样实现

4.1 E1固定row纵向压缩与E2条带化

E1为每个逻辑row建一个payload流：row 0的有效word永远写Bank 0，依此类推；4-bit mask负责恢复NOP。为了保持Bank结构统一，四个Bank都必须按最热row定深。E2保存的信息不变，但把同拍有效word依次写入从phase开始的lane，解码后再散布回原row，因此存储lane与逻辑row解耦。

4.2 静态完整指令字典怎样构建，是否有论文

  1. 把同一context地址的四个32-bit row word拼成一个128-bit完整context。
  2. 扫描整个常驻程序池；首次见到一种128-bit值时，将它加入字典并分配编号。
  3. 本池共114个字典项，所以每个原context用7-bit索引表示。
  4. 硬件先从索引SRAM读7-bit编号，再用该编号并行读取四个32-bit字典Bank，重建128-bit context。流水化后可以每拍输出一个，但启动/跳转至少涉及两级存储路径。

这个具体“把OpenEdge完整128-bit context作为字典项”的实现是本实验构造的强基线，不应声称复现了某一篇论文。它属于经典dictionary code compression；可引用Lefurgy等MICRO 1997的Improving Code Density Using Compression Techniques作为基础文献。VLIW领域还可引用Xie等2006的variable-to-fixed code compression。Multanen 2024则是更接近本问题、且能运行时改字典的现代方案。

当前CACTI表对静态字典是偏乐观的：计入索引SRAM和四个字典Bank的读能量，但未综合两级地址路径、流水寄存器、分支重定向、字典更新控制。它适合作为“封闭池可达到的强上界”，不能只凭该行CACTI SRAM就宣称完整系统一定优于E2。

4.3 Lee 2018：论文完整方法与本次可复现部分

Lee等2018针对逐周期读取超宽context的模调度CGRA。原方法先在编译器中利用inactive entity的don't-care周期，把配置值向前或向后传播，使多个硬件实体尽量在同一周期改变；再把超宽context按统计相关性做entity级分区。每个分区保存“发生变化的新值流”和逐原周期的1-bit decompression-offset，并有独立压缩PC。值不变时不读新payload，保持上一值，因此可无额外输出周期地恢复。

OpenEdge没有论文所用的SRP编译器、entity级don't-care信息和247个loop数据。本实验只能做一个严格无损子集：将四个现成32-bit row各视为固定分区；若当前row word与上一拍完全相同，change mask写0并保持，否则写1并保存新word。每个程序边界重置为NOP，所有trace均逐拍恢复验证通过。

  • 12池共4×348=1,392个row位置；固定row时间保持仍需保存1166次变化，逻辑bit为38,704。
  • 2次幂宏下它与E1都需要4×512 payload，但读取次数更多，CACTI一次池能量为1.826 nJ，高于E1。
  • 这只能说明“Lee的原始trace固定row子集不适合OpenEdge这12个mapping”，不能声称完整Lee算法比E2差；完整复现必须重建字段级entity、证明don't-care传播不改变功能，并实现其调度器和分区器。

4.4 Multanen 2024：在OpenEdge上的机制级实现

Multanen等2024把指令切成多个字段，每个字段有独立小字典。进入适合压缩的控制流区域前，header后跟dictionary frame，运行时把本区域常用字段写入字典。随后，若连续B条指令的所有字段都能命中字典，就把这些索引打包进一个与原指令等宽的固定bundle；无法命中的指令保持raw。固定bundle避免任意变长取指，但frame装载会停顿。

映射到OpenEdge时，本模型建立四个32-bit row字典。原论文的TTA把62-bit原指令扩成64 bit来容纳2-bit控制标记；OpenEdge原context已经是完整128 bit，因此本实验不能假设有免费空位，而是增加独立的2-bit raw/compressed/header tag流。CACTI按最小8-bit物理字宽计算该tag SRAM。搜索后选择每row 32项，索引总宽20 bit，因此一个128-bit bundle可容纳6个原context的四路索引。由于原作者CFG region builder和精确entry-selection代码未公开，本实验将每个mapping作为一个region，用可复现启发式选择字典项，并完整模拟raw旁路、frame和恢复；这是机制级模型，不是原作者编译器复现。

在这一保守口径下，E2的绝对面积为0.010715 mm²，E1为0.011126 mm²。E2仍优于E1，但不再是37.7%的巨大差距。静态字典仍最小；Multanen模型面积与E2接近，但一次池能量比E2高14.25%，且含frame停顿。功耗较低部分来自运行时间变长，不能只看平均mW。

7.3 程序按未知顺序到达时，phase_q怎样选

不必预先为每个程序永久保存phase。loader知道当前四条Bank尾地址，程序到达时只试四个q，选择让装载后最深Bank最小的那个，然后把q与对应的lane基址信息一起传给启动接口。本实验用状态动态规划精确统计全部12!种到达顺序，而非随机抽样。

  • 总顺序：479,001,600。
  • 得到255/255/255/255：446,757,120种，占93.268%。
  • 得到256/255/255/254：32,244,480种，占6.732%。
  • 所有顺序均不超过256深，因此2次幂SRAM组织不依赖一个精心挑选的装载次序。

8. 能否构造“审稿人不会质疑、又更有利”的扩大池

不能把复制同一mapping、循环移位row、随机修改立即数或使用deprecated旧ISA文件包装成更多benchmark。复制代码本可共享，不应重复占容量；row轮换会改变物理PE和通信位置；修改立即数可能改变控制流或程序语义。这些做法容易被审稿人直接否定。

当前公开数据能做的最强、且可审查的实验就是：

  1. 7个真实应用mapping作为非挑选的功能集，诚实报告同档结果；
  2. 全部12个官方mapping作为context-memory容量压力池，明确其中5个是测试/压力程序；
  3. 全部4095子集、12折leave-one-out和全部12!到达顺序，证明满池结果不是由单个样本或特定顺序人为制造；
  4. 同时报告2次幂宏和不取整CACTI，隔离“负载均衡本身”和“跨深度档位放大”两种收益。

若论文还需要真正扩大benchmark数量，唯一稳妥路径是新增独立、功能可验证的OpenEdge mapping：选择PolyBench/MachSuite等循环kernel，按当前32-bit ISA映射，生成instructions_*.py，用官方行为模拟器对照C参考输出，再纳入池统计。OpenEdge当前没有公开自动mapper；这会是新的手工映射工作，不能由本轮软件压缩脚本凭空生成。

9. 对论文叙事的影响

建议主张：“针对逐周期、多等宽槽、统一Bank深度的配置存储，提出值无关的slot/lane解耦。外部phase输入消除程序边界偏置，在不减lane、不改调度、不中断一拍一context恢复的情况下，把固定slot峰值容量转化为接近总有效word数/Bank数的均衡容量。”
  • 不要主张E2压缩的信息熵低于E1：两者逻辑bit完全相同；创新在物理Bank容量均衡和可替换程序池。
  • 不要只报512→256：必须同时报266→255的exact-depth CACTI结果。
  • 静态字典是closed-world压缩上界；论文的价值需要通过未知程序替换、固定周期恢复、单级数据读取和RTL逻辑开销来与它区分。
  • Lee完整方法可能通过编译器don't-care优化得到更强结果，应诚实标注本次只是固定row、原始trace子集。
  • Multanen应报告冷切换和重复执行两种摊销口径；当前frame开销不能代表长时间重复kernel的最终能耗。
