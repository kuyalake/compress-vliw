可获取指令 trace 的公开 VLIW 平台调研（指令压缩用）

日期：2026-09-14 ｜ 目的：为 E0/E1/E2/字典指令压缩寻找"能拿到逐周期多槽指令 trace"的公开 VLIW 平台（FRV 主平台之外的独立对照）。检索范围：公开工具链、学术论文、模拟器文档（网络检索 + 本地 paper/ 参考文献）。

核心结论（2026-09-14 二次修正）：两条硬性筛选条件收敛了平台选择：（a）本地 SRAM 程序池（§1.5，排除 cache 层次的通用 VLIW：ρ-VEX/Patmos/Hexagon/C6000/Itanium）；（b）slot 有固定功能/空间身份、不能免费互换（§1.6，排除对称 TTA——等宽+可互换会让编译器把各槽排匀，E2 相对 E1 无收益）。两条都满足的是 FRV（主平台）+ CGRA 类（固定空间身份）。OpenASIP 等宽 TTA 路线已放弃（§1.6）。以后不再考虑（对称）TTA。

1. 评估维度

  • 真 VLIW：静态调度、每拍多槽并行发射；
  • 逐周期 trace：能导出每拍哪些槽有效 + 各槽 payload 值；
  • 槽等宽：利于 E2（无位宽惩罚）；
  • benchmark：有可得的真实/标准程序；
  • 可构建性：工具链能否在我们的环境（Linux）跑起来。

1.5 架构模型匹配性（关键修正，2026-09-14）

这是比"槽宽是否齐"更根本的筛选条件。本文 E0/E1/E2/字典的隐含前提是：程序池整个驻留在本地片上 SRAM（L0/IMEM/程序池），处理器每拍直接从这块 SRAM 取指；压缩的收益 = 这块 SRAM 的容量（面积）+ 取指能耗。这是"可编程加速器 / SFU / ASIP 本地指令存储"模型。
本文模型（本地 SRAM 程序池）通用 VLIW 处理器（cache 层次）
指令驻留全程序在片上 SRAM主存 + I-cache 工作集
压缩对象本地 SRAM 容量 + 取指能耗I-cache 缺失率 / 取指带宽 / 主存代码大小
典型场景可编程加速器 / SFU / ASIP 本地指令存储通用 VLIW 处理器
对应 prior art较少（本文主战场）拥挤：Wolfe(Huffman)、Conte(TINKER/MultiOps)、Lefurgy、Benini、Multanen 本人

后果：若把 E2 搬到 cache 层次的通用 VLIW（ρ-VEX/Patmos/Hexagon/C6000/Itanium），就从"加速器本地程序池压缩"漂移到了"cache 代码压缩"——后者是拥挤的成熟领域，新颖性被稀释，且问题定义改变。因此通用 VLIW 不宜作为主平台。它们最多作为"等宽槽 + 稀疏峰值"的参考，不能作为本文压缩模型的直接对照。

本文模型下的匹配平台：FRV（主平台）、OpenASIP TTA（IMEM 为本地 SRAM，Multanen 字典即压此层）、CGRA（OpenEdge context memory、CCF 指令 bin），以及下文 §3.5 新检索到的本地程序存储平台。

1.6 理想外部平台判据（含放弃等宽 TTA 的原因，2026-09-14）

为什么放弃"等宽 TTA"路线（见 openasip_equal_width_tta_chstone_embench_e0e1e2e6_plan_2026-09-11）： 若把目标机器做成"各槽等宽 且各槽可随意互换"，编译器在调度时就能把各槽排得更均匀——各槽负载被人为拉平后，E1（纵向压缩）已接近最优，E2 条带化相对 E1 就没有额外收益了。E2 的收益来源恰恰是"槽有固定身份、编译器不能免费重排"所造成的稀疏/不均衡。所以对称等宽 TTA 反而把 E2 的优势条件破坏掉了。以后不再考虑（对称）TTA。

理想外部平台应同时满足（关键是第 3 条）：

  1. 每周期输出完整宽控制字；
  2. 逻辑 slot 等宽，或可按少量宽度类别划分；
  3. slot 具有固定功能或空间身份，不能免费互换（关键——它保证编译器无法把各槽负载拉平，从而保留 E2 相对 E1 的条带化收益空间）；
  4. 指令中存在明确 NOP；
  5. 每周期有效 slot 峰值明显小于总 slot 数，或各 slot 长期负载明显不均；
  6. 有公开 RTL、映射结果或逐周期 trace；
  7. 没有已经使用等价的共享 bank 压缩。
用第 3 条反过来评估已有平台：
  • FRV：满足——LOAD/STORE/VECTOR/SCALAR/SFU 是固定功能身份，编译器不能把 LOAD 挪到 STORE 槽；
  • CGRA（OpenEdge/CCF）：满足——每个 PE/context 槽有固定空间身份（PE 位置）；
  • 对称 TTA：不满足——任一 move 可上任一总线，编译器可自由均衡各槽；
  • 经典 VLIW（ρ-VEX/Patmos/Hexagon/C6000）：部分满足——槽↔FU 类型有固定映射（如 slot0=ALU、slot1=MEM），但同类型槽之间常可互换，且它们是 cache 模型（§1.5），双重不匹配。
结论：判据 3（固定 slot 身份）+ §1.5（本地 SRAM 程序池）共同把筛选收敛到 FRV（主平台）+ CGRA 类（固定空间身份）；对称 TTA 与通用 cache VLIW 都被排除。

3. 关键洞察：经典 VLIW 的等宽槽正好消除 TTA 的位宽惩罚

我们在 OpenASIP TTA 上发现 E2 的"位宽异构惩罚"（lane 必须按最宽槽设计，浪费 1.35–3.01×）。经典 VLIW 的每个槽是等宽 32-bit syllable（VEX/ρ-VEX/Patmos/Hexagon/C6000 皆然），所以搬到这些平台后 E2 不再有宽度惩罚——这正是 E2 的"槽宽齐"胜出条件在真实公开 VLIW 上天然成立的地方。但注意（§1.5）：这些经典 VLIW 多为 cache 层次结构，与本文"本地 SRAM 程序池"模型不匹配——等宽槽的优势只有在"本地程序存储"的平台（如 R-Blocks、CGRA context memory）上才对本文有意义。

3.5.1 CGRA 指令/context 压缩 prior art（本文 related work 直接相关）

这批工作就在"本地配置/指令存储压缩"上，是本文最近的邻居，必须在 related work 中对齐：

  • Aslam et al. 2008（TVLSI）：CGRA 指令码字典压缩，4×4 阵列平均 CR 0.56；按局部性重排/分组码位、按 kernel 自适应重装字典。
  • Kim & Mahapatra 2009（TVLSI）：CGRA 动态 context 压缩（低功耗）。
  • Lee et al. 2018（ACM TACO，本地 paper/ 已有全文）：模调度压缩/解压，分区配置存储 + 各分区独立 PC/offset 恢复。
  • MorphoSys / RoMultiC / FloRA：行/列广播、多播位图减少配置存储与取指。

定位提醒：本文 E2 与这些 CGRA context 压缩的区别在于——它们多依赖"同值广播/多播"或"字典"，而 E2 是"逻辑槽→物理 lane 解耦的条带化存储"。对照时应强调 E2 不依赖值重复、逐拍精确恢复、且面向"每拍有效槽稀疏"的冗余。

4. 建议的优先级与下一步（2026-09-14 修订）

  1. 主平台仍是 FRV（真实 NN 负载、本地程序池、有 RTL/综合）。
  2. baseline/反例仍是 OpenASIP TTA（Multanen 字典机制 + 稠密 FFT 反例）。
  3. 新增同构对照首选 R-Blocks：OpenASIP 系 VLIW-SIMD CGRA + 本地 scratchpad，与本文流程天然兼容（ttasim trace），且有 22nm 能效数据。但 2026-09-14 查证其不开源（内部版 OpenASIP + 自研翻译器/后端，无公开仓库）——要用需联系作者。注意：退回"自造等宽 TTA"的路线已放弃（§1.6：等宽+可互换的槽会让编译器把各槽排匀，E2 相对 E1 无收益）。
  4. 对称 TTA 不再考虑（§1.6 判据 3：slot 须固定身份、不能免费互换）。
  5. CGRA context 压缩 prior art 进 related work（Aslam 2008 / Kim 2009 / Lee 2018 / MorphoSys / RoMultiC），明确 E2 与"广播/字典"路线的区别。
  6. 通用 VLIW（ρ-VEX/Patmos/Hexagon/C6000/Itanium）不作主平台；如要引用，仅作"等宽槽"参考，并明确标注其 cache 模型与本文不匹配。
与既有工作的关系（2026-09-14 二次修正）：本文的平台分层为——FRV（主平台，真实 NN 负载、本地程序池、固定功能槽身份）证明 E2 的硬件收益；OpenASIP TTA（Multanen 字典机制 + 稠密 FFT）给出 baseline 与反例；CGRA（OpenEdge/CCF，固定空间身份槽）给出边界。对称等宽 TTA 因 slot 可自由互换、编译器可把各槽排匀，使 E2 相对 E1 无收益，已排除（§1.6）；通用 cache VLIW（ρ-VEX/Patmos/Hexagon/C6000/Itanium）因非本地程序池，亦不作主平台（§1.5）。相关工作的指令压缩鼻祖（Conte 的 TINKER/MultiOps，NOP-free + silo cache，IMPACT 编译器 + SPEC92/95 trace 驱动）与 CGRA context 压缩（Aslam 2008 / Kim 2009 / Lee 2018 / MorphoSys / RoMultiC）可作为 E2 的经典对照写进 related work。
