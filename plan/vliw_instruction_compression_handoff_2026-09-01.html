FRV-SFU-VLIW 指令压缩研究 Handoff

面向不熟悉项目的接手者：问题、证据、创新边界、实验数据和下一步工作的一站式说明

编写日期2026-09-01
当前阶段可行性预研 / Trace 审计
项目状态黄色：方向可行，创新尚未锁定
实验规模6 workloads × 2 个 X = 12 traces
阅读本文件时最重要的口径 本项目同时讨论“外部压缩文件大小”“加载后的逻辑有效位数”和“实际片上 SRAM 宏面积”。 三者不是同一个指标。当前 Trace 实验能严格给出前两类逻辑位数，但尚不能替代 SRAM compiler 与 RTL 综合结果。

1. 执行摘要

目标平台是已有论文提出的 FRV-SFU-VLIW 非线性函数加速器。编译器把 Softmax、LayerNorm、GELU 等函数表示为 DAG，静态调度器在不同 FUV mode 下生成确定性的、 逐周期执行的 184-bit VLIW 指令流。宽指令包含五个执行槽和一个 4-bit 控制槽。 由于不同功能单元活动密度差异很大，大量位用于 NOP，形成明确的压缩动机。

研究目标不是普通“代码文件压缩”，而是让压缩指令直接驻留在片上指令存储中， 前端每周期恢复出与原调度行为一致的完整 VLIW，不允许因为解压产生停顿。方案还必须在四个月、 单人可完成的范围内，压缩率优于 Li et al. 2020 的纵向压缩基线，并且解压硬件足够简单。

目前已经被数据支持的事实

  • 位宽加权槽位利用率只有 9.3%–30.7%。
  • 不同槽的事件数高度不均衡，存在明显的异构压缩机会。
  • 字段相邻周期重复率为 49.4%–69.6%。
  • 字段 Shannon 熵下界为原始字段位数的 37.8%–60.9%。
  • 12 条字段 codec + 原始 timing delta 软件往返均逐 bit 恢复原始 Trace。

目前最重要的否定性结论

  • 不存在覆盖所有 workload 的“通用稳定周期核”。
  • 仿射地址/寄存器再生不能作为通用主创新。
  • gap 字典相对修正后的 5-bit 功能 mask + 隐式 EOP 基线仅多约 2.9% 的算术平均逻辑收益。
  • 10.02% 字段混合结果是逐 workload、逐字段自由选择 RAW/DICT/DELTA 的 oracle 下界，不能证明存在跨 workload 通用 codec。
  • 独立槽流、NOP 删除、Mask、字典和差分本身均有直接先行工作。
  • 当前 11.6% 字段混合结果是软件上界，不是已实现硬件结果。
当前最合理的主线 以简单的 5-bit 功能 mask + 隐式 EOP + 五个执行槽 RAW 紧凑 payload 作为跨 workload 的统一前端， 优先研究异构物理存储组织以及确定带宽、零停顿供给。 1–2 bit 固定地址 delta + RAW escape 只作为后期小优化；必须报告其加法器、状态和 MUX 成本，不能用 10.02% oracle 结果替代真实格式结果。

2. 平台与问题定义

2.1 原平台

原论文 A Fully Reconfigurable and Programmable VLIW Architecture for Nonlinear Function Acceleration 提出 FRV-SFU-VLIW：RFU 向量数据通路与轻量 SFU 通过 Function Unit Virtualization（FUV） 在多种 mode 间重配置；Static Multi-Mode Scheduler 对函数 DAG 做周期精确调度并生成 VLIW。 当前压缩研究必须保持原调度和数据通路语义，不能通过修改运算顺序“制造”压缩率。

原平台采用 TSMC 28 nm、目标 1 GHz，论文报告核心面积 4.019 mm²、功耗 3.61 W； 其中 VGPR 为 2.031 mm²（50.5%），Decoder/Crossbar/Others 为 0.166 mm²、0.156 W。 论文没有单列 IMEM 容量、面积或功耗，因此压缩研究不能从原 Table V 直接推导存储收益。

4.1 Li 2020 的三个存储口径

外部压缩文件各列有效数不同，保存前把短列补齐到最高列；另存 ifnull 和 profile。本项目当前主比较公式采用这一口径。
片上逻辑有效量论文说明加载到独立 bank 后可删除填充 NOP，因此逻辑有效量接近各列非 NOP 位数之和加 FIR。
物理 SRAM真实面积受 bank 深宽、最小宏、端口和容量取整影响。Li 报告综合时将 IMEM 容量设为原来的 50%，并报告 IMEM 面积降低 44.26%；不能直接用 29.85% 逻辑 CR 推导面积。
当前 Li 外部总存储模型： S_Li = 184 × Hmax + 6 × T + 64 T = 原始 VLIW 周期数 Hmax = 六个 slot 中最高的有效事件数 6 × T = ifnull 数组 64 = 当前模型中的 profile 预算（需按最终格式复核）

5. 当前关键决策与原因

保留并修正5-bit 功能 mask + 隐式 EOP。五个功能槽共有 32 种组合；CONTROL 只在最后一条 EOP 指令为 1，因此由函数总周期数隐式产生，不必逐周期保存第六位。含 32-bit 周期数字段后的算术平均逻辑比例为 22.57%，加权比例为 21.74%。
不进入主格式mask 模板压缩。4-bit 模板 + escape 在 12 条 trace 上平均约 4.09 bit/cycle，相对固定 5-bit 仅省 0.91 bit/cycle；总容量只下降约 0.50 个百分点，尚未扣除模板表和 decode MUX。
降级固定 gap / gap 字典。仅作为消融实验；gap 字典相对修正后的 mask 基线平均只多约 2.9% 逻辑收益。
否决通用稳定周期核。Softmax 与 LayerNorm 的严格结构核覆盖低于 4%，不满足通用方案条件。
可选周期 fast path。可用于 GELU 等规则 workload 的上界或附加模式，但不能代表全部函数。
降为 oracle通用字段混合编码。普通值字典和逐 workload 训练的寄存器 delta 表不能作为通用非线性计算方案；10.02% 只保留为压缩潜力下界，不进入主格式。
后期小优化固定小 delta fast path。仅考虑 LOAD/STORE 的 28-bit mem_addr 与 8-bit gpr_addr，以及 SFU 的 8-bit dst/src。默认仍为 RAW；命中固定的 1–2 bit delta 编码时做模加，未命中时用 escape 并补充完整地址。该模式必须对所有 workload 使用同一格式和同一组硬连线 delta，不能逐 workload 建表。
delta 码宽与 escape 必须一起计算： 若 escape 占用同一个 b-bit 码字，则最多只能容纳 2^b−1 种常用 delta； 例如 2-bit 码只能表示 3 种 delta + 1 个 escape，1-bit 码只能表示 1 种 delta + 1 个 escape。 若要让 2-bit 覆盖完整 4 项 delta，则必须另存 escape 标志/位图，实际事件开销不再只有 2 bit。 escape 事件还要在独立 RAW 流中保存完整的 28-bit mem 地址或 8-bit gpr 地址。
优先物理公平建模。下一步先定义 SRAM 组织与固定格式，再讨论最终压缩率和面积收益。

6.2 已实现的 Trace 指标

指标定义用途与限制
六位 Trace mask 分布原始统计 bit 顺序为 LOAD/STORE/VECTOR/SCALAR/SFU/CONTROL；实现时前五位作为功能 mask，末尾 EOP 单独处理。每条 trace 实际出现 7–27 种；合法空间为 32 种功能组合 + 1 种 EOP，而非 64 种。
位宽加权槽利用率所有周期有效 slot 位宽之和 ÷ 184×T。比“平均活跃槽数”更公平，因为槽位宽不同。
字段分布每个 active slot 内，每个字段统计唯一值数、Shannon 熵、众数比例。熵只是无元数据、无随机访问约束的理论下界。
相邻重复率分别统计事件到事件，以及两个相邻周期均 active 时字段是否相等。支持 CONST/DICT/DELTA 候选判断，不证明硬件收益。
严格结构周期核忽略地址/寄存器字段，对周期 1–1024 搜索；候选段必须逐周期结构相等且连续重复至少三轮。报告 period、起止、覆盖率和自相关匹配率；不是调度器显式 II 标注。
周期对齐仿射拟合在严格结构核内，按 phase 收集跨迭代字段，以模字段位宽的 base+k×stride 拟合。100% 仅表示核内序列；不覆盖核外残差。
滑动窗口带宽每周期需求为所有有效原始 payload 位宽之和；窗口为 1/2/4/8/16/32/64/128 周期。用于估计突发读取；尚未加入 SRAM 读宽、对齐和延迟。
固定带宽预填充max_t(cumulative_demand(t) - B×(t+1))。是避免 deadline 下溢的逻辑下界，不等于最终 FIFO 容量。

CONTROL 在所有功能周期均为 0，只在最终 EOP 周期为 1，且该周期五个功能槽均为空。因此正常周期只需 5-bit mask； 若函数描述符保存总周期数，解压器可在末周期自动产生 EOP。现有 mask_distribution.csv 仍按原始六位 Trace 统计， 但不代表最终物理格式必须保存第六位。

9. 可能成立的突破方向

当前主线：跨 workload 固定格式与物理供给闭环 保留 5-bit 功能 mask、隐式 EOP 和 RAW 有效槽作为统一保底格式；主要评估异构 bank 的物理容量、 固定读取带宽和零停顿恢复。任何字段优化都必须对所有 workload 使用同一 codec，并计入 escape、状态、加法器和对齐成本。
候选方向具体内容可能的新颖性必须证明风险
A. 后期固定小 delta fast path 仅对 LOAD/STORE 的 mem/gpr 地址及 SFU 的 gpr 地址开放 1–2 bit 固定 delta 码；未命中通过 RAW escape 保存完整地址。 它只是统一格式上的小优化，不作为论文主创新；不能使用逐 workload 字典。 扩展 workload 后仍有净收益；逐周期精确恢复；escape、初值、状态寄存器和物理对齐全部计入。 需要 28-bit mem 地址模加法器和若干 8-bit gpr 地址模加法器、状态寄存器与 MUX，面积/功耗/时序可能抵消容量收益。
B. 不等高、不等宽 bank 的物理布局 利用各槽位宽和事件数不同，按实际 SRAM 宏组合布局；避免最高列主导全部宽度。 针对 42/42/34/31/31/4 异构槽的宏级 packing 与并行读取。 同工艺、同端口下的宏面积/能耗；不能只报逻辑 bit。 Li 已有分 bank；差异必须落到可量化物理组织。
C. 确定带宽供给与最小缓冲 在固定 SRAM 读宽下，离线布局 payload，计算预填充/FIFO，形式化保证每周期 deadline。 把压缩率、带宽、FIFO 和零停顿作为联合优化问题。 所有 Trace 无下溢；端口、读取延迟、对齐全部计入。 如果直接多 bank 并行读取已经足够，额外 FIFO 贡献可能偏弱。
D. Mask/字段编码联合优化 仅在消融中比较固定 5-bit mask 与 4-bit 模板 + escape；字段 payload 布局仍可独立研究。 验证低熵是否能转化为真实物理收益，而不是只报理论熵。 当前模板仅省约 0.91 bit/cycle、总容量约 0.50 个百分点，还未计模板表。 当前不建议作为候选突破方向：解码成本与先行工作风险均高。
E. Workload-specific 周期 fast path 只对通过门槛的 GELU/LogSoftmax/Softplus/LogSumExp 核启用；其他区域回落字段编码。 作为多模式 codec 的一个可选模式，而非通用周期理论。 核识别、残差边界和切换元数据；综合收益仍为正。 TACO 2018 先行工作强，主张必须保守。
F. 等价编码降低翻转 在行为等价而非逐 bit 相同的前提下，优化解压输出或控制分发切换。 可把收益扩展到动态功耗。 形式化行为等价、门控安全和功耗实测。 当前没有数据；应放在压缩 RTL 稳定之后。
G. Mask 驱动的解码与分发门控 利用 ifnull 阻止 NOP 槽驱动字段恢复、crossbar 和功能单元控制端口。 不是新的压缩原语，但可把收益从静态容量扩展到动态切换功耗。 门控不改变有效周期行为；报告取指、解码、分发和全核功耗分解。 单独论文分量较弱，应作为主 codec 的配套贡献。
H. 压缩感知的 R/tile 协同选择 把压缩后物理 IMEM 容量加入原论文的 tile 因子选择，重画存储—性能折中曲线。 系统层证明压缩允许选择性能更优、原本受 IMEM 限制的配置。 R=2/4/8/16/32 全扫描，并保持原调度周期语义。 属于系统评估贡献，不能替代核心编码机制。

11. 当前局限、风险与未完成项

问题当前状态为什么影响结论解决办法
字段混合格式过于自由每字段独立选最优，模式元数据固定估计 18 bit。逐 workload 过拟合且需要太多并行 LUT、MUX、加法器和窄流。降为 oracle；主格式使用 RAW，仅在后期评估固定地址 delta + escape。
SRAM 宏未建模统计为逻辑 bit。小字典、窄 bank 和不规则深度可能造成严重取整浪费。获取 28nm memory compiler 可用宏；对每方案做 bank packing。
带宽模型无端口时序按 bit deadline 计算，无读延迟/对齐。96 bit/cycle“零预填充”可能无法由实际宏实现。加入读字宽、端口数、1–2 周期延迟和 burst 粒度。
周期搜索是后处理启发式最大 period 1024，精确重复至少三轮。未与调度器内部 loop/iteration ID 对齐。让调度器导出 iteration/phase 标签，交叉验证 period。
仿射拟合不是形式化最优搜索由高频相邻差分生成候选 stride。可能漏掉带少量异常的更优规则。实现确定的最小残差求解，并显式编码异常。
Shape 覆盖有限每函数一个 Y，X=32/64。不能证明对常用隐藏维度、tile 因子稳定。固定合理 X，扫描 Y 与论文中的 R/tile 因子。
取指切换/能耗尚未统计当前只有字段值、重复率与 payload bit deadline。不能证明 mask 门控或压缩读取带来净动态能耗下降。从 RTL 导出 SAIF/VCD，分解 SRAM 读、恢复逻辑、crossbar 和控制端口功耗。
基线不完整已有全宽、Mask/Li、事件和理论混合。审稿人会要求 Stop-bit、有限模板、Li 片上物理基线。统一格式实现所有基线并计物理开销。
尚无 RTL只有 Python 编码/解码。无法证明面积、功耗、1 GHz 与真实一拍吞吐。先做最小 ifnull + 受限字段 codec RTL，再决定论文主张。

Kill Criteria

  • 受限编码加入对齐和 SRAM 宏取整后，相对 Li 片上物理基线没有明显容量优势。
  • 解压逻辑面积或功耗超过节省的 IMEM，或主频低于原设计目标。
  • 固定读带宽和合理 FIFO 下无法证明全周期无下溢。
  • 最终贡献退化为“使用字典/Mask/分 bank”，无法与 2020/2024 先行工作区分。
  • 扩充 Y/R 后收益只存在于 GELU/Softplus 等高度规则个例。

14. 术语表

术语本项目中的含义
VLIW一个周期同时控制多个功能单元的宽指令。本平台固定为 184 bit。
slotVLIW 中对应某类功能单元的字段；五个执行槽加一个控制槽。
NOP该槽当周期无操作；当前编码为槽值全 0。
ifnull / mask原始统计是六位有效表；推荐物理格式只保存五个功能槽位，1 表示该槽需从紧凑流取出下一条 payload，末周期 EOP 由总周期数隐式产生。
payload去掉 NOP 后真正需要保存的有效槽指令内容。
gap同一 slot 两次有效事件之间的周期距离；gap=4 表示中间有三个空周期。
descriptor解释压缩流所需的长度、模式、表大小、位宽或地址等元数据。
CR / 剩余比例压缩后位数除以原始位数；越低越好。本文同时使用“减少百分比”，必须看清口径。
结构周期忽略寄存器和地址变量字段后，槽操作结构的重复周期。
仿射再生用 (base + k×stride) mod 2^width 恢复跨迭代字段。
compressed-resident压缩形式直接驻留于实际指令存储，而非先整体展开到等容量 cache。
零停顿供给解压/读取前端在每个 deadline 周期均能给出所需完整 VLIW，不产生气泡。
接手者的第一原则 先问“这个数字属于外部文件、逻辑有效位，还是物理 SRAM？”再比较压缩率； 先问“这个机制已有谁做过？”再命名创新；先完成固定格式和 RTL，再把软件上界写入论文结论。
