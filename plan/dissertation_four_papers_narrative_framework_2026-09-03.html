四篇小论文串联为博士学位论文的叙事框架

基于三篇论文原文与第四篇174-bit VLIW/4-slot实验重新梳理｜2026-09-03

推荐结论：最稳固的总叙事不是“两个VLIW工作加两个非线性工作”，也不是把四篇文章按发表顺序拼接，而是面向结构可预知复杂计算的多层次资源解耦。四篇论文分别解除运算与粗粒度任务、函数与固定电路、计算单元与固定角色、逻辑指令槽与物理存储Bank之间的固定绑定；共同采用离线分析或编译，把复杂性从运行时转移到软件侧，使硬件保持确定、简单和高效。

第一层运算依赖解耦OOLU：operation graph
第二层函数实现解耦SMM-FSM：参数化拟合
第三层执行资源解耦FRV：FUV资源重构
第四层指令存储解耦4-slot：跨槽共享Bank

1. 四篇论文的准确定位

编号论文/工作核心问题核心方法在大论文中的角色
第一篇OOLU：稀疏LU分解VLIW加速器矩阵列/元素级依赖过粗，掩盖可并行的细粒度运算。把数值分解转换为operation-level task-flow graph，通过资源和存储冲突感知的静态调度生成VLIW。建立“细粒度计算图＋离线静态调度＋简单硬件执行”的方法基础。
第二篇SMM-FSM：随机计算通用多变量非线性模块传统LUT、Taylor、CORDIC或固定随机计算结构无法兼顾复杂函数覆盖与低硬件开销。输入空间分段、仿射归一化、分段参数配置；利用K–A表示组合多个单变量SMM-FSM。建立“函数不应与固定电路绑定，而应由离线参数配置到统一硬件”的函数级可重构思想。
第三篇FRV-SFU-VLIW：可重构非线性函数加速器非线性DAG同时包含Vector、Scalar、Reduction、SFU和访存，固定资源划分会造成资源失衡。primitive DAG、静态多模式调度、RFU Function Unit Virtualization、逐周期VLIW。前两条探索路线的系统汇合点：用图调度组织可编程非线性执行。
第四篇174-bit VLIW的4-slot共享Bank压缩逐周期VLIW平均槽利用率低，普通纵向压缩仍因功能槽隔离产生Bank容量碎片。编译期最多4-slot调度、5-bit target mask、phase条带化四条payload流、Bank门控和精确周期恢复。补齐控制面：解决可编程架构生成的宽静态指令流如何低开销存储和逐拍供给。

2. 推荐主线：从固定绑定到多层次可重构映射

2.1 大论文应回答的总问题

对于计算结构能够在运行前获知，但依赖关系不规则、函数形式多样、操作类型异构的复杂计算，如何把复杂性转移到离线建模和编译阶段，在保持硬件确定性执行的条件下，逐层消除固定绑定造成的并行度损失、功能覆盖不足、计算资源闲置和指令存储浪费？

2.2 四篇论文共同的“结构可预知”前提

工作运行前已知的结构软件侧完成的工作运行时硬件承担的工作
OOLU稀疏矩阵非零模式在多次Newton和瞬态迭代间基本不变。符号分解、operation graph、调度和数据映射。顺序读取VLIW并驱动Bank、Crossbar和PE。
SMM-FSM目标函数、定义域、误差要求在模块配置前已知。分段、拟合、归一化和参数生成。读取分段参数并执行随机状态转移和累加。
FRV-SFU-VLIW非线性DAG、primitive延迟、寄存器和执行资源约束已知。DAG构建、FUV模式分析、周期精确调度。每拍执行一条预生成VLIW，不做动态调度。
4-slot完整逐周期指令trace在程序安装前已知。限制发射宽度、事件抽取、Bank条带化和地址生成。mask译码、按需读Bank并确定性恢复五个逻辑槽。

因此，四篇工作最深层的一致性不是应用相同，也不是都用了VLIW，而是同一种软硬件分工：

运行前：复杂的结构分析、函数拟合、资源搜索、调度和存储映射 ↓ 运行时：规则、确定、低控制开销的硬件执行 总原则：Offline complexity → Online simplicity

2.3 四种“解除固定绑定”

原有绑定造成的浪费解除绑定的方法收益
Operation ↔ 矩阵列/元素必须等待整个元素或列完成，局部已就绪运算不能提前执行。OOLU把更新、除法等操作独立成图节点，根据真实数据依赖调度。暴露跨列、跨元素的细粒度并行性。
Nonlinear function ↔ 固定电路函数变化需要重新设计硬件，复杂或非单调函数难以覆盖。SMM-FSM把函数差异转换为分段和参数表差异。统一、全数字、可重新配置的函数逼近。
RFU ↔ 固定Vector角色SFU繁忙时Vector RFU闲置，Vector繁忙时过多SFU又浪费面积。FRV通过FUV把部分RFU重构为特殊函数二次多项式后端，由编译器选择模式。降低异构非线性DAG中的“dark silicon”与资源失衡。
Payload event ↔ 固定slot BankVECTOR Bank可能接近容量上限，SCALAR/SFU Bank却留下无法互借的空间。第四篇把五类有效事件条带化到四个共享Bank，再按mask和phase恢复。在保持周期的同时降低Bank容量碎片和指令存储面积。

第二篇：函数与数据通路路线
目标非线性函数 → 离线分解/拟合 → 参数化统一硬件
第三篇：系统汇合
非线性函数 → primitive DAG → FUV资源配置＋静态多模式调度 → FRV-SFU-VLIW
↓

第三篇不是把SMM-FSM直接塞入VLIW。正确关系是：第一篇解决“怎样组织细粒度操作”，第二篇解决“怎样让函数实现可配置”，第三篇将这两个问题意识汇合为面向非线性DAG的可编程执行系统，并选择确定性FP16/BF16轻量SFU满足高吞吐需求。

4. 第一篇与第四篇之间的真实连接

第一篇并不需要在第四篇中重新研究LU，但它已经明确暴露了VLIW控制规模问题：

  • 16个PE、32个BRAM Bank的示例VLIW达到832 bit。
  • 论文指出指令宽度随PE和Bank数增加，需要软件避免过长指令。
  • FPGA实现中，指令存储与矩阵数据合计消耗60.39%的BRAM。
  • 大矩阵需要从DDR/HBM流式提供指令，带宽成为扩展约束。
  • Future Work明确提出instruction compression，以降低VLIW宽度并支持ASIC及更大规模部署。

因此，大论文可以说第一篇揭示了宽静态控制流随并行资源扩展的问题，第三篇在结构更规则的五槽异构VLIW中再次暴露逐周期NOP和instruction footprint，第四篇最终针对这一类问题建立Bank共享与精确恢复方法。

边界必须写清楚：第四篇目前直接验证的是第三篇174-bit非线性VLIW，不能宣称已经验证OOLU的832-bit、PE-scaled指令。第一篇在大论文中提供问题来源和方法学铺垫，不需要重新开展LU方向实验。

5. 建议的大论文章节组织

章节建议标题承担的叙事任务
第1章绪论提出结构可预知但依赖不规则、操作异构的复杂计算；说明固定绑定在四个层次造成的浪费。
第2章图驱动可重构加速的统一方法框架定义计算图、离线映射、配置时间尺度、静态指令流和软硬件边界，建立全篇共同术语。
第3章面向稀疏矩阵计算的运算级依赖解耦与VLIW调度对应OOLU；证明细粒度图和静态调度可从不规则依赖中释放并行性。
第4章面向通用非线性函数的分段参数化随机计算架构对应SMM-FSM；把可重构性从任务调度推进到函数实现。
第5章面向非线性DAG的执行资源虚拟化VLIW架构对应FRV-SFU-VLIW；汇合图调度与非线性可配置执行，处理Vector/SFU资源失衡。
第6章面向低槽利用率VLIW的共享Bank压缩与周期精确恢复对应第四篇；处理系统可编程性带来的指令存储和供给代价。
第7章多层次资源解耦的统一分析从配置粒度、配置时间尺度、性能、面积、能耗、通用性和运行时开销横向比较四篇工作。
第8章总结与展望总结从依赖、函数、执行资源到指令存储的完整演进。

第2章和第7章非常重要。没有这两个综合章节，四篇论文仍可能看起来像论文合集；加入统一抽象和横向分析后，四篇工作才真正构成体系。

8.2 可直接用于摘要或绪论的核心句

本文针对结构在运行前可知、但依赖关系不规则且操作类型异构的复杂计算，研究图驱动的软硬件协同加速方法。本文依次从运算依赖、非线性函数实现、执行资源角色和指令存储组织四个层次解除固定绑定，将复杂的依赖分析、函数拟合、资源配置和指令映射转移到离线软件阶段，在保持运行时确定性执行的同时，提高计算并行度、函数可编程性、执行资源利用率和指令存储效率。

9. 四篇之间可直接使用的过渡逻辑

第一篇 → 第二篇

第一篇表明，对运行前结构可知的不规则计算，细粒度表示和离线优化能够显著简化硬件并释放并行性。但仅优化依赖调度还不能解决计算功能随应用变化的问题，因此进一步研究函数级可配置硬件。

第二篇 → 第三篇

第二篇证明了通过离线参数生成可以在统一硬件上覆盖多样非线性函数，但随机序列存在明显的精度—延迟权衡。对于Transformer等需要高吞吐且包含规约、逐元素、SFU和数据搬移的非线性DAG，需要进一步采用确定性数值表示、细粒度DAG和可重构执行资源。

第三篇 → 第四篇

第三篇通过FUV和静态多模式调度提高了计算资源利用率，但它每周期读取完整VLIW，未使用槽填充NOP；论文已经依靠tiling在指令存储与周期之间折中。这说明计算数据通路得到优化后，指令存储和供给成为下一层瓶颈，因而需要4-slot共享Bank压缩。

全篇收束

四篇工作依次回答“算什么操作”“怎样表示函数”“由哪些资源执行”“如何低成本提供控制”四个问题，形成从计算表达、执行组织到控制存储的完整软硬件协同链条。

10. 必须避免的叙事错误

  1. 不能说SMM-FSM演化成FRV-SFU。两者数值表示、目标和硬件路径不同，是互补设计点。
  2. 不能把稀疏LU称为非线性函数计算。SPICE外层有非线性迭代，但第一篇直接加速的是数值LU分解。
  3. 不能宣称第四篇已经验证OOLU压缩。当前直接证据来自第三篇174-bit VLIW和非线性/LLM负载。
  4. 不能只把“VLIW”当共同点。第二篇不是VLIW；真正共同的是离线结构提取、配置化映射和在线确定性执行。
  5. 不能把第四篇写成第三篇的附属工程优化。它解决的是逻辑槽与物理存储绑定导致的一般性容量碎片问题，并补齐控制面。

11. 最终建议

总思想采用“多层次资源解耦”，章节结构采用“从计算图到指令供给”。第一篇和第二篇作为两条互补的前期探索路线，第三篇作为汇合点，第四篇作为系统层面的收束。这样既保留第一篇和第二篇的独立学术价值，又能让第三、第四篇形成强连续性，而且不需要引入SMM-FSM+SFU或重新研究LU等已被导师否定的方向。
