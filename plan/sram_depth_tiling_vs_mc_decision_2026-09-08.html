三个模型程序池的深 SRAM：已有宏拼接还是 MC 专用宏

面向 28 nm、1 GHz 的软件预评估与实现决策（2026-09-08）

输入为 model_pool_compression_study_2026-09-08.html 的 BERT、LLaMA、SD-UNet 三个程序池；对 E0（未压缩）、E1（纵向压缩）和 E2（4-slot）逐个判断深 SRAM 的实现方法。

直接结论优先送 MC：32768×5它同时改善面积/漏电，并消除 E2 控制路径上的两级深度选择。
时序备选同时申请：16384×34软件 PPA 不占优；只有当 LLaMA E2 的拼接版本在 1 GHz 不能收敛时才切换。
建议拼接其余深度先用现有宏尤其 8192×34 及 E0 的宽字深存储，不值得为第一轮实验新增专用宏。
最实用的下一步：先写一套参数化 depth-tiling wrapper，完成三个程序池的全部功能仿真；同时让 MC 生成 32768×5，并把 16384×34 作为 E2-LLaMA 的时序保险。不要等待 MC 才开始 RTL。

2. 软件模型怎样计算

2.1 两种实现

两片深度拼接（例：2×4096×34 → 8192×34） 地址高位 ──► 片选译码 ──► 只使能一片 SRAM 地址低位 ──────────────► 两片 SRAM 的地址口 ┌─ SRAM 0 Q ─┐ 延迟一拍的地址高位 ───────────►│ 2:1 MUX ├─► 34-bit Q └─ SRAM 1 Q ─┘ 专用深宏（例：MC 直接生成 8192×34） 完整地址 ──► 单个 SRAM ──► 34-bit Q

拼接必须满足三个细节：每周期只打开被选中的一片（否则动态功耗会乘以片数）；地址高位必须延迟到与 SRAM 的同步读数据同拍；4 片时输出选择器要做成平衡的两级 2:1 树，不能写成优先级链。

2.2 面积、功耗与时序口径

  • SRAM：HP CACTI 32 nm、1RW 口、0.9 V；它是 MC 前筛模型，不是 TSMC 28 nm memory compiler 的签核数字。
  • 拼接逻辑：2:1 mux 近似 3 个 NAND2 gate-equivalent/bit，再计入片选译码与片选寄存器；NAND2 面积取 2.54144 µm²。功耗以 0.5–2.0 fF/GE 和 1–20 nW/GE 给出区间。
  • 动态读功耗：config 每功能周期读一次；payload 按真实 trace 的有效事件数读，保留 E1/E2 的精确 CEN 门控；推理执行期不含程序装载写功耗。
  • 1 GHz：周期为 1 ns。现有宏的 tCD 来自仓库 Verilog timing model：8192×144 为 0.744 ns、8192×27 为 0.6267 ns、8192×5 为 0.4979 ns、4096×34 为 0.5177 ns、2048×34 为 0.3855 ns。
边界：现有 Verilog 文件名显示的是特定快角模型，CACTI 也不是目标工艺签核模型。因此本报告可以决定“先做哪种 RTL、优先向 MC 要哪些宏”，不能替代 MC datasheet、目标 PVT 的 .lib STA 和布局布线后的 1 GHz 签核。

3.1 为什么 E0 的深宽宏不建议送 MC

171×16384/32768 看似减少宏个数，但 CACTI 的单宏访问时间已经达到 1.053/1.498 ns。cycle time 小于 1 ns 只说明内部阵列可流水地连续接收请求，不等于数据能在一个 1 ns 周期内返回。要使用这类宏，往往仍需增加输出流水级。另一方面 E0 只是论文 baseline，不值得优先投入两种深度×两种宽度（144/27）的 MC 生成、验证和 floorplan 工作。因此：

  • SD-UNet E0：两组 8192×171 深度拼接；
  • LLaMA E0：四组 8192×171，平衡 4:1 树；若 STA 不过，在 E0 输出后单独增加一级寄存器。E0 仍可保持每周期一条指令的吞吐，只增加固定启动延迟；比较时要报告 latency 差异。

3.2 为什么 32768×5 最值得 MC

它虽然只有 5 bit 宽，却是每周期必读的 config。四片拼接要在 config Q 与 mask/popcount/enable 译码之间增加两级选择器；这条路径还要产生下一拍 payload 的地址和 CEN，是 E2 的控制关键路径。专用 32768×5 在模型中面积低 6.4%、漏电约低 12%，并完全删除这两级 mux。单次读能量会从约 3.76 pJ 上升到 6.32 pJ，但这是用约 2.6 mW 动态功耗换取更清楚的 1 GHz 路径和更少的宏实例。

3.3 为什么 16384×34 只能算“时序保险”

四片 4096×34 的拼接模型面积更小，单次有效读能量也只有专用深宏的大约一半。E1 中 payload Q 后面只需送入固定 slot，因此应直接拼接。E2 中情况不同：数据先经过深度选择器，再经过 lane→slot 的 4:1 散布 mux，形成两段 mux 级联。专用 16384×34 能删除前一段，可能解决 LLaMA E2 的 1 GHz 闭合问题。故正确流程不是直接选择 MC，而是拼接版与 MC 版并行保留，用实际 STA slack 决胜。

5. 最终逐宏决策清单

32768×171（物理上 144+27）4 深度拼接P0专用宽深宏读能量和访问时间明显变差；MC 与集成成本高。若 4:1 mux STA 不过，先加流水，不先做深宽 MC。
16384×52×8192×5P0仅一个 5-bit 2:1 mux；专用宏虽省约 9% 本宏面积，但系统绝对收益很小、读能量更高。SD-UNet E2 的 config→enable 路径出现负 slack 时再生成。
32768×5MC 专用宏P0-MC面积/漏电均改善，并去掉控制关键路径的两级 mux；E1/E2 共用同一种宏。若 MC 不支持 5-bit，申请 8-bit 物理宽度、只用低 5 bit，并重新比较 .lib/PPA。

6. 1 GHz 实现与验证步骤

  1. 先完成通用 depth wrapper。支持 1/2/4 个深度 tile、同步读、延迟片选、单片 CEN 门控、平衡输出 mux；用参数锁定实际宏，避免综合把宏内容推平。
  2. 做连续跨页仿真。重点检查地址 8191→8192、16383→16384、24575→24576；连续每拍读，不能有气泡、重复或丢指令。程序 EOP 恰好落在边界前后也要覆盖。
  3. 先综合三个最高风险 wrapper。171×32768 拼接、5×32768 拼接、E2 的 4×(34×16384 拼接)+散布路径。约束 1.0 ns，报告 WNS/TNS 与具体 startpoint/endpoint。
  4. 获取 MC 数据。第一批请求 32768×5（或 8）；同时请求 16384×34 作为时序备选。必须拿到 datasheet、所有 signoff PVT .lib、LEF、GDS、功耗模型与 Verilog model。
  5. 做 apples-to-apples 综合。同一顶层、同一程序池、同一 PVT、同一时钟和 IO delay，分别替换 tile wrapper 与 MC wrapper；若只比较裸宏 tCD，会漏掉 E2 的下游散布逻辑。
  6. 用真实活动率做功耗。从三个程序池仿真导出 SAIF/VCD；确认未选 tile 的 CEN 不活动且 Q 保持。分别报告 leakage、internal、switching，不只报一个 total。
