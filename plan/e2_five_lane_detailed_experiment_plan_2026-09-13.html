1. 实验定位与结论

建议：E2 五 Lane 应作为论文的“干净主实验”。它保留原始 max-5 调度，允许 5 槽并发，不改变任何程序执行周期；创新只来自逻辑 Slot 与物理存储 Lane 解耦。

仓库当前的四 Lane E2继续保留，但应作为后续“调度约束＋压缩”的增强版本。二者不能混为同一个实验：

  • E2-5：不改变调度，单独验证共享存储组织的价值。
  • E2-4：把最大并发限制为 4，再减少一条物理 Lane，验证调度与压缩联合优化。

2. E2 五 Lane 的严格定义

FRV-SFU-VLIW包含5个逻辑功能槽，每个槽使用34-bit容器：

表1　逻辑槽编号。Slot ID 是逻辑功能身份，并不是物理 SRAM Lane 编号。
Slot ID逻辑槽Payload 宽度
0LOAD34 bit
1STORE34 bit
2VECTOR34 bit
3SCALAR34 bit
4SFU34 bit
原始有效 VLIW 宽度 = 5 × 34 bit + 1-bit EOP = 171 bit

E2-5在存储侧设置5条34-bit物理Lane。任意逻辑槽的有效payload都可以写入任意Lane，解码时再恢复到原来的逻辑位置。

5个逻辑Slot
只提取有效Payload
5条共享Lane
Mask＋Phase解码
恢复完整5槽VLIW

E2-5必须满足以下硬约束：

  • 使用原始 max-5 schedule，不能禁止五槽并发。
  • 每个时钟周期恢复一条完整逻辑指令，II=1。
  • 有效槽内容和逻辑位置逐 bit 不变。
  • 空槽恢复为 NOP，空指令周期也必须保留。
  • 允许有效 mask 为 11111。

4. 软件编码与条带化方法

4.1 Config 保存每周期 5-bit Mask

表3　Config Mask位定义。位为1表示本周期对应逻辑槽有效。
Mask 位逻辑槽
bit 0LOAD
bit 1STORE
bit 2VECTOR
bit 3SCALAR
bit 4SFU

例如 mask=10110 表示 STORE、VECTOR、SFU 有效。mask=00000 表示本周期为全NOP，但该Config条目不能删除，否则会改变周期位置。

4.2 EOP 必须改为程序长度隐式生成

四Lane E2可以用11111表示带内EOP，因为max-4调度不会产生五槽并发。五Lane版本中，11111是合法数据，不能继续复用。

推荐与E1统一：

  • Config只保存真实执行周期的mask；
  • prog_len包含额外的EOP周期；
  • 计数到prog_len-1时不读Config和payload，硬件生成全NOP＋eop=1。
若程序有 1000 个真实执行周期：
Config 条目数 = 1000
prog_len      = 1001
周期 0～999   = 读取 Config 并恢复指令
周期 1000    = 硬件生成 EOP

4.3 五Lane轮转条带化

维护一个取值为0～4的3-bit phase。同一周期内，有效逻辑槽按Slot ID升序排列，第r个有效事件分配到：

physical_lane = (phase + r) mod 5

周期结束后：

phase_next = (phase + popcount(mask)) mod 5

跨周期连续轮转后，整个程序中五条Lane的有效payload数量近似均分。每个程序独立编码并从phase=0开始，可支持任意程序启动顺序。

4.4 编码例子

设phase=3、mask=10110，有效槽为Slot 1、2、4：

表4　示例中逻辑槽到物理Lane的分配。
逻辑槽有效事件Rank物理Lane
STORE / Slot 10(3+0) mod 5 = 3
VECTOR / Slot 21(3+1) mod 5 = 4
SFU / Slot 42(3+2) mod 5 = 0
 
lane 3 ← STORE payload
lane 4 ← VECTOR payload
lane 0 ← SFU payload
phase_next = (3 + 3) mod 5 = 1

4.5 为什么不能每周期固定从Lane 0开始

若每周期第一个有效槽总写入Lane 0，那么Lane 0仍会最长，纵向Bank不均衡会转化成物理Lane不均衡。连续phase轮转使所有有效事件在五条Lane之间全局条带化，才是真正解决统一深度浪费的关键。

6. Config RAM 设置

6.1 逻辑配置

  • 宽度：5 bit。
  • 类型：同步单端口SRAM。
  • 运行时：每个真实指令周期读取一次。
  • 装载和运行互斥，因此不需要双端口。
  • 空闲、复位和隐式EOP周期关闭CEN。
  • Config输出比payload读取提前一级流水。

Config中不保存phase、物理Lane编号、Slot ID、codebook编号或EOP位；这些由硬件状态和程序描述符产生。

6.2 三个程序池的测量容量

程序池程序数Config有效条目有效Payload总数最长Lane分池Config宏分池Payload宏

SD-UNet511,67913,5202,70516384×55×4096×34

6.3 论文主硬件采用统一最大配置

主硬件不能按函数单独定制。建议把物理核固定为能够覆盖最大LLaMA程序池，并用同一套硬件覆盖替换BERT、SD-UNet和LLaMA程序池：

表6　统一最大物理配置。E1的五个逻辑Bank严格等深，E2的五条物理Lane也严格等深。
方案Config RAMPayload RAM物理SRAM总bit数
E0无1×32768×1715,603,328
E1-uniform1×32768×55×16384×342,949,120
E2-51×32768×55×8192×341,556,480

E2-5物理bit数相对E0减少72.2%，相对E1-uniform减少47.2%。但面积不能直接等同比特数，最终必须使用SRAM宏面积和综合逻辑面积。

E1和E2保存的有效信息量相同：二者都是“每周期5-bit Mask＋所有有效34-bit Payload”。E2的优势不是减少信息熵，而是让不同逻辑Slot共享物理Bank容量，使五个统一深度SRAM的长度均衡。

6.4 Config占比与宏选择

Config  = 32768 × 5          =   163,840 bit
Payload = 5 × 8192 × 34      = 1,392,640 bit
总计                            1,556,480 bit

Config占E2-5物理bit数约10.5%。它面积占比相对较小，但每个真实周期都访问，因此需要单独统计动态功耗。

  • Config：使用仓库已有原生32768×5宏。
  • Payload bring-up：先使用两个现有4096×34宏做深度拼接。
  • 最终PPA：用MC生成原生8192×34宏，并与拼接版本对照。
  • 因为Payload宏复制5份，专用宏的面积和功耗收益会被放大，值得生成。

7. RTL 解码器实现

7.1 顶层接口

表7　建议的装载与程序描述符接口。地址宽度按统一最大配置设置。
信号宽度含义
load_sel3 bit0=Config，1～5=Payload Lane 0～4
load_addr15 bit兼容32768深Config；Payload只使用低13 bit
load_wdata34 bitPayload使用全部34 bit；Config使用低5 bit
cfg_base15 bit所选程序在Config池中的起始地址
prog_len15 bit程序总输出周期数，包含隐式EOP周期
lane_base0..4各13 bit所选程序在五条Payload Lane中的起始地址
start1 bit锁存描述符并启动执行的单周期脉冲

7.2 Stage A：发起Config读取

start时锁存描述符并初始化：

cfg_pc  ← cfg_base
ptr[0]  ← lane_base0
...
ptr[4]  ← lane_base4
phase   ← 0
count   ← 0

真实指令周期满足count < prog_len-1时，向Config SRAM发送cfg_pc。Config SRAM在下一拍输出mask。

7.3 Stage B：Mask解码并发起Payload读取

在Config输出有效的周期计算：

k          = popcount(mask)
sum        = phase + k
phase_next = (sum >= 5) ? sum - 5 : sum

本周期需要读取从phase开始的连续k条环形Lane。启用的Lane读取当前ptr[i]，然后对应指针加1。同时将本周期的旧phase和mask送入Stage C寄存器。

Stage C必须使用旧phase，而不是更新后的phase。Payload SRAM当前返回的数据正是按照旧phase分配和读取的。

7.4 Stage C：Scatter恢复逻辑Slot

每个Slot的有效事件Rank由低编号有效位的前缀和得到：

rank(slot0) = 0
rank(slot1) = mask[0]
rank(slot2) = mask[0] + mask[1]
rank(slot3) = mask[0] + mask[1] + mask[2]
rank(slot4) = mask[0] + mask[1] + mask[2] + mask[3]

若Slot s有效，其来源Lane为：

source_lane[s] = (phase_c + rank[s]) mod 5

使用5组34-bit、5选1散布MUX把五条Lane的输出恢复到LOAD、STORE、VECTOR、SCALAR和SFU。

7.5 无效槽的低翻转输出语义

  • 有效槽：所有字段寄存器装载新Payload。
  • 无效槽：OP字段写0，其他字段保持上一次有效值。
  • 下游只依据OP字段判断NOP，保持的其他字段不参与执行。
  • 同一低翻转输出级必须用于E0、E1和E2，不能单独计为E2收益。

7.6 特殊Mask处理

表8　边界状态。特别注意11111在E2-5中是正常指令，不是EOP。
状态含义硬件行为
00000全NOP周期不读Payload；phase和指针不变；仍输出一个有效指令周期
单个1单槽有效只读phase所指的一条Lane
11111五槽全部有效五条Lane全部读取；phase加5模5后保持不变
隐式EOP程序结束不读Config和Payload；输出全NOP并拉高eop

7.7 不使用通用除法器

phase和popcount之和最大为9，因此模5只需一次比较和条件减法。Lane使能建议进一步使用case({phase,popcount})生成5-bit one-hot/multi-hot结果，合法组合只有约30种，更利于1 GHz时序。

7.8 E2相对E1新增的逻辑

  • 3-bit phase寄存器；
  • popcount5与四个前缀计数；
  • 模5条件减法和Lane使能译码；
  • 5个Payload Lane指针；
  • 5×34-bit、5选1Scatter网络；
  • Mask和phase流水寄存器。

E2-5不需要Payload Slot ID、可编程codebook、CAM、变长解析、多周期解压队列或背压。预综合估计新增逻辑约2～4 kGE，但只能作为量级判断，论文必须使用实际28 nm综合网表数据。

8. 1 GHz 时序设计

8.1 关键路径一：Config到Payload SRAM控制

Config SRAM Q
  → popcount / Lane-enable译码
  → Payload SRAM CEN、地址建立

Config必须比Payload提前一个流水级读取，不能试图在一个周期内串联完成两次SRAM访问。

8.2 关键路径二：Payload到输出寄存器

Payload SRAM Q
  → 34-bit 5:1 Scatter MUX
  → 字段输出寄存器

若该路径不能满足1 GHz，依次尝试：

  1. 把二进制选择MUX改为综合友好的一热AND-OR结构；
  2. 只对实际输出字段生成MUX，裁掉未使用bit；
  3. 拆分字段组并降低选择信号扇出；
  4. 增加一级固定流水线，并给E0/E1加入对齐寄存器。

增加一级流水只改变启动后的首次输出延迟，不改变II=1，也不增加算法的指令周期数；论文需要分别报告延迟和吞吐率。

9. 功能验证计划

9.1 软件Roundtrip

原始 max-5 schedule
  → E2-5 编码
  → 软件解码
  → 原始 schedule 逐周期、逐Slot、逐bit比较

必须同时检查Config条目数、Payload总数、Lane长度差、11111合法性和程序独立phase初始化。

9.2 Mask×Phase穷举

穷举32种mask × 5种phase = 160种状态，验证：

  • popcount(lane_en) == popcount(mask)；
  • 同一周期每条Lane最多读取一个Payload；
  • 每个有效Slot具有唯一来源Lane；
  • 不同Slot不会错误读取同一Payload；
  • phase_next始终在0～4。

9.3 完整Workload回归

正文可以选10个代表程序展示，硬件回归建议跑完当前三个程序池的全部12个程序：

  • BERT：softmax、layernorm、bias+GELU、tanh；
  • SD-UNet：groupnorm、SiLU、layernorm、softmax、GEGLU；
  • LLaMA：RMSNorm、softmax、SwiGLU。

Golden必须来自max-5调度，不能误用现有golden_issue4。逐周期比较五个34-bit容器和EOP。

9.4 程序池乱序启动

所有程序一次装入SRAM，然后按不同于存储顺序的顺序运行，验证Config基址、五个Lane基址和phase复位，确保无需重新加载程序池。

9.5 建议的RTL断言

phase <= 4
popcount(lane_en) == popcount(mask)
mask == 0      → 所有Payload Lane CEN关闭
mask == 11111  → 五条Payload Lane CEN全部开启
总Payload读取次数 == 总有效Slot事件数
运行时禁止再次start
load_en与run不能同时有效
done只在EOP输出后产生

10. 面积、功耗与性能实验

10.1 面积拆分

每种方案分别报告：

  • SRAM宏面积；
  • 取指和Config解码组合逻辑面积；
  • 指针、phase、描述符和输出寄存器面积；
  • Scatter网络面积；
  • 总面积及相对E0/E1的变化。

不能用SRAM总bit数直接替代面积结果。逻辑综合时将SRAM视为黑盒，最后把MC报告中的宏面积加回。

10.2 功耗拆分

使用相同workload产生SAIF或VCD，在相同电压、PVT和1 GHz约束下报告：

  • Config RAM动态功耗和漏电；
  • Payload RAM动态功耗和漏电；
  • Scatter、指针与控制逻辑功耗；
  • 输出寄存器功耗；
  • 总功耗、每周期能量和每个有效Slot事件能量。
E1与E2-5的Payload读取总次数相同。E2-5潜在功耗优势来自更浅的Payload宏；潜在代价来自5:1 Scatter及其控制翻转。因此功耗结论必须由宏功耗和门级活动共同给出。

10.3 性能验收条件

  • E0、E1和E2-5的算法指令周期数完全相同；
  • E2-5持续输出II=1；
  • 报告固定流水填充延迟，但不把它混入算法周期数；
  • 报告最差时序裕量和可达到的最高频率；
  • E2-4的性能变化单独列出，不能归入E2-5。

11. 建议执行顺序与交付物

  1. 新增E2-5软件编码器，不修改现有E2-4。
  2. 跑完全部程序的编码—解码Roundtrip。
  3. 生成三个程序池的Config、五条Lane、描述符和Golden。
  4. 完成160种Mask×Phase解码穷举。
  5. 新建五Lane RTL，先接行为级同步SRAM。
  6. 完成单程序逐周期RTL比较。
  7. 完成三个程序池与乱序程序切换回归。
  8. 接入深度拼接SRAM Wrapper并完成时序仿真。
  9. 综合统一最大配置的E0、E1-uniform和E2-5。
  10. 比较2×4096拼接与专用8192×34 Payload宏。
  11. 完成1 GHz门级时序签收。
  12. 回标SAIF，得到分模块面积、功耗和能量。
  13. 最后加入E2-4，形成“纯存储优化→调度联合优化”的完整实验链。
