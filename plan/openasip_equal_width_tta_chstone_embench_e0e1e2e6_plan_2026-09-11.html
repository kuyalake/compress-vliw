0. 已确认的决策（2026-09-11 与用户确认）

决策点结论
目标机器形态对称等宽 5 槽 TTA，规模仿 Multanen（5 个 move 槽做成等宽；FU/RF/互连足够编译 CHStone/Embench）。CHStone 与 Embench 共用同一台机器（可行，Multanen 即如此）。
E6（Multanen 字典）复现深度机制级复现于自造等宽机器：每槽可编程字典 + 定长 bundle + frame 装载 + 选择性压缩。明确标注"独立复现、非原作者平台"（其确切 ADF/编译器/trace/压缩器未公开）。
benchmark 范围Multanen 同款：CHStone 7（Adpcm, Aes, Blowfish, GSM, Mips, Motion, SHA）+ Embench 7（Tarjan, Qrduino, Primecount, Matmult-int, Huffbench, Edn, crc32）。
E2 lane 数 N按方案本意每程序自适应 N = max_k（最大并发）；另报固定 N 对照。
CACTI 口径CACTI 7.0，HP 32 nm，1 GHz，1R/W（沿用仓库既有口径）。

1. 实验目标

  1. 构造一台各数据槽等宽的对称 5 槽 TTA 目标机器（解决上一实验发现的"位宽异构惩罚"问题）。
  2. 用 tcecc 把 CHStone 7 + Embench 7 编译到该机器，ttasim 产出逐周期动态 trace。
  3. 对每个 benchmark 和 两个套件程序池（CHStone 池、Embench 池，全部常驻）统计 E0 / E1 / E2 / E6 的压缩率，显式计入 config 开销与字典开销。
  4. 基于 CACTI 做面积与功耗估算。
  5. 定位：这是论文的跨平台稳健性 + baseline 对比层，主平台仍是 FRV。

3. 目标机器设计：对称等宽 5 槽 TTA

3.1 结构

  • 5 条对称数据 move 总线（等宽条带化的对象）+ 1 条控制总线（GCU，跳转/调用，单独处理不进条带）+ 1 个长立即数槽（limm，独立于 move 槽，如 fft_limm 的处理方式）。
  • FU：2× 整数 ALU（add/sub/逻辑/比较）、1× 乘法器、1× LSU（ld/st）、1× GCU。RF：1× 32×32-bit 整数 RF（或 2 个对称 RF）+ 1× boolean RF（谓词）。操作集要覆盖 CHStone/Embench 的整数运算需求（无浮点/64-bit，与 Multanen 的剔除口径一致）。
  • 互连对称：5 条数据总线以完全相同的方式连接源/目的 socket（同样的 FU 输出口、RF 读口作源；同样的 FU 输入口、RF 写口作目的），且 guard 集合一致——这是"等宽"的唯一来源。

3.2 等宽的验证与迭代

关键风险：等宽、可编译、宽度合理三者互相牵制。完全对称的全连接会让槽过宽；连接太少则编译器无法调度。迭代流程：
  1. 手写对称 ADF（5 数据总线 + 控制 + limm）；
  2. BEMGenerator 生成 BEM → 检查 5 个数据槽位宽是否相等（不等则调连接/socket 数）；
  3. ProgrammabilityValidator 校验可调度性；
  4. 试编译最小的 CHStone（如 sha）→ 能出 TPEF 且功能正确（ttasim 对参考输出）再固化。
目标槽宽参考 Multanen（5 槽共 64-bit ⇒ 约 12-bit/槽），但以"等宽"为硬约束、宽度数值为软目标。

4. benchmark 编译与 trace 生成

  1. 编译：tcecc -O2/-O3 -a machine.adf -o out.tpef bench.c，对 CHStone 7 + Embench 7 各产出一个 TPEF。
  2. 动态 trace：ttasim 开 bus trace，得到逐周期、逐总线的执行序列（动态 CR 与 E2 峰值检查都依赖它）。同时生成参考输出做功能校验。
  3. 程序池：CHStone 池 = 7 个 benchmark 的镜像拼接常驻；Embench 池同理（对应仓库"程序池"口径）。
  4. 占用统计先行：先算每个程序的逐周期 max_k 与 mean_k——这决定 E2 在各程序上的 N 和是否有收益空间（见 §7 风险）。

5. 四种方案与开销口径（同一台机器、同一批程序）

方案存储组织config 开销字典/其它开销
E0 不压缩整宽字 × 指令数无无
E1 纵向每槽专属 bank（等宽槽 ⇒ 各 bank 同宽），统一深度每拍 M-bit 有效 mask—
E2 条带化N 条等宽 lane（N=max_k），phase 滚动条带每拍 M-bit mask + phase/程序 descriptor—
E6 Multanen 字典每槽可编程字典 + 定长 bundle 装入原宽字bundle 控制位 + 压缩/未压缩标记frame 装载（header + 每字典项一整宽字）+ 字典存储 + 每拍字典读

所有方案做 bit-exact 编码→逐拍恢复自检（沿用已验证脚本）。

6. 统计指标

  • 静态 CR：程序镜像 bit（含 E6 的 frame 装载字、E1/E2 的 mask/config），相对 E0。
  • 动态 CR：动态取指 bit（E6 含字典读与 frame 摊销），相对 E0。对热点循环加权。
  • 运行开销：E6 的 frame 装载周期占总周期比例（对照 Multanen 的 0.13%）。
  • E2 接纳性：每程序 max_k 与 N=max_k 的可行性（周期不变）。
  • CACTI 面积/功耗：各方案的 SRAM 组织（E0 主存、E1 槽 bank、E2 lane、E6 主存+字典）分别建模面积、读能耗、漏电。字典用小 SRAM 宏作代理，并标注"原文用 latch-RF，CACTI 为代理"的口径差异。

7. 风险与缓解

风险 1（最重要）：等宽 ≠ 稀疏。5 槽机器上编译器会尽量填满 5 条总线，CHStone 可能 max_k≈5（稠密），使 E2 的 N=5=M 无收益。缓解：① §4 先测 max_k 再下结论；② E2 收益按程序如实报（稀疏的赢、稠密的平）；③ 论文里 E2 的主证据仍是 FRV（NN 负载天然稀疏），本平台是稳健性/baseline 层，不背 E2 的主结论。
风险 2：E6 是机制级复现。无法拿到 Multanen 确切平台，数字不会等于其 0.71/0.69。缓解：明确标注"独立复现"；如需精确对比，另行联系作者索取 artifact（可作为并行支线）。
风险 3：对称机器可编译性。见 §3.2 的迭代流程；若 5 槽对称机编译失败，退一档加连接/加 RF，或放宽到"近似等宽"（各槽宽差 ≤1 bit）并记录。
风险 4：CACTI 只建模 SRAM。不含解压组合逻辑/时钟树/字典 latch-RF 的真实功耗；面积功耗数字只作方向性对比，不作最终芯片结论。
