分模型程序池压缩实验：BERT / LLaMA / SD-UNet

2026-09-08 ｜ 平台：FRV-SFU-VLIW（174-bit ISA）｜ X=64 ｜ index priority ｜ 三方案：无压缩 / Candidate A / 4slot ｜ 脚本：experiments/model_pool_compression_study.py

研究问题：是否应让一个模型里的非线性 workload 各成一组程序池（按 BERT / LLaMA / SD-UNet 分开统计）？本实验对三个模型各自的非线性函数池，在三种指令存储方案下统计周期数与Bank 深度。结论：三方案周期完全相同（max-4 调度零损失）；4slot 相对 Candidate A 的分配位数在 BERT/SD-UNet 池降 56.7%、在 LLaMA 池降 18.9%；相对无压缩最高降 77.6%。

1. 实验设置

  • 池组成（架构纯净口径，只放该模型真实用到的非线性函数）：
    • BERT（512 序列/768 隐藏/3072 中间维）：Softmax(512)、LayerNorm(768)、Bias+GELU(3072)、Tanh(768)；
    • LLaMA 2（4096 隐藏/11008 中间维）：RMSNorm(4096)、Softmax(4096)、SwiGLU(11008)；
    • SD-UNet（代表尺寸）：GroupNorm(1280)、SiLU(1280)、LayerNorm(768)、Softmax(1024)、GeGLU(3072)。
  • 调度：每函数在 mode 0/1/2 中取周期最短者；无压缩/A 用 MAX_ISSUE_SLOTS=5，4slot 用 MAX_ISSUE_SLOTS=4。
  • 新增 DAG 构造器（基础调度器没有，按 plan §3.1 重实现）：Bias+GELU、RMSNorm、SwiGLU、SiLU、GeGLU、GroupNorm。
  • Bank 深度口径：合并池、取整到 2 的幂。无压缩 = 174b×深度；A = config(5b) + 5×34b 专属 Bank；4slot = config(5b) + 4×34b 共享 Lane。

3. 关键对比与发现

池周期（三方案）4slot vs A 位数4slot vs 无压缩位数A vs 无压缩位数4slot 是否跨越深度边界
BERT7667−56.7%−77.6%−48.3%是（4096→2048）
LLaMA30704−18.9%−58.0%−48.3%否（同 16384 档）
SD-UNet11684−56.7%−77.6%−48.3%是（8192→4096）
  1. 周期零损失：三个池、所有函数，max-4 与 max-5 调度周期完全相同（T4 == T5），4slot 不付出性能代价。
  2. 4slot 相对 A 的收益高度依赖「是否跨越 2 的幂深度边界」：BERT/SD-UNet 中 A 的 VECTOR Bank 顶到上一档（4096/8192）而 4slot 共享后压进下一档（2048/4096），位数 −56.7%；LLaMA 池事件量大、未跨档，收益只剩「少一个 Bank」（−18.9%）。
  3. 宏种类：无压缩 1 种、A 与 4slot 各 2 种（config + payload）；4slot 的 payload Bank 数比 A 少一个（4 vs 5）。
  4. 分池的价值：按模型分池后，BERT 与 SD-UNet 池因事件规模适中而能跨深度边界、收益显著；LLaMA 池（SwiGLU Y=11008 主导）事件量大、深度档位饱和，收益收窄。这说明「按模型/负载规模分池」直接影响压缩收益，支持按模型分开统计。
