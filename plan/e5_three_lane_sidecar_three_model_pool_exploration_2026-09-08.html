1. 先回答：三层故事成立，但第三层必须从 E5-R 修正为 E5-B

论文中的层次解决的问题本轮证据判断
第一层：只存有效槽，槽和 Lane 解耦Candidate A 的五个专属 Bank 事件数差异大，却为了通用替换而全部按最忙 Bank 定深。E2 把所有有效事件均衡分到四个共享 Lane；BERT、SD-UNet 都跨到更浅的 SRAM 档。成立 是最稳定的主贡献。
第二层：max-5 改成 max-4五槽同拍极少，可通过静态调度利用其它空闲拍消化，从而少一个共享 Lane。BERT 只有 5 拍、SD-UNet 只有 3 拍五槽同发，LLaMA 为 0；三池 max-4 周期与 max-5 完全相同。成立 但结论仅覆盖本实验域。
第三层：原始 E5-R，只把四槽拍的第 4 个事件送侧道希望把第四条深 Lane 换成很浅的侧道。只在 LLaMA 池节省；BERT/SD-UNet 的三条主道被迫翻倍。不能直接使用 “四槽稀少”不是充分条件。
第三层修正：E5-B，容量平衡侧道侧道除了接必需的第 4 个事件，还分担少量普通周期事件，使三条主道留在较浅一档。三个池均保持原调度和原周期，逐 bit 恢复通过；预估面积相对 E2 为 −10.1%/−22.3%/−9.8%。值得做 RTL 软件证据正向，尚未综合。

表头说明：“层次”是论文叙事顺序；“解决的问题”说明每一步为何存在；“本轮证据”只写本次实际统计或验证；“判断”区分已成立、已否定和仍需 RTL 的内容。

2. 小白版：E0、E1、E2、E5 到底分别是什么

处理器每拍最多控制 LOAD、STORE、VECTOR、SCALAR、SFU 五类硬件。可以把一条 VLIW 想成一张五栏表格，每栏 34 bit。某栏本拍不工作，就是空栏（NOP）。

名字存储方式优点问题
E0：不压缩每拍保存完整 174-bit 调度字，空栏也保存。硬件最直接。大量 NOP 占空间，每次读取整条宽字。
E1：Candidate A 纵向压缩5-bit mask 表示哪些栏有效；五类槽各有自己的 34-bit Bank，只保存自己的有效操作。删除 NOP，解码简单。Bank 与槽绑定。VECTOR 很忙、SCALAR 很闲时，各 Bank 长短悬殊；为可替换性统一深度会浪费。
E2：四条共享 Lanemask 不变；任何有效槽都可写入四条共享 Lane，用 phase 轮转均衡。静态调度保证每拍最多四个有效槽。Lane 与槽语义解耦，负载均衡；比 E1 少一个 payload Bank。四条 Lane 仍必须一样深；四槽同拍很少时，第四条深 Lane 看起来利用不足。
E5-R：原始 E5前三个有效事件进入三条主道；仅四槽同拍时，第 4 个事件进入小侧道。不加 Config bit；侧道访问极少。主道承担几乎全部事件，单道平均负载从约 E/4 上升到 E/3，可能跨入两倍深的 SRAM。
E5-B：本轮修正版四槽同拍仍必须用侧道；另外选择一些普通周期，把最高 rank 的一个事件送侧道。6-bit Config 中新增 spill 标志。可以主动把三条主道压在目标深度内；不重新调度、不增加周期。Config 多 1 bit；需要离线选择 spill 周期；mod-3 phase 和新 RTL 尚未综合。

表头说明：“存储方式”是每个方案真实保存的数据；“优点/问题”说明为什么要从上一层继续演进。这里的“4slot”不是 4-bit 指令，也不是固定四种模板。

6. 原始 E5-R 为什么会在两个池中失败

令 E 为池中所有有效事件数，Q4 为四槽同拍周期数。原始 E5 每个四槽拍只把第 4 个事件送侧道，因此：

E2 单 Lane 深度 D2 = pow2ceil( ceil(E / 4) ) E5-R 主道事件数 Emain = E − Q4 E5-R 单主道深度 Dmain = pow2ceil( ceil(Emain / 3) ) E5-R 侧道深度 Dside = pow2ceil(Q4) 原始 E5 不让主道变深的必要条件：E − Q4 ≤ 3 × D2

“四槽同拍很少”只保证 Dside 很浅，却意味着几乎所有事件仍要挤进三条主道。三条主道平均承担 E/3，比 E2 的 E/4 高约三分之一；一旦越过 2 的幂边界，主道深度直接翻倍。

7. 修正版 E5-B：让侧道承担“容量溢出”，而不只承担四槽峰值

7.1 每拍怎样编码

输入：E2 已经合法的 max-4 schedule 若本拍有 4 个有效槽： 前 3 个 → 三条主道；第 4 个 → 侧道；spill=1（必须） 若本拍有 1～3 个有效槽且被离线算法选中： 最高 rank 的事件 → 侧道；其余 → 三条主道；spill=1（可选） 其它周期： 全部有效事件 → 三条主道；spill=0 Config = {spill, 原 5-bit slot mask} 三条主道内部继续轮转：lane = (phase3 + rank) mod 3 每拍结束：phase3 = (phase3 + 主道事件数) mod 3

为了减少布线，本次没有允许任意事件进入侧道。可选 spill 只从“本拍最高有效槽是逻辑槽 3 或 4”的周期中选择；四槽周期的第 4 个事件天然也只可能是槽 3 或 4。因此侧道输出只需连接最后两个槽。三条主道仍可恢复五个槽。

7.2 离线算法怎样选容量

  1. 枚举 2 的幂主道深度 Dmain 和侧道深度 Dside，要求 Dside ≤ Dmain/2，确保它确实是“小侧道”。
  2. 所有四槽周期必须进入侧道，因此侧道事件数至少为 Q4。
  3. 三条主道总容量为 3×Dmain；若总事件超出，侧道至少还要吸收 E−3×Dmain 个事件。
  4. 从合法候选周期中按程序顺序选择额外 spill；每个程序 EOP 后 phase 归零。若多程序 phase 重置使某条主道多出 1～2 项，就再 spill 少量事件直到三道都不越界。
  5. 对可行组合调用 CACTI，选择 SRAM 面积最小者；不是根据函数名字训练字典。

8.4 不应忽略的部署口径

如果一个物理核只需要“轮流替换”三个模型池，并统一按最大的 LLaMA 池定深：E2 为 4×16384；原始 E5-R 用 3×16384 + 1×128 已能容纳三个池，统一 8-bit Config 的预估面积约从 0.6236 mm² 降到 0.4842 mm²（−22.4%）。但这会让 BERT/SD-UNet 使用严重过量的存储。若三个池分别右定尺寸，或者将来需要多个池同时常驻，仍必须使用 E5-B 或重新求联合容量。论文必须先说清“分别定制、覆盖替换、同时常驻”是哪一种，不能混用最有利数字。

8.5 为什么这些数字与已有 28nm RTL 表不同

仓库已有的三程序小池（Softmax/LayerNorm/GELU X64）完成过 28nm RTL 综合：E0/E1/E2 分别为 289,077/96,268/80,364 µm²，39.41/6.029/5.44 mW。本节新表使用更大的 BERT/LLaMA/SD-UNet 池和 CACTI 32nm，并沿用最新软件文档的 174-bit E0；已有 RTL 为删去三个保留位后的 171-bit E0。因此只能比较同一张新表内的相对趋势，不能把新表绝对数与旧 28nm 数字直接拼接。

9. E5-B 的硬件实现、关键路径和真实风险

9.1 推荐三拍流水

流水阶段做什么相对 E2 的变化
A：Config 地址按 PC 读取 6-bit {spill,mask[4:0]}。Config 多 1 bit；EOP 可定义为 spill=0, mask=11111。
B：Config 解码和 payload 地址由 mask 得到有效槽顺序；spill=1 时最高 rank 送侧道；其余最多三个事件生成主道 enable。三主道指针和侧道指针前递。mod-4 phase 改为三状态 phase；不能用简单低两位截断。
C：payload 返回和散布三条主道经 3→5 散布；侧道只连逻辑槽3/4；mask 决定无效槽输出 NOP。路由门当量预估约低于 E2 的完整 4→5；必须用综合确认线长和时序。

表头说明：三个阶段与 E2 保持同样 II=1、固定三拍延迟。这里的“阶段”是流水位置，不代表一条指令需要停顿三次；流水填满后仍每拍输出一条完整 VLIW。

9.2 mod-3 不需要除法器

E2 的模 4 可以直接取低两位，E5 的模 3 是真实新增风险。但硬件不需要做通用除法：phase 只有 0、1、2 三种状态，主道事件数只有 0、1、2、3 四种情况，只需一个 3×4 的小真值表。主道事件数为 3 时 phase 不变；为 1/2 时按固定三状态跳转。应在 RTL 中写成明确 case 或组合加减，并综合检查 Config-Q 到 payload-CEN 的路径。

9.3 E5-B 仍然是通用编码，不是 workload 字典

  • 硬件不认识 Softmax、RMSNorm 或模型名字，只读取 mask 和 spill。
  • spill 周期由装载/编译工具根据目标 Bank 容量选择，类似链接器把代码段放入存储区，不需要运行时训练。
  • 任何 max-4 程序都可编码；能否装入某个固定深度由容量接纳检查决定。
  • 如果目标程序没有足够的槽3/4候选 spill，可以退回更深主道、允许侧道连接五槽，或判定该容量配置不接纳；不能静默破坏功能。

9.4 当前最主要的风险

风险为什么可能发生下一步怎样关闭
浅侧道不一定有合适 foundry SRAM 宏128/1024/2048 深的 34-bit 宏可能需要 SCM、寄存器或多种 compiler 选项；最小宏面积可能吞掉软件容量收益。先查真实 SRAM compiler 菜单；分别综合 SRAM、SCM、寄存器三种侧道实现。
mod-3 使能路径变慢Config Q 到主道 CEN/地址是关键路径，E2 的 mod-4 更简单。写 E5 RTL，使用三状态查表；目标 1 GHz，报告 slack。
E5-B 多一个 Config bit如果 foundry 只有精确 5-bit 和 6-bit 宏，面积/能耗并非完全相同。同时报告原生 5/6-bit 宏和统一 8-bit 端口；本报告主表已采用后者防止 CACTI 跳变。
额外 spill 不再“极罕见”BERT/SD-UNet 侧道事件约占总周期 12.8%/10.6%，虽仍低频，但不是原始 Q4 的不到 1%。论文用“容量平衡 overflow lane”，不要继续声称侧道只处理极罕见四槽拍。
控制流入口状态分支/循环入口需要恢复三主道指针、侧道指针和 phase。每个程序/基本块 descriptor 保存四个 base 和初始 phase；做随机切换与回跳仿真。
软件 PPA 误差CACTI 32nm 与实际 28nm 宏、布局布线不同；门当量不是网表。不得把本报告百分比写进摘要，直到 RTL+真实宏+SAIF/VCD 完成。

表头说明：“风险”是当前尚未被实验关闭的部分；“原因”说明为什么软件正结果可能在硬件中反转；“关闭方法”是形成论文证据所需的具体动作。

10. 论文叙事和创新点应当怎样调整

10.1 推荐的完整叙事

  1. 观察一：语义槽负载不均衡。纵向压缩虽然删除 NOP，但把存储 Bank 永久绑定到 LOAD/STORE/VECTOR/SCALAR/SFU，统一深度时受最忙槽支配。
  2. 方法一：槽/Lane 解耦。有效操作进入可共享 payload Lane，mask+rank+phase 在固定周期内恢复语义槽，解决槽间高度不均衡。
  3. 观察二：峰值 issue width 不等于有效 issue width。三个模型池的五槽同发只有 5/0/3 拍；max-4 静态调度保持周期不变，因此从五个存储端口降到四个。
  4. 观察三：四槽同发低频，但单纯稀有侧道存在 SRAM 深度悬崖。原始 E5 在 2/3 池反而更差，说明“看直方图挑小侧道”不够。
  5. 方法二：量化感知的容量平衡侧道。联合选择主/侧道深度和 spill 周期，使每拍仍至多三主+一侧、schedule 不变，同时避开 2 的幂容量台阶。
  6. 硬件：确定性三拍恢复。无字典、无运行时仲裁、无可变解压延迟；通过 Config 的显式 spill bit 保留通用性。
比原始 E5 更像论文的地方：E5-B 的创新不再是“发现四槽拍少，所以把第四 Bank 做小”这一句经验性优化，而是把静态调度的逐周期端口约束、SRAM 离散深度和事件到 Bank 的映射联合起来。原始 E5-R 是一个重要消融：它在 BERT/SD-UNet 失败，反过来证明容量平衡算法不可缺少。

10.2 建议贡献表述

  1. 提出语义槽与物理 Lane 解耦的有效事件存储，实现每拍完整 VLIW 的确定性恢复。
  2. 提出面向程序域的 issue-width 接纳方法：只在周期损失阈值内减少物理 Lane 数，而不是假定所有程序都稀疏。
  3. 提出 SRAM 深度量化感知的非对称主道/侧道映射，在不改变已有 schedule 的情况下选择 spill，避免原始 rare-only 方案的 2× 深度悬崖。
  4. 在 BERT、LLaMA、SD-UNet 三个模型程序池上同时给出容量、性能、恢复正确性和 RTL PPA；最后一项目前尚待完成。

11. 接下来最合理的具体工作

  1. 先做 E5-R/E5-B RTL 编码器和解码顶层。不要一开始做调度优化；直接使用本次已经生成的三个池 schedule 和新脚本输出。
  2. 做池模式逐 bit 回归。覆盖 BERT 4 个程序、LLaMA 3 个、SD-UNet 5 个，采用非连续切换顺序；检查 config 读数、三主道读数、侧道读数和 phase reset。
  3. 综合四个尺寸工作点。至少实现 main/side=2048/1024、4096/2048、16384/128，再加一个统一最大配置；报告 1 GHz slack、面积、功耗。
  4. 侧道实现消融。比较真实 SRAM 宏、SCM 和寄存器；尤其关注 34×128 小侧道，因为 CACTI 对超浅宏可能过于乐观。
  5. Config 端口消融。分别综合 5-bit E5-R、6-bit E5-B 和统一 8-bit 物理实现。
  6. 论文必需消融。E2、E5-R、E5-B 三者必须同时出现；否则读者看不到深度悬崖和容量平衡映射的必要性。
  7. 再扩大域。在跨平台工作中定义的其它 VLIW/CGRA trace 上检查“可选侧道候选是否足够”，验证算法不是五槽 FRV 专用技巧。

13. 最终建议

继续探索，但不要直接实现旧 E5-R 后就写论文。推荐把 E2 作为已经有真实 RTL 证据的主基线，把 E5-R 作为揭示 SRAM 深度悬崖的必要消融，把 E5-B 作为真正进入下一轮 RTL 的候选。若 E5-B 在三个尺寸下仍满足 1 GHz，且真实宏总面积相对 E2 保持约 8% 以上下降，这条“调度接纳 + 槽/Lane 解耦 + 量化感知非对称侧道”的故事足以比单一四 Bank 压缩完整得多；若浅侧道宏或 mod-3 关键路径抵消收益，则保留 E2 为最终架构，并把 E5 的负结果写成设计空间分析，不能强行宣称成功。
