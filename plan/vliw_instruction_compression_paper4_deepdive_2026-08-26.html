一、本轮相对交接文件的三处实质修正

修正 1：交接文件 §6 的"周期描述符—有效负载双流 / RAW-SPARSE-TEMPLATE 多模式"不能作为论文创新点。 经全文核实，Conte 等人 1996 年 MICRO 的 TINKER 压缩编码已经是"删 NOP + header/tail 位界定 MultiOp 边界 + 变长取指 + 缓冲平滑"，ρ-VEX 的 sparse encoding（ReConFig 2015）就是"mask word 指示后续 bundle 中哪些操作存在"。这两者合起来已经覆盖了 Descriptor+Payload 与 SPARSE 模式的全部要点。TTA 的 template-based compression（SAMOS 2014 / IJPP 2018）覆盖了 TEMPLATE 模式。把它们重新包装会被审稿人直接命中。
修正 2：第三篇指令流的主导冗余不是"空槽"，而是"周期性重复"。 第三篇的调度器（Algorithm 1）把整个工作负载展平成一条逐周期的直线指令流，没有任何分支/循环指令，以 EOP 结束。但工作负载本身是"同一个小 DAG（Softmax 8 个算子、LayerNorm 17 个算子）在成百上千个向量分段上重复"。于是展平后的指令流在稳态下是严格周期的：同样的槽位模式每隔一个固定的启动间隔 II 重复一次，只有寄存器索引在按固定步长平移。用论文自己的数据可以验证（见 §五）：GELU(512×3072) 的 24603 周期 ≈ 6144 个分段 × 4，误差 0.1%。这意味着可压缩上界远高于掩码方案能达到的水平。
修正 3：第三篇没有报告 VLIW 位宽、槽位字段、NOP 编码，也没有报告指令存储的面积/功耗。 Table V 的模块面积分解里根本没有指令存储这一项（只有 VECTOR / SFU / SCALAR / VGPR / SGPR / Decoder-Crossbar-Others）。所以第四篇必须先自己把"基线指令存储代价"建立起来。好消息是：三篇论文第一作者都是本人，RTL 与调度器源码在手，这不是研究风险，只是一项必须先做的取数工作——不要靠推算写进论文。

8.1 主推方向 D1 详解

一句话：编译器为了适配无循环的 ISA，把一个事实上的模调度展平成了几千到几万条直线指令；D1 用一个编译后处理把它卷回去，再用一个极小的硬件前级在运行时逐周期再生，且保证与展平流逐位完全一致。

编译侧四步

  1. 周期结构识别。对调度器输出的展平流寻找最小启动间隔 II 与稳态核 K（长度 II 的槽位模式），使得对所有稳态周期 t，Instr[t] = K[(t−t₀) mod II] 在除寄存器索引外的所有字段上逐位相等。实现上是对 trace 做自相关 / 最小周期检测，O(T log T)。
  2. 仿射规则拟合。对寄存器索引字段拟合 reg = (base + k·stride) mod depth，k 为迭代序号，depth = 256（VGPR/SGPR 深度，p.9 §VI-B）。同样对 Ping-Pong Buffer 地址字段拟合。
  3. 残差分离。无法归入周期核的周期（prologue、epilogue、跨分段的层次归约节点）作为残差流，交给 D2 的掩码编码处理。
  4. 产出 {prologue(S1), K(定宽 II 条), 仿射规则表, 迭代次数 S, epilogue(S1)}。

展平流（现状，6144 段 × 4 = 24576 条 × ~150 bit ≈ 3.7 Mbit）： cycle 0 : LOAD v0 ← buf[0] cycle 4 : LOAD v3 ← buf[3] cycle 1 : SFU v1 ← GELU(v0) cycle 5 : SFU v4 ← GELU(v3) cycle 2 : NOP cycle 6 : NOP cycle 3 : STORE buf[0] ← v2 cycle 7 : STORE buf[1] ← v5 ... 重复 6144 次，仅寄存器号与 buffer 偏移平移 ... D1 编码： K[0] = LOAD vR(0) ← buf(0) 规则: vR(i) = (base_i + k) mod 256 K[1] = SFU vR(1) ← GELU(vR(0)) buf(j) = base_j + k K[2] = NOP II = 4, S = 6144 K[3] = STORE buf(0) ← vR(2) prologue/epilogue → 掩码编码 核存储 ≈ 4×150 = 600 bit + 规则表 ≈ 200 bit + 残差 ≈ 数十条 3.7 Mbit → 数 kbit

寄存器分配细节（活跃区间回绕、bank 冲突约束）须按实际调度器输出核对；此处仅说明编码形态。

8.2 保底方向 D2 · 掩码 + 模板 + 字段字典

即前文的 S1（6 bit 槽位掩码 + payload 按槽分 bank）与 S2（模板 ID + 逐槽字段字典）。无论 D1 成败都必须实现，因为它同时是三件事：D1 的残差编码器、论文的对照基线 B1/B2、以及 D1 被否时的兜底方案。

S1 编码

周期 t mask=100010 → LOAD, SFU 有效 DESC : 1 0 0 0 1 0 (6 bit) PAYLD: [LOAD 28b][SFU 24b] (52 bit) 合计 58 bit (原 ~150 bit) 周期 t+1 mask=000000 → 全 NOP DESC : 0 0 0 0 0 0 (6 bit) 合计 6 bit (原 ~150 bit)

Payload 按槽位分 6 个 bank，每 bank 读地址由自己的 mask 位累加得到，不需要跨槽变长对齐器——这是相对经典变长取指的一处实质简化，源自第三篇无分支这一结构性优势。

S2 编码

模板表 (compile-time, 16 项) T0 = 000000 (全 NOP) T1 = 100010 (LOAD+SFU) T2 = 000110 (VECTOR+SFU) ... 周期 t : [T=0001][SFU.Op=idx2][VGPR src/dst] 4 bit + 3 bit + 16 bit = 23 bit

预期压缩率 3.5×～8×（≈ 加权槽位利用率倒数）。该数字不构成论文创新，只是基线。最坏情况是连续多周期 6 槽全满，压缩退化为 1×，须在 FIFO 下界模型中显式覆盖。

8.3 必做配套方向 D3 · 掩码驱动的解码与分发门控

第三篇 Table V：Decoder/Crossbar/Others = 0.166 mm² / 0.156 W（占总功耗 4.3%）。而按 §5.1 推导，每周期 71%～88% 的槽位是 NOP——这意味着 crossbar 每个周期都在把 NOP 的控制字段分发到各计算模块。用已有的 mask 位做时钟门控/操作数门控，可以省掉这部分翻转功耗，而且不需要任何新信息：mask 本来就是 D2 编码的副产品。

为什么值得单列：它把论文的收益从"省面积"扩展到"省功耗"，覆盖了两个独立的评审关注点。工作量极低（综合时加使能条件），风险极低（不改功能）。这是性价比最高的一个加分项。

需要注意的诚实边界：第三篇没有报告 decoder 内部的翻转率，所以收益上限未知；0.156 W 是这条路径的绝对天花板，实际可省的只是其中一部分。论文里不能写成"省 4.3% 功耗"，只能报实测。

8.5 评估过但不采纳的两个方向

D5 · 逐负载定制 ISA（不做）

按每个负载裁剪槽位宽度与字段编码，能拿到很高的压缩率。

否决理由：直接打脸第三篇的核心卖点。第三篇标题就是 "Fully Reconfigurable and Programmable"，p.2 强调新增复合函数"只需构建 DAG 并重新编译，无需改 ISA 或硬件"。逐负载定制 ISA 会把这条卖点变成谎话——审稿人一定会指出第四篇在拆第三篇的台。

与第三篇论点冲突，明确不做

D6 · 给 ISA 加循环指令 + 旋转寄存器（只作对照）

最"显而易见"的工程答案：既然编译器事实上在做模调度，那就给 ISA 加循环型分支、LC/EC 寄存器和旋转寄存器堆，让它直接发射循环。

不作为本文方案的理由：①这是 1989 年 Cydra 5、2001 年 IA-64 的既有方案，毫无新颖性；②要改 ISA + 调度器 + 寄存器堆，第三篇已发表的 Table III/V/VI/VIII/IX 全部作废，单人 3～4 个月做不完重新验证；③它只覆盖完美周期的部分，残差仍需 D2。

必须作为评估中的对照上界出现
这个方向的最强反对意见，必须在开题时主动提出并回答：
"既然问题是编译器被无循环 ISA 逼着展平，那为什么不直接给 ISA 加循环指令？"

预备回答（三层）：
  1. 可行但不是本文的问题。加循环指令是重新设计一颗芯片；本文解决的是已经存在的静态调度加速器如何在不动 ISA 的前提下拿回指令存储。二者是不同的设计点，不是替代关系。
  2. 本文的可迁移性更强。解压前级对下游硬件透明，可以套到任何"小 DAG × 大量数据实例 + 无循环 ISA + 静态调度"的加速器上；加循环指令则是每一颗芯片各做一次的重新设计。
  3. 但要诚实：如果是设计新芯片，加循环指令可能确实是更好的工程答案。因此论文评估必须把 D6 作为上界对照报出来，明确回答"离理想设计点还差多少"。把最强反对意见做成评估的一列，比回避它可信得多。

8.7 审稿人质疑与预备回答

质疑预备回答
Q1. 这不就是循环缓冲 / 旋转寄存器堆吗？见 §8.1 差异表。核心区分：本文是解压机制，目标是逐位重建原流，寄存器堆/解码器/数据通路零改动；ZOLB 要求迭代逐位相同（此处不成立），旋转寄存器堆要求 ISA 有循环分支与可旋转 RF（此处三个前提全不成立）。
Q2. 为什么不直接给 ISA 加循环指令？见 §8.5 三层回答，并在 Table II 中把 D6 作为上界列出。
Q3. 压缩率高只是因为你的基线（不分块）不合理。正面接受：所有压缩率都在 R = 2/4/8/16/32 全扫描下报告，不只报不分块。核心论证不是"压缩率多高"，而是"折中曲线被压平"。
Q4. 只在一个平台上验证，一般性存疑。把可迁移条件写成明确的三条判据（小 DAG × 大量数据实例、无循环 ISA、静态零停顿调度），并列举满足这些条件的公开架构；不声称在它们上面测过。
Q5. 周期检测在真实负载上会不会退化？Fig. 7 的 Y 扫描专门回答这一点；并明确给出"退化时自动回落 B1、不劣于基线"的保证。
Q6. 解压是否影响主频？报综合结果。由于无分支，增加取指流水级没有分支惩罚——这是该平台的结构性优势，可以用增加级数换时序而不损失性能，这一点要在论文中显式论证。
Q7. 收益是不是只在指令存储上，太局部？D3 的分发门控把收益扩到动态功耗；D4 把收益扩到 buffer 容量与系统折中。三者合起来覆盖面积、功耗、系统三个层面。

第二章（第二篇 SMM-FSM）：非线性函数的概率计算路径。极致面积/功耗，代价是 2048 周期的码流延迟。

第三章（第三篇 FRV-SFU-VLIW）：非线性函数的确定性可编程路径。逐周期发射，延迟确定，代价是宽指令字与控制开销。第二、三章构成同一目标下的两条对立技术路线的完整对比——这样第二篇就不再是孤儿。

第四章（第四篇）：把第三章路线的代价还回去——在不牺牲任何确定性与可编程性的前提下消除控制流开销。全篇形成闭环：提出问题（一）→ 两条路线（二、三）→ 补上主路线的短板（四）。

这一叙事同时解决了交接文件 §4 约束 7 提出的"两篇概率计算 + 两篇 VLIW"结构问题：主题是非线性函数加速，VLIW 只是其中一条路线的实现手段。需与导师确认是否接受这一主线调整（见 §十二 问题 4）。

九、评估模型

9.1 压缩率

CR = (Desc + Payload + Kernel + RuleTable + Residual) ⁄ (T · WVLIW)

必须同时报告四个对照点：B0 = 原始展平流；B1 = stop-bit/mask（S1）；B2 = 模板+字典（S2）；D6 = 给 ISA 加循环指令+旋转寄存器的理想设计点（上界）。只报 B0 会被认为在跟稻草人比较。

9.2 无停顿供给的缓冲下界

交接文件 §6.3 提出的下界模型经核对是正确的，但只适用于 D2：

Fmin ≥ max[a,b] ( Σt=a..b Lt − (b−a+1)·B )

其中 Lt 为第 t 周期 payload 位数，B 为存储每周期供给位数。这是标准的"漏桶"下界，可用前缀和在 O(T) 时间精确求出（求 Σ(L_t − B) 的最大子段和）。

但对 D1，这个模型基本不需要：周期核是定宽的（II 条全宽指令常驻小 SRAM 或寄存器组），稳态下每周期供给量恒定，不存在变长抖动。变长抖动只出现在残差流（prologue/epilogue），而残差流的位置在编译期完全已知，可以静态预取。这是 D1 相对 D2 的又一个实质优势，值得在论文里单独论证。
