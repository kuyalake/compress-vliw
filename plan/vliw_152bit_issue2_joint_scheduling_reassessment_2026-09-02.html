152-bit VLIW 与双发射联合调度

从A/B/C/D详细重判之后的全部分析、讨论、实验、修正与当前结论

本文的时间边界 本文从收到 vliw_compression_abcd_detailed_reassessment_2026-09-01.html 开始记录，完整覆盖其后的讨论与新增实验。此前184-bit结论仅作为历史背景；从本轮起，所有新实验以152-bit指令为基准。

1. 结论摘要

调度性能

+1.66%双发射总周期：20,413 → 20,752。

逻辑容量

25.13%双Lane纵向格式占新调度152-bit原始流。

粗总面积

−4.80%最多两段SRAM + 337 GE解析增量逻辑。

SRAM读能耗

+21.41%通用最大配置运行12条Trace的累计估算。
当前总判断 双发射联合调度的性能结果很好，证明“五个功能单元并不需要每周期都具备五槽发射宽度”； 但双Lane把26/31-bit操作统一补到34 bit，导致读能耗上升。只有在允许每条逻辑流最多拆成两个SRAM宏时， 双Lane才得到6.41%的SRAM面积优势；加入粗逻辑后只剩约4.80%。该结果低于此前设定的15%论文门槛， 当前不足以单独作为第四篇论文核心创新。
  • Candidate A仍是最强工程基线：5-bit Calendar + 五条原生宽度纵向流，无FIFO。
  • 双Lane最有价值的结果是周期代价低，而不是压缩率或能耗已经胜出。
  • “保持无效槽payload、只清零OP”有效降低总线翻转，但也可用于A，不能算双Lane独有收益。
  • CACTI不是目标foundry SRAM compiler；337 GE也不是RTL综合结果，因此尚不能作最终No-Go。

2. 起点：A/B/C/D详细重判带来的结论

收到的最新研究成果已经完成四类候选的重新评价：

候选机制截至9月1日的判断
ACalendar + 五条原生纵向槽流；每槽独立Bank和地址计数器。接近物理Pareto，简单可靠，但接近Li 2020，不能单独作为新创新。
B单256-bit packet SRAM + deadline供给 + FIFO/Reservoir。单Bank SRAM收益不足以覆盖packet buffer、FIFO和demux，淘汰。
C16-event语义块，RAW/CONST/STRIDE/DELTA和变长抽取。逻辑位数可到16.211%，但约10.8k GE解码器使物理结果失败，仅作软件上界。
DLOAD/STORE的mem_addr和gpr_addr分字段固定差分，带RAW exception流。最大配置粗面积约省8.77%，但Softmax/LayerNorm逐程序反向；只是长规则内存流的局部技术。

文档11.1提出“物理成本驱动的稀疏VLIW指令供给综合”，11.2提出“instruction-capacity-aware scheduling / R-tile协同”。 后续讨论认为11.1偏向EDA设计空间搜索，并且在硬件固定、必须支持多workload的前提下， “按workload选择codec”不成立。因此本轮把重点转向11.2：让静态调度和指令组织共同变化。

3. 第一步修正：建立152-bit新原始基准

3.1 mem_addr的真实含义

一个mem地址不是Byte地址，也不是单个16-bit元素地址，而是一个完整向量行地址：

1 mem_addr = 256 elements × 16 bit = 4096 bit = 512 Byte

将mem_addr从原来的28 bit改为12 bit后，可寻址：

2^12 = 4096个向量行 总片上数据空间 = 4096 × 512 Byte = 2 MiB

该地址空间足以覆盖当前工作负载；例如GELU X64、Y=3072在NUM_VE=256时， 输入需要64×ceil(3072/256)=768个向量行，即384 KiB。

3.2 新LOAD/STORE和总指令格式

LOAD / STORE = 26 bit
[25:24] mem_fmt      2 bit
[23:12] mem_addr    12 bit
[11:10] gpr_fmt      2 bit
[9:2]   gpr_addr     8 bit
[1:0]   optype       2 bit
26 LOAD + 26 STORE + 34 VECTOR + 31 SCALAR + 31 SFU + 4 CONTROL = 152 bit/cycle
后续统一口径 从本轮起，152 bit是未压缩原始指令。184→152减少17.39%属于ISA/地址空间合理化， 不能错误归因于后续压缩算法。正确报告顺序应为： 184→152 ISA优化、152→A稀疏纵向压缩、A→新方案净收益。

3.3 对旧Candidate D的影响

旧D将42-bit LOAD/STORE变为19-bit main record，每事件最多省23 bit； 新RAW只有26 bit，而D main仍约19 bit，每事件只省7 bit，单位事件潜力下降约70%。 依据旧总量粗换算，D相对新A的逻辑优势只剩约5.8%，但恢复器、状态、模加法器和exception流并未消失。 因此D需要用新格式重跑，方向上已进一步弱化。

4. 对11.1“物理成本驱动供给综合”的重判

4.1 它原本要挖掘什么

该方向试图在芯片设计阶段最小化：

Total Cost = Σ SRAM_macro_area(width, depth, ports) + codec logic + exception storage + counters/registers/mux + routing

搜索对象包括每槽使用RAW vertical、fixed predictor或不实例化，宏宽深、端口、分段和流水级。 选择发生在硬件设计/综合时，不是每个workload运行时携带所有codec再动态选择。

4.2 为什么新基准使其潜力下降

LOAD    26 bit
STORE   26 bit
VECTOR  34 bit
SCALAR  31 bit
SFU     31 bit

五个槽现在都接近32/36-bit常见宏宽。原来42-bit LOAD/STORE缩到19-bit所可能跨越的物理宏档位已经大幅缩小； 自动搜索很可能最终仍为所有槽选择RAW。该方向作为工程生成工具仍有价值，但只在本平台上做， 容易被评价为EDA式设计空间探索，且未必产生稳定优化。

讨论结论 不把11.1作为当前首选论文方向。只有扩展成跨多种VLIW/CGRA ISA、包含真实SRAM compiler、 自动生成RTL并在独立Trace上获得稳定收益时，它才可能成为方法论文；四个月内风险偏高。

5. 新假想：每周期最多发射两个功能槽 + 配置槽

5.1 问题重定义

保留LOAD、STORE、VECTOR、SCALAR、SFU五类执行资源，但把指令发射宽度限制为最多两个异构操作。 静态调度器重新安排DAG，而不是压缩后恢复旧五槽Trace的原周期。 

Configuration + Lane 0 + Lane 1

每个Lane最大34 bit，可容纳：
LOAD/STORE 26 bit
VECTOR     34 bit
SCALAR/SFU 31 bit

5.2 5-bit配置码为什么恰好完整

两个Lane不能同时发送同一种功能类型。合法状态数：

两个Lane无效： 1 只有一个Lane有效：5种类型 × 2个位置 = 10 两个Lane有效且类型不同：5 × 4 = 20 EOP： 1 合计： 32 = 2^5

因而5-bit配置码恰好覆盖31种正常Lane映射和1种EOP。 它同时给出两个Lane的valid、目标功能槽、五槽有效mask和EOP。 单操作可自由放在任一Lane，使编译器能够平衡两个Lane的最大深度。

5.3 两种存储方式

固定横向73-bit

5 + 34 + 34 = 73 bit/cycle 73 / 152 = 48.03%

一个SRAM、一拍一行，硬件最直接；但空Lane仍占34 bit，容量明显差于Candidate A。

三条纵向流

Configuration SRAM：5 bit × T
Lane 0 SRAM：34 bit × N0
Lane 1 SRAM：34 bit × N1

无效Lane不存payload、计数器保持。只有三个逻辑Bank、无FIFO、无packet和无变长抽取，是本轮真正评估的格式。

6. 第一轮联合调度实验

6.1 实验方法

  1. 复制152-bit调度器为schedule_v18_issue2.py。
  2. 在每个调度周期加入max_issue_slots=2硬约束；原有DAG依赖、GPR Bank冲突、功能单元占用、写回延迟和mask FIFO约束保持。
  3. GELU固定mode 2，LayerNorm固定mode 0；其余函数重新扫描mode 0/1/2并选周期最少者。
  4. 运行Softmax、LayerNorm、GELU、LogSoftmax、Softplus、LogSumExp，各X=32/64。
  5. 比较对象是此前五槽最佳模式的周期数；新调度必须保证每周期最多两个有效功能槽。

7. 5-bit Configuration + 双34-bit Lane编码实验

7.1 编码、Lane平衡和往返

编码器逐周期读取新调度。双操作采用固定Lane顺序；单操作放入当前较短的Lane， 从而平衡两个流的最终深度。解码器按Configuration分别从Lane流顺序pop， 路由回五个原生槽并补齐无效槽。

  • 全部12条新Trace的最大有效槽数均为2。
  • 全部case的Lane 0与Lane 1最终深度完全相等。
  • 所有配置流和Lane流解码后，与新152-bit调度逐周期逐bit一致。
  • EOP使用配置码31；其余31个码覆盖全部正常映射。

8. 无效槽保持前值、仅将OP置0的低翻转方案

8.1 推荐硬件实现

不需要在指令SRAM中重复写入“上一条字段”。在五个槽输出端使用带使能的保持寄存器：

selected[s] = 1： payload_reg[s] ← new_payload output_op[s] ← stored_op selected[s] = 0： payload_reg[s] 保持 output_op[s] ← 0

这样无效周期只翻转OP字段；operand、地址和控制字段保持上一条有效操作。 无效Lane也不读取SRAM，Lane计数器保持。

9. 32 nm HP CACTI SRAM物理比较

9.1 模型和口径

  • 工具：HP CACTI公开仓库，32 nm、scratch RAM、1个read-write port。
  • 硬件固定支持所有12条workload：每条逻辑流深度取所有程序中的最大值，不按程序重新定制芯片。
  • 字宽按整Byte分配：5→8、26→32、31→32、34→40 physical bits。
  • 深度首先上取2次幂；另评估每条逻辑流最多拆成两个2次幂深度宏。
  • CACTI输出面积、访问时间、cycle time、泄漏和每次读能量；不是目标foundry memory compiler。

10. 双Lane相对A的非SRAM逻辑粗估

在两种方案都使用相同payload保持和OP门控的公平前提下，双Lane相对A主要增加或减少：

  • 增加：约148 bit的Lane 0/Lane 1选择路由，按3 GE/bit估算为444 GE。
  • 增加：5-bit配置码映射解码，暂估100 GE。
  • 减少：五个槽计数器约51 bit变为两个Lane计数器24 bit，按DFF+incrementer 6 GE/bit约省162 GE。
  • 减少：A的L/S/SFU分段输出MUX共83 bit，双Lane两个分段MUX共68 bit，约省45 GE。

该数字只能用于方向筛选 337 GE不是Yosys或商业综合结果，未计真实标准单元驱动、扇出缓冲、时钟树、布线、 Configuration流水、宏选择控制及保持寄存器时钟门控。它说明“逻辑大概率不会完全吃掉3.41×10⁻³ mm² SRAM差值”， 但不能支持论文PPA主张。

11. 正确性和问题边界的变化

11.1 不再恢复旧五槽Trace的原周期

此前硬约束是压缩后第t周期行为必须等于旧Trace第t周期。联合调度会改变某些操作的发射周期， 因而该约束必须重定义：

旧要求： Decoded_new[t] = Original_5slot[t] 新要求： New_schedule在DAG依赖和硬件资源约束下功能等价； Decoded_issue2[t] = New_schedule[t]，逐周期逐bit一致。

第一轮已经验证第二行的编码往返；调度器仍使用原DAG依赖、ready time、GPR Bank冲突和资源占用模型。 但尚未运行完整数值仿真或RTL系统对拍，因此最终还需证明函数输出与旧设计一致。

11.2 无效字段保持是行为等价而非bit等价

无效槽OP=0时，其operand字段不参与执行，可以保持上一有效值。 因此功能行为与全零NOP相同，但152-bit输出字不再逐bit等于“全字段置零”的旧NOP编码。 必须明确形式化边界：OP=0应无条件禁止寄存器写、存储访问、功能单元启动和异常状态更新。

12. 创新性与合理性判断

12.1 如果后续物理结果改善，可辩护的完整机制

候选表述 面向异构稀疏VLIW的调度约束双Lane指令供给：通过静态调度限制每周期最多两个异构操作， 使用完整5-bit Lane映射码本、两条定宽纵向操作流和状态保持式无效槽输出， 联合优化性能、程序容量、SRAM宏组织和取指翻转。
  1. 5-bit码本恰好覆盖31种正常有序双Lane映射和EOP。
  2. 调度器共同优化周期、FUV mode、最多双发射和Lane深度平衡。
  3. 以三条逻辑流替代六条槽流，不依赖FIFO、packet、字典或变长解码。
  4. 通过固定硬件的最大深度比较，而不是逐workload定制硬件。
  5. 以payload保持和OP清零降低无效周期翻转，但公平地作为两种架构均可使用的低功耗机制。

12.2 当前为什么仍不足

  • 限制issue width、VLIW template、clustered VLIW和压缩感知调度均有大量先行工作；不能只声称“五槽改双槽”。
  • 逻辑存储比A增加9.49%，并非更好的压缩率。
  • 单宏配置物理面积增加33.07%；只有允许分段时才小幅胜出。
  • 粗总面积优势约4.80%，低于15%目标，容易被工艺误差、路由和控制抵消。
  • SRAM读能耗增加21.41%，低翻转机制又不是双Lane独有。
  • 联合调度改变旧Trace周期，论文问题已经从“无损压缩前端”升级为ISA/调度/存储协同设计。
当前科学判断 该方向已经通过“性能损失是否可接受”的第一关，但没有通过“相对Candidate A是否有显著物理净收益”的第二关。 现阶段应定义为有价值的kill-test结果或设计空间点，不能宣布核心创新成立。

13. 下一步实验与Go/No-Go

13.1 必须做的验证

  1. 真实目标SRAM compiler：确认是否支持接近768、896、2,272等非2次幂深度，以及分段宏的面积、端口和能耗。
  2. 参数化RTL：实现A和双Lane的Configuration读取、计数器、分段选择、2-to-5路由、保持寄存器和OP门控，使用同一工艺库综合。
  3. 公平功耗：A和双Lane均启用payload保持；以同一12条Trace生成VCD/SAIF，分别报告SRAM、时钟、路由和输出总线功耗。
  4. 功能验证：新调度运行完整数值模型；RTL每周期对拍新调度，最终函数输出与旧五槽设计一致。
  5. 文献边界：重点检查2-wide VLIW、template encoding、clustered VLIW、issue-width-aware scheduling和低切换NOP编码。

13.2 明确的继续门槛

Go

  • 真实SRAM + RTL总面积相对A至少下降10%–15%；
  • 总取指/恢复能耗不高于A，最好下降10%以上；
  • 周期损失保持在当前约2%量级，最坏workload不超过5%–8%；
  • 查新后完整组合仍有清晰差异。

No-Go

  • 面积仍只有约5%收益或依赖特殊宏切分；
  • SRAM/总能耗继续增加；
  • 保持低翻转成为唯一正收益；
  • 创新最终退化为普通2-wide VLIW调度。

若No-Go，应保留152-bit ISA修正和双发射性能实验作为设计空间结论， 但停止把它包装成压缩论文；转向更明确的系统问题，或重新选择第四篇论文主题。
