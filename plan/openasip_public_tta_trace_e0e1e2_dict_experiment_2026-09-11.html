1. "OpenASIP 的 VLIW 做了吗"——为什么没有独立的操作型 VLIW 实验

OpenASIP 的原生静态多发射模型就是 TTA。README 原文："The internal processor template of OpenASIP is based on the … Transport Triggered Architecture (TTA), which is still its default target programming model for static multi-issue designs. OpenASIP, however, also has initial support for other programming models such as standard operation-based VLIW (demonstrated in Blocks CGRA) and … RISC-V."

对仓库 artifact 的逐条核查结果：

  • Blocks CGRA（操作型 VLIW 演示）：工作流是 blocks_translator 把 Blocks 架构 XML（generic_blocks_vliw_arch.xml）翻译成 TTA ADF（实测翻译出 51 总线/20 FU/8 RF 的 TTA 机器）；其示例程序 binarization.tpef 配 blocks_risc.adf——后者是 10 条 32-bit 总线、带 segment/guard 的标准 TTA 机器，程序仍是 move-slot TPEF。所以"OpenASIP 的 VLIW"在 artifact 层面就是 TTA 格式，用本实验的 TTA 解析器即可分析，已补做（见 §4/§5 的 blocks_vliw_binarization）。
  • RISC-V 支持：是标量定制（operation-triggered format），不是 VLIW；仓库中没有已调度的 RISC-V/operation-triggered 多发射程序 artifact（全仓检索 operation-triggered ADF/BEM 与 riscv TPEF 均无）。

结论：不是"只做了 TTA 而没做 VLIW"，而是 OpenASIP 公开仓库里不存在独立编码的操作型 VLIW 指令流 artifact；其 VLIW 能力以"翻译到 TTA 内部模板"的方式提供，因此本实验覆盖的 TTA trace 已经包含了 OpenASIP 唯一的 VLIW 演示程序（Blocks binarization）。

2. 为什么不能直接跑 OpenASIP 工具链（证据）

README 要求 Unix/Linux（macOS 为 experimental），依赖其打过补丁的 LLVM（tools/scripts/install_llvm_*.sh）、boost、xerces-c、sqlite、tcl、cmake 等；本机（macOS 沙箱）无 cmake/brew/docker，会话内无法构建。因此改为直接解析仓库内公开的预编译产物：TPEF 程序二进制、BEM 编码映射、ADF 机器定义、测试套件 golden 参考（RTL 总线 trace、PIG 程序镜像）。CHStone 只有 C 源码和参考周期数（topresults.csv），无预编译 TPEF，其 TTA trace 需在 Linux/CI 上构建 tcecc 后生成（后续工作）。

3. 方法：从公开仓库 artifact 重建 slot 级 trace

  1. TPEF 解析器（逐字段复刻 src/base/tpef/TPEFHeaders.hh、TPEFCodeSectionReader.cc 等）：每条指令每个 move slot 的 (源, 目的, guard, 立即数) 符号化值；相同符号值 ⇔ 相同编码比特。
  2. BEM 解析器（按 src/base/bem/ 各类 width() 规则）：每个 move slot 的位宽与全指令宽度。
  3. 动态 trace 重建：fft_simm.asm 头部自带 BB 频次（BB0×1；5×{BB1, BB2, BB3×84, BB4, BB5}），拼成 5234 周期动态序列。
  4. 四种方案（与 FRV 程序池同口径）：E0 不压缩；E1 纵向（每槽独立事件流 + 有效 mask，等深取 2 的幂）；E2 条带化，lane 数 N 按 trace 最大并发自适应（方案本意），有效事件按 slot 序、phase 滚动分配到 N 条 lane；DICT（Multanen 2024 式每槽可编程字典 + 定长 bundle + frame 装载，选择性压缩）。

6.1 为什么这些 TTA trace 上 E1 > E2：宽度异构惩罚的定量分解

程序lane 宽（=最宽 move 槽）E1 原生位宽 payloadE2 等宽 lane payload宽度惩罚
fft_simm213,1428,5892.73×
fft_limm / limm_opt103,0114,0801.35×
fft1024_compiler_28bus223,70211,1543.01×
结构性解释（E2 的适用条件被精确刻画）：条带化要求任意槽的值可落到任意 lane，因此 lane 宽必须取所有槽的最大值。FRV 的 5 个槽等宽 34-bit，无惩罚；而这些 TTA 机器的槽宽从 5 bit 到 21/22 bit 不等，惩罚 1.35×–3.01×。同时，稠密 FFT 代码里各槽事件数本就接近（多数槽 28–32 个事件），E1 的"等深取整到最长流"浪费很小；E2 相对 E1 的剩余优势（跨槽均衡深度）被宽度惩罚吃掉。E2 的胜出条件 = 槽宽齐（无惩罚）+ 各槽事件数不均衡（E1 深度浪费大）+ 跨 SRAM 深度档位——FRV 三条全占，这四条 TTA trace 一条都不占。

6.2 解决位宽异构：宽度分组条带化（E2-G）与混合方案（E2-H）

针对 §6.1 的宽度惩罚，实验了两种"化整为零"的条带化变体（均通过 bit-exact 往返验证）：

  • E2-G（宽度分组条带化）：把槽按位宽分成若干等宽类，每类内部独立做 phase 条带化，lane 宽 = 该类最大槽宽。窄槽不再被最宽槽拖累。
  • E2-H（混合）：超过阈值 T 的宽槽各自留专属 bank（E1 式），其余窄槽共享条带 lane。

结论：位宽异构是可以解决的，且"划分多个等宽 lane 组"（E2-G）有效。
  • E2-G 在四条 trace 上都赢 E1（统一深度口径下 61%/58%/61%/63% vs E1 的 63%/62%/63%/63%；每类自深度口径下进一步到 57%/58%/61%/41%），且动态取指与 E1 完全相同（等宽类 ⇒ 每周期按原生槽宽读，fft_simm 两者同为 624,109 bit）——即"E1 的动态能耗 + 更优的静态容量"。
  • 收益机制拆解：① 窄 lane 代替最宽 lane，消除 1.35–3.01× 宽度惩罚；② 同类内互补活跃的槽共享 lane（lane 数 < 槽数，如 fft_simm 的 7 个 5-bit 槽只需 6 条 lane）；③ 每类独立深度（宽松口径）让稀疏类不再向全局最长流对齐——28bus 上 41%→63% 的差距正来自此，统一深度后与 E1 持平，说明该口径差异是 28bus 大幅领先的部分原因，写论文时必须分开声明。
  • E2-H 不优于 E2-G，分组条带化是更干净的形式。
  • 对论文：E2-G 可作为 E2 在槽宽异构机器上的推广形态——"逻辑槽 → 物理 lane 解耦"的核心不变，只是 lane 按宽度分组。这把 E2 的适用范围从"槽宽齐"扩展到"槽宽异构"，是一个可以成立的扩展贡献点。

8. 对第四篇论文的意义

  • regime 对照成立：OpenASIP FFT TTA = "槽密集 + 值重复 + 槽宽异构"（E2 可行但不及 E1；字典动态有效）；FRV = "槽稀疏 + 值不重复 + 槽宽齐 34-bit"（E2 有效、字典无效）。两个平台合起来把 E2、E1、字典的适用边界划得很干净。
  • E1 在两个 regime 都稳定约 -37% 静态容量，是稳健纵向基线；E2 的优势窗口由"槽宽齐 + 事件不均衡 + 跨深度档"三条件刻画，本实验给出了反例侧的定量证据。位宽异构可用"宽度分组条带化 E2-G"解决：四条 TTA trace 上 E2-G 均不劣于/优于 E1（统一深度 61%/58%/61%/63%，每类自深度 57%/58%/61%/41%），动态取指与 E1 相同——这是 E2 向槽宽异构机器的一个可成立推广。
  • Blocks VLIW（binarization，10 总线 max_k=3）属于稀疏 regime，是本批唯一 E2 同时赢 E1/E0 的程序（E2 N=3：1,264 vs E1 2,000 vs E0 5,440，ADF 估计位宽）；它把 E2 的胜出条件（稀疏峰值 + 可接受 lane 宽）在 OpenASIP 公开 artifact 上正面演示了一次，但程序仅 33 条、位宽为估计值，只能作方向性证据。
  • CHStone/Embench 的 TTA trace 需构建工具链（patched LLVM + 全套依赖，Linux），建议作为 CI/后续工作。

9. 证据边界

  • 本实验是独立复现，不是 Multanen 论文平台：其 .adf/.bem、二进制、动态 trace、2024 压缩器代码均未公开。
  • 自研 BEM 位宽与 PIG 实际打包有小差异（fft −6~−8 bit；28 总线 221 vs golden 255）。所有方案统一同口径位宽，相对比较公平；绝对容量同时给参考宽度。该偏差不影响 max_k、占用分布、字典可压性、动态取指比等结构性结论。
  • 动态能耗未计组合逻辑/时钟树；字典读为 latch-RF 小存储，不能与主 SRAM bit 直接相加。
  • tremor.tpef 为未调度顺序形式（max_k=1），已排除出 VLIW 占用结论。
  • OpenASIP 无独立编码的操作型 VLIW artifact（Blocks 经翻译进 TTA；RISC-V 为标量），本实验的 TTA trace 已覆盖其唯一 VLIW 演示程序。
