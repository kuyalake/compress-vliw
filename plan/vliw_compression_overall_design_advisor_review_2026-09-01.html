FRV-SFU-VLIW 指令压缩整体方案设计

导师评估版：融合 2026-08-31 方向评审后全部讨论、修正与新增定量结果

日期2026-09-01
目标周期单人 3–4 个月
当前状态方案候选，尚未物理闭环
实证规模6 workloads × X=32/64
阅读口径 本文将“软件逻辑位数”“固定包后的实际存储位数”“SRAM 宏物理面积”和“包含 FIFO/恢复器后的总面积”严格分开。 当前已有前两类数据；真实 SRAM、有限 FIFO 和 RTL 综合尚未完成，因此本文给出的是供导师决定是否进入实现阶段的设计提案， 不是已经完成的芯片结论。

1. 执行摘要与当前判断

修正后的首要方案：Candidate A，直接分槽读取 压缩指令完整驻留片上 SRAM 时，最自然的实现是 5-bit Mask SRAM + 五个原生宽度槽 SRAM + 五个独立地址计数器。 每周期先得到 mask，各有效槽 Bank 并行读一条并递增本槽地址，无效槽直接补 NOP。 除固定 SRAM 流水寄存器外，不需要深 FIFO、stream ID、packet demux 或供给期限调度。

Candidate A：默认实现

六个分离 SRAM，按 mask 直接并行读

逻辑有效量 21.74%；必须取得真实宏的深宽取整、外围面积和读能耗。

Candidate B：条件候选

单/少 Bank fixed packet + 有限 FIFO

256-bit包为22.79%，128-bit包为27.33%；均未计FIFO与恢复器。

论文生死线

Candidate B 总成本显著优于 A

如果A更优，则Bank Folding方向失败，不能把增加FIFO本身称为创新。

当前不能声称“核心创新已经成立” 5-bit mask、RAW 槽流、固定包和 FIFO 各自都不是新原语。本文只有在证明 “编译期供给期限约束的包交织 + 多逻辑槽流向单物理 Bank 的时间折叠 + 周期精确零停顿 + 真实物理净收益” 这一完整闭环后，才具备可辩护的新颖性。如果 Candidate A 优于 B，则当前候选创新被否决； 直接分槽虽然是正确实现，却接近 Li 2020，只能作为 Baseline，不能包装成本文核心创新。

2. 平台、指令特征与不可妥协约束

2.1 原平台

目标平台是已有论文提出的 FRV-SFU-VLIW 非线性函数加速器。静态调度器把函数 DAG 映射成无分支、 按周期顺序执行的 VLIW Trace。硬件每周期消费一条 184-bit 指令，直到最后一个 EOP 周期。

槽位宽主要字段当前 NOP
LOAD42mem_fmt、28-bit mem_addr、gpr_fmt、8-bit gpr_addr、optype全零
STORE42mem_fmt、28-bit mem_addr、gpr_fmt、8-bit gpr_addr、optype全零
VECTOR34half、imm、connect、dst/src1/src0、mask、optype全零
SCALAR31imm、connect、dst/src1/src0、mask、optype全零
SFU31borrow、dst/src、is_vector、rounds、optype全零
CONTROL4reserved(3)、eop(1)仅末周期 EOP 有效

2.2 设计硬约束

周期行为严格一致

  • 第 t 周期的每个槽必须与原 Trace 第 t 周期一致。
  • 不允许提前执行、延迟执行、重新调度或插入气泡。
  • NOP 位置、同周期并行关系和 EOP 周期均保持。

压缩驻留与零停顿

  • 片上指令存储保存压缩格式，不能放一份等容量全宽展开副本。
  • Candidate A 可直接流水读取；Candidate B 可以提前恢复到 FIFO，但只能在原周期输出。
  • 正式执行期间每周期必须形成完整 184-bit VLIW。

通用格式

  • 所有非线性 workload 使用相同包格式、相同硬件和相同编码算法。
  • 不允许每个 workload 训练不同字典或选择任意字段编码器。
  • 编码内容不同是程序数据不同，不等于方案不同。

低开销

  • 目标 28 nm、1 GHz，不让解压进入原执行发射关键路径。
  • 总面积/功耗必须计算 FIFO、路由、状态寄存器和 SRAM 外围。
  • 单人四个月内能够完成软件、RTL、综合和论文实验。

4.4 关键架构修正：片上完整驻留时为什么可以不使用 FIFO

以上逻辑流可以直接落入六个独立片上 SRAM，而不必先改造成单一 tagged packet 流： 

Mask SRAM:    5 × T bit
LOAD SRAM:   42 × Nload bit
STORE SRAM:  42 × Nstore bit
VECTOR SRAM: 34 × Nvector bit
SCALAR SRAM: 31 × Nscalar bit
SFU SRAM:    31 × Nsfu bit

每个执行槽维护一个地址计数器。周期 t 的 mask 位为 1 时，对应 Bank 读取当前地址并令计数器加一； mask 位为 0 时地址保持、输出 NOP。五个槽 Bank 彼此独立，因此即使局部周期五槽同时有效，也能并行各读一条。 同步 SRAM 的 1–2 拍延迟只产生固定启动流水延迟，不要求事件 FIFO，也不改变程序内部逐周期关系。

addr_s(t+1) = addr_s(t) + mask[t][s] mask[t][s] = 0 ⇒ output[t][s] = NOP mask[t][s] = 1 ⇒ output[t][s] = SlotSRAM_s[addr_s(t)]
逻辑位数不能直接决定物理优劣 Candidate A 的逻辑容量就是 5-bit mask + 不补齐 RAW 槽流，约为原始存储的 21.74%。 它的潜在代价是六个小 SRAM 宏各自的最小深宽取整、外围电路、地址器、布局布线和并行读能耗。 Candidate B 引入 FIFO 的唯一合理动机，是以单/少 Bank 时间复用减少这些物理代价；若真实宏结果不支持这一点，FIFO 就是多余开销。

5. Candidate A/B 架构及评估优先级

5.1 Candidate A：直接分槽、按 mask 读取

5-bit Mask SRAM ───────────────► 周期 t 的有效槽控制
LOAD/STORE/VECTOR/SCALAR/SFU ──► 五个独立原生宽度 SRAM
五个槽地址计数器 ──────────────► mask=1 时各自递增
并行槽输出 + NOP 填充 ─────────► 原始 184-bit VLIW
  • 无深 FIFO、无 3-bit stream ID、无 packet demux、无运行时调度。
  • 同周期多槽由不同 Bank 并行提供，直接满足局部五槽峰值。
  • 这是首要 RTL/物理 Baseline，也是默认工程实现。
  • 该机制与 Li 的纵向槽流、ifnull/mask 和多 Bank 重组接近，不能单独作为论文创新。

5.2 Candidate B：单/少 Bank fixed packet + 有限 FIFO

仅作为有条件的物理优化候选 Candidate B 不是功能正确性所必需。只有当多个窄小 SRAM 宏的取整和外围开销显著大于 单/少宽 Bank 加有限缓冲与路由的成本时，继续研究 Bank Folding 才有意义。

5.3 Candidate B 的六条逻辑流

编码器先从原 184-bit Trace 中建立六条按原周期/事件顺序排列的逻辑流：

Stream 0: Calendar，正常周期每项 5-bit mask
Stream 1: LOAD，有效事件每项 42 bit
Stream 2: STORE，有效事件每项 42 bit
Stream 3: VECTOR，有效事件每项 34 bit
Stream 4: SCALAR，有效事件每项 31 bit
Stream 5: SFU，有效事件每项 31 bit
  • CONTROL 不再形成独立每周期流；函数头保存总周期数，末周期自动产生 EOP。
  • 每个槽内只保存有效 RAW 指令，不使用普通值字典、字段字典或逐 workload delta 表。
  • 同一槽流中的事件顺序严格等于原 Trace 中该槽的时间顺序。

5.4 固定包原则

Packet = [stream_id | data]

stream_id = 3 bit
一个 packet 只属于一条逻辑流
一条槽指令不得跨 packet
包内不足部分补 0
包间可以按编译器生成的供给顺序交织

3-bit ID 的意义是把整包路由到对应 Reservoir，而不是为每条指令保存 slot tag。

5.6 256-bit包为何容量更接近理想值

关键是 6×42=252，253-bit 数据区几乎完美容纳六条 LOAD 或 STORE； 128-bit 包则每两条 LOAD/STORE 固定浪费 41 bit。12 条 Trace 中， 256-bit 包相对 128-bit 包总容量减少 16.64%，从 27.33% 降至 22.79%，只比理想 bit-tight 的 21.74% 高 1.05 个百分点。

5.7 函数头建议

当前容量估算统一预留 256-bit 函数头。建议字段包括：

  • 版本、包宽模式（128/256）、总执行周期 T；
  • 五个槽事件数和 Calendar 项数；
  • 总包数与执行前预取包数；
  • 可选模式使能位、校验/保留位。

最终位分配必须在 wire-format 定稿时固定，不能继续用抽象“descriptor预算”替代。

6. 下一步软件方案

6.1 两条实现分支

  1. 先实现 Candidate A：生成 Mask SRAM 和五个槽 SRAM 的独立初始化文件，模拟五个计数器和固定 SRAM 延迟，逐周期对拍。
  2. 再实现 Candidate B：仅在相同逻辑流上增加固定包、供给期限、包交织和有限 FIFO，以便与 A 公平比较。

  1. 逐周期解析原 Trace，生成 5-bit 功能 mask；最后 EOP 不保存 mask 第六位。
  2. 对每个有效槽按固定容量分组，保证槽指令不跨包。
  3. 为每个包计算其数据覆盖的事件范围，以及最早必须准备好的执行周期。
  4. 在同槽包顺序不可改变的约束下，生成全局包交织顺序。
  5. 模拟 SRAM 读延迟、包解复用、Reservoir/FIFO 写入和逐周期消费。
  6. 输出最小预取量、各 FIFO 峰值、下溢周期和总物理位数。

6.3 “供给截止周期”的严格含义

为避免与执行时序混淆，建议论文使用“供给就绪期限”而不是简单“截止周期”。 对原 Trace 中周期 t、槽 s 的事件 e：

Ready(e) ≤ t Issue(e) = t

SRAM 读取和解包可以提前，事件可提前进入 FIFO；但只能在原来的第 t 周期从 FIFO pop 并输出。 包交织改变的是“何时把数据准备好”，不改变“何时执行”。

6.4 包交织问题

软件应把包交织建模为带顺序约束和缓冲上限的离线调度问题：

  • 每周期最多读取一个 128-bit 或 256-bit 包；
  • 同一逻辑流内部包顺序固定；
  • 每个包的数据必须在其最早消费事件前进入对应 Reservoir/FIFO；
  • 过早读取也受 FIFO 容量限制，不能继续依赖“无限 FIFO”；
  • 目标是最小化预取包数、最大 FIFO 位数和 SRAM 读使能次数。
下一步必须从无限 FIFO 转向有限 FIFO 目前 128/256-bit 包的 27.33%/22.79% 仅是容量结果。 只有生成真实可行的包交织序列，并证明有限 FIFO 下全部 Trace 不下溢，这个格式才能进入 RTL。

6.5 解码参考模型

建立与最终 RTL 同构的 cycle-accurate Python 模型，每周期模拟：

  1. SRAM 请求、1–2 拍返回和 read-enable；
  2. stream ID 解复用；
  3. 整包/槽指令写入对应 FIFO；
  4. 当前 5-bit mask 消费；
  5. 五槽 pop、NOP 填充和 EOP 生成；
  6. 与原 184-bit word 逐位比较。

7.3 128-bit 与 256-bit硬件权衡

设计程序存储优势主要代价必须验证
1×128-bit口，128-bit包 27.33% 输入寄存器和路由较窄；单包解码简单。 LOAD/STORE与VECTOR包内空洞大；包数 7,997。 能否在有限 FIFO 下覆盖峰值；总读能耗。
1×256-bit口，256-bit包 22.79% LOAD/STORE几乎满包；包数仅 3,331；带宽裕量高。 宽输入寄存器、253-bit路由、宽包缓冲和潜在多写入。 FIFO/解包器是否抵消 16.64% 的程序存储下降。
256-bit口，每拍两个128-bit包 27.33% 包缓冲仍为128 bit；可同时补充两条逻辑流。 两套 ID 解码和路由；128包空洞仍存在。 面积/能耗是否优于单256包。
Li式多窄Bank 文献基线 同周期多槽直接并行读取，FIFO需求低。 多宏、地址器、端口和容量碎片。 同工艺宏级物理面积与读能耗。

7.4 FIFO不能按“无限”或“与端口同宽”简单处理

若六条逻辑流各保留一个完整包：

128-bit包：6 × 128 = 768 bit 256-bit包：6 × 256 = 1,536 bit 固定增加：768 bit

两包深时分别为 1,536 bit 与 3,072 bit。若包 FIFO 用触发器实现，每 bit 面积远高于 SRAM bit。

另一种方法是立即拆成原生槽指令 FIFO，此时 FIFO 字宽仍是 42/42/34/31/31/5，不因 SRAM 口翻倍；但一个 256-bit 包可能含：

  • 6 条 LOAD/STORE，或 7 条 VECTOR，或 8 条 SCALAR/SFU，或 50 条 mask；
  • 若一拍全部写入，需要高写端口 FIFO；
  • 若分多拍写入，需要 256-bit 保留寄存器，并可能暂停后续 SRAM 读取。
因此当前不直接选择 256 bit 256-bit 包在程序 SRAM 容量上占优，但端口宽度必须由 程序 SRAM + Packet Buffer + Slot FIFO + Demux + Write Ports 的总物理面积和能耗决定。128/256 两个版本应共享 RTL 参数化设计后综合比较。

7.5 时序隔离

  • SRAM 返回、ID 解码和 FIFO 写入可流水化，不进入执行侧组合关键路径。
  • 执行周期只做 5-bit mask 读取、五个 FIFO valid/pop 和 NOP 选择。
  • 若 FIFO 数据已经按原槽宽保存，最终 184-bit 拼接只需布线和固定位置复用。
  • 目标是保持原 1 GHz，不以降低频率换取压缩。

8. 逐周期精确恢复原则与验证

8.1 恢复不等于提前执行

包可以提前读取、解复用和进入 FIFO；但 Calendar 在执行周期 t 才触发相应槽 pop：

对所有周期 t、槽 s： mask[t][s] = 0 ⇒ output[t][s] = NOP mask[t][s] = 1 ⇒ output[t][s] = next(FIFO_s) 必须满足： output[t][s] = original[t][s]

8.2 为什么顺序槽流可以恢复同周期并行

  1. 每条槽流只删除该槽自己的 NOP，有效事件保持时间顺序。
  2. 到周期 t 前，Calendar 中槽 s 的 1 的数量等于该槽已经消费的事件数。
  3. 因此周期 t 的下一事件就是原 Trace 在该周期的槽事件。
  4. 不同槽是否同时 pop 由同一个 5-bit mask 决定，同周期关系不会变化。

8.3 必须完成的验证层次

  • 软件 wire-format：编码文件→解码文件逐周期逐 bit 等于原 Trace。
  • cycle model：加入有限 FIFO、SRAM 读延迟和包写入吞吐，验证无下溢。
  • RTL 对拍：每周期比较五槽、reserved、EOP 和完整 184-bit word。
  • 系统行为：函数输出数值、执行周期和原论文结果一致。

9. 本文核心创新点：候选表述与成立条件

有条件的候选名称，并非已经成立的创新 面向周期精确稀疏 VLIW 的供给期限排序固定包编码与物理 Bank 时间折叠
Deadline-Ordered Packetization and Temporal Bank Folding for Cycle-Exact Compressed-Resident VLIW

9.1 先回答“为什么不直接分槽存储”

可以，而且应当先这样做。压缩程序完整驻留片上时，Candidate A 直接按槽存入独立 SRAM， 再由 mask 控制每个 Bank 的读使能和地址递增，即可无 FIFO 地逐周期恢复。 Candidate B 中 FIFO 和解码器不是正确性必需品，只是为了把多个物理 Bank 折叠为单/少 Bank 而支付的代价。

如果 Candidate A 优于 Candidate B 当前 Bank Folding 候选创新即告失败。Candidate A 虽然更合理，但与 Li 2020 的纵向槽流、 mask/ifnull、分 Bank 并行重组高度接近，只能作为正确而强的 Baseline，不能成为本文的新贡献。 此时应重新寻找创新点，而不是继续增加 FIFO、字典或解码复杂度。
如果 Candidate B 优于 Candidate A 创新才可能落在“编译期受限包交织 + 有限缓冲 + 多槽逻辑流向单/少物理 Bank 的时间折叠”这一完整协同设计， 且必须由总 SRAM 宏、FIFO、路由、能耗和 1 GHz 时序结果证明显著净收益。

9.2 Candidate B 的核心机制

  1. 固定包编码：Calendar 与原生宽度槽流形成统一 tagged packet，不依赖 workload 字典。
  2. 供给期限建模：每个包对应一组未来槽事件，具有不得晚于的准备周期。
  3. 编译期包交织：在同流顺序和有限 FIFO 约束下，生成单一顺序包流；物理顺序就是运行时预取计划。
  4. Bank 时间折叠：把 Li 在执行周期空间并行访问的多条物理槽 Bank，转换为执行前在单/少 Bank 上时间复用读取。
  5. 周期精确重建：运行时无动态调度，只用固定 ID 路由、FIFO 和 Calendar 在原周期输出。

9.3 与 Li 2020 的差异

维度Li 2020本文候选

9.4 仅在 B 胜出后可以写入 Contributions 的内容

  1. 提出带同流顺序、有限 FIFO、SRAM 延迟和单端口约束的固定包交织/供给综合问题及算法。
  2. 提出把多逻辑槽流折叠到单一顺序物理包流的轻量前端，并给出周期精确与无下溢保证。
  3. 在真实 28 nm SRAM 宏和 RTL 下证明相对 Li 多 Bank 的净面积/能耗 Pareto 优势。
  4. 以 R/tile 扫描证明压缩后可选择性能更优的分块点，而不再被 IMEM 容量迫使选择高 R。

9.5 如果 A 胜出，下一轮可验证的真正创新方向

  1. 跨 workload 统一的语义字段编码： 只利用 ISA 明确定义的隐含字段、未使用操作数、固定控制位或同寄存器关系； 使用一套固定格式和 RAW escape，不使用逐 Trace 训练字典。
  2. 物理 SRAM 感知的有界块压缩： 以固定周期块保存 mask 序列和紧凑 payload，只允许严格上限的双块缓冲； 目标是减少小宏取整与外围开销，而不是依赖无限槽 FIFO。
  3. 异构 Bank 的物理组织优化： 基于槽宽、槽深和共激活关系提出新的 Bank 组合或低能耗读取结构。 单纯采用不同深度的五个 SRAM 过于直接，必须有可量化的新组织机制才可能构成创新。

这些方向仍只是待验证候选。论文最终方案必须同时满足：统一格式、全部 workload 周期精确恢复、 总存储明显优于纵向压缩、解码低开销，并且不依赖逐 workload 字典。

9.6 不能夸大的边界

  • 固定包、mask、FIFO、预取、分 Bank 各自都不是新颖性。
  • 若包交织只是普通 EDF，且已有 VLIW stream buffer 已覆盖同一问题，算法新颖性可能不足，需进一步查新。
  • 若物理综合后只剩“mask+payload加FIFO”，应停止以该方向投稿，而不是通过增加字典复杂度包装。

11. 可能有帮助、但下一步再考虑加入的点

11.1 固定 1–2 bit 地址 delta + RAW escape

只考虑以下字段：

  • LOAD/STORE：28-bit mem_addr、8-bit gpr_addr；
  • SFU：8-bit dst/src gpr 地址；
  • VECTOR/SCALAR 寄存器保持 RAW。

所有 workload 必须使用同一组硬连线 delta，不允许训练不同字典。未命中时保存完整地址：

若 escape 占用 b-bit 码字： 可编码的常用 delta 数量最多为 2^b − 1 2-bit：3 个 delta + 1 个 escape 1-bit：1 个 delta + 1 个 escape

硬件需要 28-bit/8-bit 地址模加法器、历史状态寄存器和 escape MUX。必须证明容量收益大于计算资源开销。

11.2 规则 workload 的周期 fast path

GELU、Softplus、LogSoftmax、LogSumExp 的部分大 X Trace 有较高周期核覆盖，可作为多模式格式中的可选段；Softmax/LayerNorm 直接回落固定包 RAW。

11.3 mask 驱动的门控

利用已经存在的 5-bit mask 阻止 NOP 槽驱动 crossbar、槽控制端口和功能单元输入，作为动态功耗配套贡献。必须用 SAIF/VCD 实测。

11.4 等价编码降低翻转

在周期行为一致但不要求输出每个无关位逐 bit 相同的后期阶段，可规范化无效控制位或选择低翻转等价编码。必须先有 bit-exact 基础版本和形式化等价边界。

11.5 R/tile 协同评估

不修改给定 R 下的调度；只把压缩后的物理 IMEM 容量加入设计空间，重画 R=2/4/8/16/32 的存储—性能曲线。

13. 评估方法与 Go/No-Go 条件

13.1 必须报告的四层指标

编码层

原始位数、包数、包内利用率、头/标签/尾部填充、最终文件字节数。

供给层

每周期读包、预取周期、各 Reservoir/FIFO 峰值、下溢、解包写入数。

物理层

SRAM 宏深宽/端口/数量、FIFO介质、面积、1 GHz时序、每包读能耗。

系统层

总核心面积/功耗、函数常驻数、R/tile—周期—IMEM曲线、周期行为一致性。

13.2 完整 Baseline 矩阵

  • 原始 184-bit、同深度单宽 SRAM。
  • Li 外部补齐、Li 片上逻辑、Candidate A 实际六 Bank 宏；A 必须包含 mask SRAM、五槽 SRAM、计数器和固定流水寄存器。
  • 5-bit mask + bit-tight RAW 理想下界。
  • Stop-bit/可变 bundle。
  • 128-bit固定包、256-bit固定包、双128包/256口。
  • 允许跨包的连续位流上界。
  • 后期消融：delta、周期 fast path、mask门控。

13.3 四周生死门

A基线直接分槽在真实 1–2 拍 SRAM 下逐周期逐 bit roundtrip，且完成实际宏映射与粗综合。
B格式128/256 wire-format 在全部 Trace 上roundtrip，有限 FIFO 和包写入吞吐下无下溢。
公平成本A与B均计算实际SRAM宏、地址/控制、寄存器、FIFO、demux及读能耗，不混用逻辑位数和物理面积。
物理仅当B总面积/能耗显著优于A且恢复逻辑达到1 GHz，Bank Folding才通过。
查新确认 VLIW stream buffer、静态 prefetch 和多流 packet scheduling 未完整覆盖本文组合。
No-Go若A优于B，或B仅退化为“mask+payload+FIFO”，立即否决Bank Folding；A保留为Baseline，重新验证统一语义字段编码、有限块格式或其他选题。
