1. 实验设置（五方案共用）

1.1 工作负载与调度

  • 测例：softmax_x64 (Y=512)、layernorm_x64 (Y=768)、gelu_x64 (Y=3072)，X=64，NUM_VE=256, VGPR_CAP=256, SGPR_CAP=256, MASK_FIFO=8, RQo=32/16/16，优先级策略 index。
  • 三个调度族（每族内各方案共享同一 schedule，周期严格可比）：max-5（E0/E1）、max-4（E2）、max-2（E3/E4）。
  • 程序池：三程序镜像一次装入指令 SRAM，按描述符 {基址, 长度} 逐程序切换运行（gelu→softmax→layernorm，非连续顺序以验证随机切换）；逐程序复位前端，宏内容保持。
  • 统一低翻转输出级：五方案相同——槽有效时装载全部字段，无效槽仅 OP 字段清 0（NOP）、其余字段保持上一有效值；字段级寄存器输出。
  • 无背压：II=1，每拍一条指令，自由运行。

1.2 验证与综合方法

  • 功能验证：真实 TSMC 28nm 宏模型 + iverilog/ModelSim，1 GHz；testbench 把五槽字段端口无损重组为 34-bit 容器逐拍记录，Python 校验脚本与 golden（由原始 174-bit schedule 经保持语义确定性变换生成）逐周期逐 bit 比对；并校验各宏实际读次数 == 编码统计的精确总数（门控正确性）。
  • 综合：TSMC 28nm，目标 1 GHz。

2. 各实验的实现方案

E0 · 无压缩（基线锚点）

存储：1× 8192×171 SRAM。格式：整字 = 5×34b 功能槽 + 1b EOP。取指/解码：PC → 整字直读 → 按位切分进字段寄存器；2 拍流水，无译码逻辑。EOP 为字内 bit0。

E1 · Candidate A（纵向压缩 baseline）

存储：config 1× 8192×5（5-bit 槽有效 mask，T−1 项）+ payload 5× 2048×34（每槽专属 Bank）。取指/解码：3 拍流水（config 提前一级）；每槽独立读指针，mask 位为 1 时递增；cen_s = mask[s] 精确门控（只读有效 Bank）。EOP 隐式：mask=11111 是合法数据（允许 5 槽同拍），EOP 由「已接受指令计数器 == 程序长度−1」产生。

E2 · 自适应 4slot（核心方案）

存储：config 1× 8192×5（5-bit mask + 带内 EOP=11111）+ payload 4× 2048×34（4 条共享 Lane）。编码：有效槽按槽号升序，第 r 个有效事件写入 lane=(phase+r) mod 4，拍末 phase+=popcount(mask)。取指/解码：3 拍流水；拍 B 用共享前缀 popcount 链算 en(i)=((i−phase) mod 4)<popcount 做占用自适应门控（未承载事件的 Lane 不读），phase 以 2-bit 流水寄存器送拍 C；拍 C 由寄存的 mask/phase 组合出选择信号，4→1 散布到五槽。

E3 · 2slot2lane

存储：config 1× 8192×5（5-bit 对码，31 普通态 + EOP=31）+ payload 2× 4096×34（2 条共享 Lane）。取指/解码：3 拍流水；拍 B 用脚本生成的对码译码表 cfg_pair_codebook 把码值译为 {valid0, slot0, valid1, slot1} 并寄存 8-bit 控制送拍 C（拍 C 纯 mux）；单事件进较浅 Lane（编码侧均衡）。

E4 · 2slot4lane

存储：config 1× 8192×6（6-bit {group, local5}，EOP=63）+ payload 4× 2048×34（4 条 Lane 分两组 {0,1}/{2,3}）。取指/解码：3 拍流水；local 字段复用 E3 的对码译码表，group 选 Lane 对，物理 Lane = 2×group + 局部序号；拍 C 每槽 4:1 mux。

核心结论：4slot（E2）在四项上取得最均衡的优势——相对无压缩面积 −72%/功耗 −86%，相对纵向压缩 baseline 面积 −16.5%/功耗 −9.8%，且周期零损失（不同于 2slot 方案在 layernorm/softmax 上的周期代价）。这验证了「跨异构槽共享容量 + 占用自适应门控」的设计价值。

5. 结论

  1. 五种方案 RTL 全部实现并满足 28nm / 1 GHz，无建立时间违例。
  2. 池模式功能验证全部逐周期逐 bit 精确；各方案读次数与编码统计精确相等，门控正确性得证。
  3. 4slot（E2）是面积—功耗—周期三维上最均衡的主方案；2slot 方案（E3/E4）面积相近但有周期损失且通用性较差；纵向压缩 baseline（E1）面积/功耗均高于 E2。

说明：面积/功耗为五个完整顶层模块（expN_*_top）的综合报告值，含 SRAM 宏与全部取指/解码/输出级逻辑；相对值由绝对值计算。作为参照，E0 顶层 289,077 µm² 中 SRAM 宏（8192×171）占 288,368 µm²，逻辑仅约 709 µm²——各方案的解码/散布逻辑开销相对 SRAM 都很小。动态读能耗另按「实际读次数 × 宏读能量」从仿真统计（见第 3 节读次数），与综合功耗口径不同、不混用。
