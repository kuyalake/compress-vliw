4-slot 条带化压缩：OpenEdgeCGRA、CISP 与 CCF 的进一步查证和实验

日期：2026-09-10 ｜ CACTI 7.0 / HP 32 nm / 1 GHz 读活动口径 ｜ 所有新方案均做逐周期、逐槽软件往返恢复

先说结论：这次查证改变了旧报告的两项判断。第一，OpenEdgeCGRA 的确没有实现指令压缩；保留 N=4 后不会改变原调度周期，但 E2 是否节省 SRAM，完全取决于程序池是否跨越 2 的幂深度边界。7 个应用 kernel 池中它不省容量；12 个公开映射的压力池中，只有给每个程序增加 2-bit 条带初始相位，E2 才能把总 SRAM 从 65,536 bit 降到 34,816 bit。第二，CCF 旧实验只看了 11-cycle 的 .sch，漏掉最终二进制中的配置和预装载指令；完整 39-cycle *_ins.bin 有一拍 16 槽全开，纯 4-lane E2 不能保持周期不变。仓库另外三组映射也普遍有 10–12 槽并发。因此 CCF 不应再被写成 E2 的普遍正向平台。

1. 先把比较方法用人话讲清楚

报告中的名字到底怎样存恢复一拍完整指令时做什么本次是否完整复现
不压缩逻辑上有 M 个槽，就放 M 个等宽、等深 SRAM bank；每个地址保存一整拍。所有 bank 用相同地址并行读，直接拼成完整控制字。是。
纵向压缩 / 强 Candidate A删除各槽中的 NOP；每个逻辑槽仍有自己的专属 bank。为了保持程序可替换性，M 个 bank 统一按最长槽流定深。每拍先读 M-bit 有效掩码；有效槽的专属指针加一，无效槽输出 NOP。这里还给 baseline 加了 bank clock-enable，已经比论文原图中“无效时读地址 0”更有利。是；逐槽往返通过。
E2：N-lane 条带化仍只保存有效槽，但逻辑槽不再绑定物理 bank。每拍有效槽按 slot 序号排序，第 r 个事件放入 (phase+r) mod N lane，phase 再增加本拍有效数。mask 给出目标 slot；phase 和 rank 算出源 lane，再散布回 M 个输出。若任一拍有效槽数大于 N，纯 E2 就无法在一拍恢复。是；phase=0 的当前 RTL 语义与增加初始 phase 的扩展语义分别测试。
固定分区 temporal-hold每个槽只在“本拍值与上一拍不同”时存新值；没变化就不读 bank，让输出寄存器保持上一值。读 M-bit change mask；有变化的槽更新，无变化的槽保持。是，但只是 Lee 等 2018 方法的固定 M 分区、无重新调度子集；其专有编译器的 ASAP-ALAN 与实体分组没有复现。
静态整-bundle 字典相同的完整宽指令只存一次；每拍只存一个字典索引。字典在物理上拆成 M 个并读的 W-bit bank。先读索引，再读字典；流水后可做到每拍一个，但通常比 E2 多一级查表依赖。是；这是经典字典基线，不冒充 2024 可编程多字典论文的完整算法。
不同值多播（辅助实验）同一拍若多个 slot 的完整 W-bit 字完全相同，只存一次；每条 lane 另带 M-bit 目的位图。一个 lane 的值可同时发给多个 slot。它来自 CGRA broadcast/multicast 这一已有思路，但与 E2 结合后的具体编码是本报告的辅助模型。软件恢复是；不是原始 E2，也不是 RoMultiC 的逐项 RTL 复刻。

表头说明：“怎样存”描述 SRAM 内的内容；“恢复”描述每周期取指端动作；“完整复现”用于防止把论文中无法获得的编译器或 RTL 误写成已经复现。

2. 实验口径：为什么同时给“信息量”和“SRAM 总 bit”

一个 trace 理论上可能只需 77 行，但真实 SRAM 通常选 64、128、256、512 等深度。论文的创新恰恰与这种取整有关，因此每个方案同时计算两类数：

未取整信息量 = 真正保存的 payload bit + 每拍 metadata bit
SRAM 总 bit = Σ（每个独立 SRAM 的宽度 × 向上取 2 的幂后的深度 × 实例数）
  • CACTI：CACTI 7.0、HP 32 nm、1R/W port、按 cycle time 优化。全部返回的最大 cycle time 为 0.130 ns 以下，因此在这个模型中都满足 1 GHz。
  • 小宏限制：CACTI 不接受小于 64 Byte 的阵列；遇到这种情况，只把 CACTI 的物理建模深度翻倍到合法值。表中的“SRAM 总 bit”仍是架构请求值，面积/功耗采用 CACTI 实际建模值。机器可读 JSON 同时保存两者。
  • 动态功耗：以 1 GHz、顺序读完池内所有指令一次的平均每拍读次数估算。原始和字典每拍读全部 payload bank；Candidate A/E2/hold 假设无事件 bank 可关读使能，这是给压缩方案的较理想口径。
  • 未计入：解码组合逻辑、指针/phase 寄存器、跨 lane 到 slot 的长连线、程序 descriptor、OpenEdge 的 PE 私有程序存储。故 CACTI 数字只能比较 SRAM，不是最终芯片面积或总功耗。
特别注意 OpenEdge：压缩的是 2 KiB context SRAM，即 CPU 预先写入、kernel 启动时再拷贝到 PE 私有程序存储的那一级。它不是每个计算周期都读的 PE 私有程序存储。因此这里的“一拍恢复”首先保证 kernel 装载仍可每拍写入一行 PE 指令；计算阶段的周期序列保持不变。

3. OpenEdgeCGRA：原工作和后续工作是否已经压缩

3.1 可确认的硬件事实

  • 原论文的默认实例是 4×4 RC；每个 RC 指令 32 bit、私有程序存储 32 words；共享 context memory 为 2 KiB。
  • 公开 RTL 的 context_memory.sv 明确实例化 4 个 row SRAM，每个 32-bit、相同深度；kernel 装载时四 bank 同址并行读。
  • 2 KiB 与 RTL 对应为 4 × 128 × 32 = 16,384 bit。多个 kernel 和其多个 column 在这四个 row bank 的地址空间内连续占用；所以本次把每个 kernel 的所有 column 先连起来，再把多个 kernel 合为程序池。

3.2 是否已经有指令压缩

结论：没有发现。原论文只描述普通 context SRAM、kernel descriptor 与向 RC 私有程序存储的拷贝；公开仓库在固定 commit 4a179fcf6faee18765f66baa0a30af91e3840728 中检索 compress/compression，也没有压缩器、压缩格式或解压 RTL。kernel ID 避免重复重装同一 kernel 是“缓存/复用”，不是减少已存指令 bit 的压缩。

我还检索了明确使用 OpenEdgeCGRA 的后续公开工作，包括 2024 年卷积映射、2025 年功耗/时序快速评估框架、HEEPsilon 与 Compigra。找到的是映射、循环调度、性能和功耗分析，没有找到“已经把 OpenEdge context/program instruction 做压缩”的公开实现或实验。因此，当前最严谨的表述是：截至 2026-09-10，未找到针对 OpenEdgeCGRA 本身的已公开指令压缩工作；这不是对所有未公开项目的绝对不存在证明。

4. OpenEdgeCGRA：保留 N=4 后的真实结果

4.1 为什么 N=4 严格不增加调度周期

这里每拍的逻辑槽本来就是四个 row 指令，即 M=4；E2 也保留 N=4 条 payload lane。因此任意原始周期最多只有四个有效槽，必有 k[t]≤4。实验对 12 个公开映射的 348 个地址逐拍检查，最大值确为 4，软件编码后又逐拍、逐 row 恢复原 token。这个结论不依赖平均利用率，也没有重新调度，所以装载地址数和计算调度均不变。

4.2 主口径：7 个应用 kernel 同时常驻

包含 dbl_max、dbl_min、fft_bitrev、fft_cplx、fft_cplx_forever、max_peak、min_max_circular；合计 118 个 context 地址、293 个有效 row 字，平均 2.483/4，24 拍四槽全开。118 行能直接放进原平台的 128 深 bank。

4.4 新发现：2-bit 初始 phase 为什么重要

当前 exp2_adaptive_4slot_top.v 在每次 start 时把 phase_q 清零。小程序很多时，每个程序的第一个有效事件总偏向 lane 0，多个程序累加后可能把 lane 0 推过 256，而其它 lane 还有空位。改进方式不是按 workload 定制 SRAM，而是在通用程序 descriptor 中加一个 2-bit initial_phase；编译器把每个程序的起点在 0/1/2/3 中旋转，硬件启动时把 phase 初始化为该值。四条物理 lane 的深度仍完全相同，程序仍可替换。

这是真正值得从 OpenEdge 实验中提炼的点：“条带化”要在程序池边界也保持全局均衡，不能只保证单程序内部差不超过 1。2-bit phase seed 使 12 个程序的 lane 从 262/256/252/250 变成 255/255/255/255，且软件证明达到容量下界。不过它对 7 应用池仍无面积收益，所以只能作为 E2 的健壮性修正，不能单独构成论文创新。

6. CCF 4×4 CGRA：原工作和其它工作是否已经压缩

6.1 原 CCF 做了什么

CCF 是 LLVM mapper + instruction generator + gem5 simulator。公开仓库 commit 866785044bd915e4c1d5dce3d601fbe3886bd4e8 中，当前源码定义 4×4 PE 和 64-bit PE 指令；generator 把 prolog、kernel、epilog 逐 PE 写成 unsigned long 数组和 *_ins.bin。代码中没有压缩格式、压缩器或解压器，二进制中保留显式 NOOP 值 0x0000000177e00000。

结论：CCF 本身没有做指令压缩。它把 modulo kernel 只存一次并循环执行，这是 loop-buffer/控制流复用，不是压缩；prolog/kernel/epilog 分段也不是删除冗余编码。

6.2 是否已有论文“对 CCF 做过压缩”

检索 CCF 全名、ASU MPSLab、CCF + instruction/context compression，没有发现把 Candidate A、Lee、字典或多播压缩实际接入 CCF 仓库并发布 trace/RTL 的工作。确实存在很多其它 CGRA的上下文压缩：例如 Lee 等在 Samsung SRP 上做时间保持与静态分区，Sargolzaei 等在自建 CGRA/CGRAmulator 上做 don't-care unification，Park/Choi 在 FloRA 上做 half/full 模式；但它们不能被写成“CCF 已经做过”。

7. CCF：设置最大 4 槽到底会不会影响周期

7.1 旧的 11-cycle 数字为什么不完整

旧脚本只读取 simple_loop_1/CGRAExec/L1/{prolog,kernel,epilog}.sch，得到 6+3+2=11 个 mapper 周期、21 个映射节点，峰值 3。对这三份 schedule 文件本身，N=4 当然可以不改周期。

但是 instruction generator 还会加入配置边界、live-in 预装载和 live-out 等指令。真正写给模拟器的三个 *_ins.bin 是 33+3+3=39 拍、67 个非 NOP；第一拍 16 个 PE 全部有效，其中包含两种不同的 64-bit 配置字。纯 E2 一条 lane 一拍只能供给一个 slot，四 lane 无法在一拍恢复 16 个 slot。

8.3 多播结果能否救 CCF 成为 E2 平台

它能救 simple_loop_1 的完整 binary，是因为首拍虽然 16 槽有效，却只有两个不同值：两个值各配一个 16-bit 目的位图即可发给全部 PE。整条 39-cycle trace 每拍最多只有三种不同有效字，所以四条 value lane 足够。

但这不能写成“E2 在 CCF 上零损失”。它把接纳条件从“每拍有效槽数≤4”改成“每拍不同有效字数≤4”，metadata 从每拍一个 16-bit slot mask 增到四个 16-bit destination bitmap（64 bit），散布器还要支持一对多广播。它属于“E2 条带存储 + 已有 CGRA multicast 原理”的新混合候选。更重要的是，另外三组 CCF schedule 中只有 node ID、没有最终机器字，无法证明那些 10–12 槽同拍也只有≤4种值。故目前只能作为值得扩展 trace 的观察，不能把 CCF 恢复为论文正向平台。

10. 对第四篇论文方向的重新判断

10.1 仍然成立的核心命题

可以保留一个一般性问题，但必须把必要条件写完整：

给定 M 个等宽逻辑槽、N 个等宽物理 payload lane：
若完整可执行 trace 的每拍有效槽数 k[t]≤N，E2 可不改调度地逐拍恢复；
是否节省 SRAM，还要求条带化后的最大 lane 长度跨过比 Candidate A 更低的宏深度档位。

这比“平均每拍只用 2–3 槽，所以共享 bank 一定更省”严格得多。OpenEdge 7 应用池说明满足峰值条件也未必省宏；CCF 说明 mapper 片段满足峰值条件也不代表最终 executable 满足。

10.2 OpenEdge 和 CCF 在论文中的合适角色

10.3 两个可能继续挖掘、但尚不能升级为主创新的点

  1. 程序描述符初始 phase：只增加 ceil(log2 N) bit/程序，使“单程序内均衡”扩展为“常驻程序池全局均衡”。下一步应在 E2 RTL 加 phase_init，综合确认 2-bit mux/寄存器开销近乎可忽略，并在三个神经网络程序池上重算是否改变任何 lane 深度档位。
  2. 相同 payload 多播：对 CCF 的 16-PE 配置拍很有效，但需要 N×M 目的位图和一对多网络。只有取得 15–30 个完整 *_ins.bin 后，比较“有效槽数”和“不同值数”的尾部分布，再决定它是通用扩展还是被一拍初始化指令偶然触发。

10.4 下一步最小可执行计划

  1. 先把本次 CCF 纠错同步进旧的跨平台结论：所有平台必须同时报告 mapper schedule 和最终 executable trace；不存在最终 trace 的平台只能标“待确认”。
  2. 给 E2 descriptor/RTL 增加 2-bit phase_init，对现有三个模型池、OpenEdge 7/12 池做同一套 bit-exact + 1 GHz 综合。若三个主模型池不跨新档位，把它作为健壮性实现细节，不包装成创新点。
  3. 若继续 CCF：完整安装工具链，至少生成 15 个 MiBench/Rodinia/Parboil loop 的最终 *_ins.bin；同时统计 max active slots 与 max distinct active words。在此之前不做 4→16 scatter RTL。
  4. 正式加入多播 baseline 前，请补充上传 RoMultiC 与 Park/Choi An approach to code compression for CGRA 全文；否则正文只能称“受已有 broadcast/multicast 家族启发的辅助模型”。
  5. CISP 只保留论文汇总基线，同时发邮件索取 trace；拿不到时明确写 artifact unavailable，不从 Figure 2 的 NOP 百分比合成假 trace。
