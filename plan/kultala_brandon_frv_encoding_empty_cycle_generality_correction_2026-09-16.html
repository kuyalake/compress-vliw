Kultala与Brandon方案在FRV上的编码、空周期与通用性复核

日期：2026-09-16 ｜ 对象：Kultala等JSP 2016、Brandon等ReConFig 2015、Li等IEEE Access 2020 ｜ 目的：纠正上一版FRV软件模型中过于乐观的变长编码假设

首先撤回上一版结论：此前报告中Kultala/Brandon的逻辑压缩率、CACTI面积和功耗不能作为正式论文数字。模型把全NOP周期分别压成2 bit和4 bit，却没有证明这种短码在真实FRV码流中如何与普通指令无歧义地区分；同时也没有证明174-bit取指加有限buffer可以在最坏连续长指令下每拍恢复一条VLIW。修正空周期以后，BERT和LLaMA的变长主SRAM深度翻倍，二者不再表现为接近或优于E2。

1. Kultala 2016：原论文方法

原文：Improving Code Density with Variable Length Encoding Aware Instruction Scheduling。该方法不是“任意mask都能变短”，而是为TTA/VLIW预先定义少量固定指令模板。

论文实验机器完整指令四种模板模板含义
threeway96 bit32、48、96、96 bit短模板只允许特定bus携带move，其他bus隐含NOP；两个完整模板用于长立即数等情况。
fourway128 bit40、72、128、128 bit40-bit模板保留前两个bus，其余隐含NOP；72-bit模板另带32-bit立即数。

假设FRV五个逻辑槽为[Load, Store, Vector, Scalar, SFU]，硬件只有以下模板：

T0：只允许 Load + Scalar，其余槽隐含 NOP
T1：只允许 Vector + SFU，其余槽隐含 NOP
T2：完整五槽

[Load1,NOP,NOP,Scalar1,NOP]可以用T0；但[Load1,NOP,Vector1,NOP,NOP]若没有对应短模板，即使只有两个有效操作，也只能使用完整T2。

1.1 编译器为何参与压缩

Kultala通过功能单元优先级和调度后NOP优化器，在不破坏数据依赖的前提下移动操作，让更多周期命中短模板。例如：

原调度：
周期0 [Load, NOP, Vector, NOP, NOP]  → 无短模板匹配
周期1 [NOP,  NOP, NOP,    Scalar, NOP] → 无短模板匹配

若Vector允许延后：
周期0 [Load, NOP, NOP,    Scalar, NOP] → T0
周期1 [NOP,  NOP, Vector, NOP,    NOP] → T1

这种优化并非免费：只有在操作具有调度余量时才能移动，论文也报告了轻微性能变化。FRV五个槽功能不同，Vector操作不能搬到Load槽，因此TTA中的bus重分配能力不能原样照搬。

2. 之前的Kultala模型为什么不成立

此前脚本实际上定义了一个新的FRV格式：

00：空周期
01：该程序池最常见的非空mask 1
10：该程序池最常见的非空mask 2
11：escape，后接5-bit mask
  1. 模板按程序池训练：BERT、SD-UNet和LLaMA分别选择各自的两个常见mask，等于一颗核使用三套不同的硬连线模板。对于未知程序覆盖替换的通用核不成立。
  2. 空周期只计2 bit：原论文中全NOP周期仍要占用一条最短合法指令，如32或40 bit，并不是只保存模板号。
  3. 没有复现调度优化：没有实现论文的function-unit prioritization和NOPOptimizer，因而既不是原论文编译器复现，也不能引用原论文收益。
  4. 变长前端未计：没有计入跨字对齐、预取buffer、变长PC、分支入口映射以及最坏码率。
通用性约束：五槽共有32种mask。少量固定模板不能覆盖所有组合；如果把模板增加到覆盖32种，模板标识至少需要5 bit，逐渐接近E1的5-bit mask。若改成可编程模板，还要计入模板表、装载协议和可编程路由，这已经不是Kultala原硬连线方法。

3. Brandon 2015 stop-bit：原论文方法

原文：A Sparse VLIW Instruction Encoding Scheme Compatible with Generic Binaries。它把一拍并行执行的有效操作称为一个bundle，每个有效操作是一个syllable；最后一个syllable的stop bit置1。

例如FRV周期：

[Load=L1, Store=NOP, Vector=V1, Scalar=NOP, SFU=NOP]

安全的FRV移植至少需要：

[slot=Load   | payload=L1 | stop=0]
[slot=Vector | payload=V1 | stop=1]

解码器读到stop=1后，才知道当前周期结束，然后把两个syllable散布回Load和Vector槽，输出完整五槽指令。此前模型按34-bit payload + 3-bit slot ID + 1-bit stop = 38 bit计算一个有效syllable。

3.1 为什么ρ-VEX上的代价不能直接套到FRV

Brandon的ρ-VEX具有重复功能单元、动态2/4/8 issue组合和已有dispatch网络，opcode还能限制syllable可路由到哪些lane。论文实际实现了instruction buffer、未对齐取指、跨cache-line拼接、变长NextPC和分支目标检测，并指出新增流水级会增加分支延迟。FRV五槽固定异构，如果payload本身不能唯一指示逻辑槽，就必须增加slot ID或更复杂路由。

4. stop-bit无法自然表示零syllable空周期

对FRV必须保留的全NOP周期：

周期t：[NOP, NOP, NOP, NOP, NOP]

纯stop-bit格式出现根本问题：空周期有零个有效syllable，因此没有任何stop bit。解码器看不到周期边界，会把下一周期第一个syllable错误地并入当前bundle，时间轴也会少一拍。

正确处理方式需要保存什么代价与风险
显式NOP syllable[slot/empty tag | NOP payload | stop=1]按当前FRV安全格式约38 bit；容易证明正确。
专用EMPTY短码一个固定、前缀无歧义的EMPTY token必须证明存在保留opcode、长度可判定、分支可落入以及不会与普通syllable冲突。
额外周期边界位图为每个逻辑周期保存边界/空周期信息逐渐退化为mask或纵向压缩，不再是纯stop-bit。
此前错误：脚本把空周期计成4 bit，却没有定义这4 bit如何与普通38-bit syllable无歧义地区分。因此它只是理想信息量，不是可实现编码。

6. 可以怎样从通用性角度进行公平区分

维度Kultala模板Brandon stop-bitE2-5
未知程序适应性依赖固定模板覆盖率；论文模板还使用adpcm画像选择。不依赖mask训练，但依赖ISA、opcode与dispatch结构。5-bit mask覆盖全部32种五槽组合，不按程序训练。
异构固定槽TTA bus可重分配能力在FRV上受限。需要slot ID或复杂路由。mask直接保留逻辑slot身份。
空周期必须保存最短合法空指令。必须增加显式NOP或EMPTY token。config中的零mask自然表示空周期。
逐拍确定恢复需要变长边界解析和预取buffer。最长五syllable约190 bit，超过一次174-bit读取。五lane按最坏并发配置，每拍恢复边界明确。
跳转/随机入口需要压缩地址映射或对齐。论文增加buffer和分支处理，并有额外分支延迟。config逻辑周期地址固定；FRV当前直线微程序语义更简单。
主要优势命中短模板时单体程序存储密度高。有效操作少时能删除尾部和中间NOP。格式固定、所有mask通用、无需按值或模板训练、吞吐可界定。
建议论文表述：Kultala和Brandon主要面向按字节寻址、带缓存的变长程序存储；E2面向要求每周期确定恢复一条完整宽指令、逻辑槽异构、程序池可替换且SRAM bank统一定深的微程序式VLIW核。前两类方法追求更高理论bit密度，但需要变长边界、buffer、路由和分支处理；E2用固定周期恢复和任意mask覆盖换取可预测硬件。

7. 纵向压缩论文是否比较了这两项工作

Li等2020全文：An Efficient and Fast VLIW Compression Scheme for Stream Processor。全文和参考文献中没有Kultala、Brandon、stop-bit或固定短模板＋调度后优化。其Table 4主要比较Guan 2012、Ji 2013、Jin 2014以及Seong与Mishra 2006的bitmask方案。

原论文没有解释为何遗漏。合理推测是平台和目标不同：Li关注CISP片上banked instruction memory的一拍直接执行，而Kultala/Brandon面向变长TTA/ρ-VEX取指前端。但这仍属于相关工作覆盖不完整，不能作为本文不比较它们的理由。

8. 为什么此前没有正确完成这一对比

此前工作先把两篇论文作为相关工作讨论，认为其平台前提与FRV差异较大，因而没有立即建立变长取指前端。随后为了补齐第五部分，我用“最常见mask模板”和“短EMPTY token”快速构造了机制模型，却把理想信息量当成了可实现格式，没有首先验证零syllable周期、前缀无歧义和最坏吞吐。这是实验建模错误，而不是论文结果本身对E2不利。

9. 下一步正确实验

  1. 撤回旧HTML中Kultala/Brandon三池的正式CACTI百分比。
  2. Kultala三个程序池共用一套设计前固定模板，禁止逐池训练；空周期按最短真实FRV模板计费。
  3. Brandon主结果用一个38-bit显式NOP syllable表示空周期；专用EMPTY只作为经过前缀编码证明后的乐观敏感性结果。
  4. 构造真实bitstream和逐bit解析器，验证每个逻辑周期、空周期和程序边界完全恢复。
  5. 扫描任意窗口内的最大bit产生率，计算174-bit取指下保证不停顿所需的最小buffer；若存在长期平均码率超过174 bit/周期，则必须增加带宽或报告性能下降。
  6. 计入buffer、barrel aligner、变长PC、边界表和slot scatter后，再重跑CACTI和RTL开销。
最终判断：修正空周期后，现有数据没有证明Kultala或Brandon能在FRV上支配E2。它们仍应作为相关工作和强baseline，但比较重点必须从“理想bit数”升级为“保留所有空周期和程序边界、保证每拍恢复、计入变长前端后的系统成本”。
