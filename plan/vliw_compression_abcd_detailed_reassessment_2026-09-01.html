VLIW 压缩 Candidate A/B/C/D：逐实验、逐 SRAM 与方向重判

日期：2026-09-01　|　数据：仓库 12 条 best trace，重点复算 Softmax X32 / LayerNorm X32 / GELU X32　|　结论级别：早期研究判断，不是流片 sign-off

结论先行：Candidate D 不是“只对 mem_addr 做 delta”，而是对 LOAD/STORE 的 mem_addr[27:0] 与 gpr_addr[7:0] 分字段差分，同时保留 6-bit 原控制字段、定宽主流和完整指令例外流。但当前实验证明，它仍然主要依赖本平台内存槽的规则地址，尚不足以成为一般性 VLIW 压缩论文的核心创新。
更关键的是：按三个代表程序分别定制 SRAM 时，D 含已建模增量逻辑后，相对 A 在 GELU X32 节省 10.1%，却在 LayerNorm X32 增加 13.5%、在 Softmax X32 增加 35.1%。全 12 trace 的“最大深度统一配置”得到约 8.77% 面积节省，并不代表逐程序都获益。当前不建议把 D 单独立项为第四篇论文。
A物理 Pareto 基线简单、定宽、直接逐周期恢复；接近 Li 式纵向压缩，不能当新创新。
B淘汰单 SRAM 的小幅宏面积收益被 256-bit 包缓存、FIFO 和分发覆盖。
C逻辑上界位数最低，但约 1.08 万 GE 的变长抽取器使物理总面积明显失败。
D局部技术固定字段预测本身硬件友好，但当前净收益小、跨工作负载不稳、一般性不足。

1. 本轮到底做了什么实验

  1. 调用现有真实编码器/解码器重新生成 A/B/C/D 数据；不是按概率估计长度。每个候选最后都按原 calendar 恢复五个槽，并逐周期逐 bit 与原 CSV 对拍。
  2. 对三个代表测例逐个列出逻辑 SRAM 宏的数量、字宽、字深，并把每个宏独立送入 HP CACTI 7（32 nm scratch-RAM 配置）。CACTI 对过小组织无合法解时，按 2 的幂增加物理深度直到得到合法宏；JSON 同时保留逻辑容量和 CACTI 实际分配容量。
  3. 逻辑面积采用已有 Yosys/ABC 门数，并以公开 SAED32/28 NAND2X1=2.54144 μm²粗换算。A 的公共计数器/对齐逻辑尚未综合；B 只有包寄存器上界；C 是未含完整控制器的下界；D 是两套 LOAD/STORE 恢复器的早期估计。
  4. 新增 opcode-context 差分实验：不增加主码字段，直接用指令中已有的 4-bit optype选择“上一条同 opcode 操作”，检验 D 能否推广到 VECTOR/SCALAR/SFU。全部 12 trace 均完成精确 roundtrip。
面积口径必须注意：下面三个测例的面积是“若硬件只按这一条程序所需深度定制”的比较，用于观察候选的工作负载敏感性。一个可运行全部程序的通用核，应对每个 Bank 取所有程序中的最大深度；不能把三个逐程序面积相加或取平均当成最终核面积。

2. Candidate A：Calendar + 五条原生纵向槽流

2.1 编码实验

原始 VLIW 每周期 184 bit，由 LOAD 42、STORE 42、VECTOR 34、SCALAR 31、SFU 31 和 CONTROL 4 组成。A 对每个非末周期写一个 5-bit mask；mask 的第 s 位说明该周期槽 s 是否有效。每个槽只顺序保存非零操作，NOP 不进入 payload。总周期数和程序参数存入 256-bit 头，EOP 由“最后周期”隐式生成。

A_bits = 256 + 5×(T−1)
       + 42×Nload + 42×Nstore + 34×Nvector + 31×Nscalar + 31×Nsfu

3. Candidate B：单 256-bit 包 SRAM + 截止周期供给

3.1 编码与供给实验

B 先生成与 A 相同的六条逻辑流，再把同一逻辑流的记录装入固定 256-bit 包。每包用 3 bit 标识流类型，余下 253 bit 可装 50 个 calendar mask、6 个 LOAD/STORE、7 个 VECTOR 或 8 个 SCALAR/SFU。不同流不能混在同一包内，因此会有尾部填充。

每个包的 deadline 是包内第一条记录最早被消费的原始周期。软件从后向前安排“每周期最多返回一个包”，并模拟六条逻辑队列；允许程序开始前预取，但在执行周期 t 只按 calendar 弹出原 trace 在 t 所需的记录。三个代表测例都无下溢，启动预取均为 1 个返回周期。

3.2 硬件

  • 架构只有 1 个 256-bit 物理程序 SRAM，但并没有消除六条逻辑队列。
  • 主要额外开销：256-bit 返回寄存器、3-bit tag 解码、宽 demux、六条 FIFO/Reservoir、每流计数/valid、日历 pop 控制以及多事件拆包写入。
  • “峰值在途包×256”只是把所有在途包都放 DFF 的保守上界，不是最终实现面积；真正 RTL 可能用原生宽 FIFO 降低，但仍需多写口、保留寄存器和路由。因此本报告不伪造 B 的精确总面积。

为什么失败：在全 12 trace 的最大配置中，单包 SRAM 为 0.044985 mm²，只比 A 的六 Bank SRAM 0.048107 mm²小 6.49%；尚未加入任何 FIFO 和 demux。三个逐程序比较中，B 的 SRAM 甚至在 LayerNorm/Softmax 已经大于 A。B 不再进入主线。

4. Candidate C：16-event 语义块 + RAW/CONST/STRIDE/DELTA

4.1 编码实验

C 保留 5-bit calendar，但把每个槽的有效指令拆成“控制字段”和“操作数字段”。每 16 个 active event 独立选一种模式：

  • RAW：逐条保存 operand；
  • CONST：整个块只保存一个 operand；
  • STRIDE：保存 base 和一个全宽 stride；
  • DELTA：保存 base，再用块内可选的小差分位宽保存后续值。

每块头固定 16 bit：2-bit mode、4-bit 条数减一、3-bit delta-width code、7-bit reserved。控制字段使用由全部 12 trace 一次性建立的静态 ISA profile，未命中则写 literal control；每个 token 仅允许 4-bit 边界，每块补齐到 64 bit。三个代表程序没有各自训练字典。

4.2 恢复硬件

每个非空槽用 64-bit SRAM。恢复端需要每槽 128-bit token window/双行寄存器、bit cursor、跨行 barrel-style extraction、模式状态、profile ROM、escape 解析、base/stride/delta 加法器和块边界控制。现有简化 RTL约 10,800 GE ≈ 0.027448 mm²，而且尚未含完整 header/controller/profile ROM 和布线，所以这是下界。

C 的意义是证明 A 后面仍有信息冗余，而不是证明这种冗余值得在每拍恢复前端中提取。全套逻辑位数 16.211%，优于 A 的 21.812%；但 SRAM+解码逻辑的物理面积比 A 更差。

5.1 它并非只做 mem_addr delta

最大配置下，A 的 LOAD/STORE Bank 由很长的程序决定，D 对这些深 Bank 的缩窄能摊薄固定恢复器面积；Softmax/LayerNorm 单程序的 L/S Bank 很浅，恢复器固定成本反而大于 SRAM 节省。这正是“逻辑压缩比”不能替代“实际物理面积”的例子。

7. D 能否挖掘出比“内存地址 delta”更一般的优势

7.1 已确认的一般性机制

  • Calendar 与 value predictor 解耦：calendar 保证事件发生周期，字段预测器只处理同槽 active-event 序列；所以预测成功率不会影响 issue 周期。
  • 定宽正常流 + 原生例外流：正常路径可直接寻址，无 variable-bit cursor；连续例外也能通过独立端口保持一条/拍。这比 C 的变长块更硬件友好。
  • 字段级而非整指令 delta：不同位宽字段分别模加，控制字段原样保存，格式不依赖 workload-trained 字典。

这些原则确实可用于其他静态 VLIW/CGRA 指令流，但它们目前只是一个通用设计模式；真正取得收益的数据相关性仍集中在本平台的 LOAD/STORE 地址。

7.2 新增 opcode-context 实验：逻辑上有效，物理上仍失败

为了避免只看相邻槽事件，本轮用主码中已有的 optype选择 previous context：例如 VECTOR opcode=ADD 的 dst/src delta 只相对上一条 ADD，而不受中间 MUL/SUB 干扰。无需额外 context bits，但每个 opcode 都要保存一组 previous operands。

7.3 D 相对 A 还能保留什么价值

  • 作为设计时可选的 slot codec：对具有长、规则内存流的 VLIW，可在综合时把该槽从 A 的 RAW vertical 换成 fixed-delta；对短流或不规则槽回退 A。这里的重点应是“物理成本驱动的自动选择”，不是宣称 delta 本身新颖。
  • 作为容量敏感性工具：当程序常驻数/展开因子使 L/S Bank 很深时，D 才可能跨过固定逻辑成本的 break-even；这一点可与第三篇的 R/tile 选择联动。
  • 作为 C 的硬件化边界：D 说明牺牲一部分压缩率换固定边界可以大幅降低解码器；适合作为论文中的设计空间点或消融。

不能声称的优势：D 不是新的通用 delta 算法，不保证每个 VLIW workload 都优于 A，也没有目前证据证明总能耗或总面积稳定下降。

checkpoint/LAT当前第三篇 trace 为直线程序，无分支/随机入口当前没有需求；未来支持跳转才需要
mask 驱动读/分发门控 D3A 已天然知道每周期有效槽可做能耗优化，但不是压缩新颖性；需门级功耗证明
R/tile/展开因子协同 D4压缩改变可常驻程序容量与 Bank break-even仍有潜力，但会改变调度/周期结果，必须升级成新的软硬件协同问题
等价编码降低翻转不减少存储容量，只可能降动态功耗可作能耗消融，不能救活压缩论文

9. 不到 10% 的潜在优化是否值得做

作为一篇独立小论文：当前不值得。“8.77%”还是 CACTI + generic GE 的早期结果；两条代表 workload 的逐程序面积反而恶化；总能耗目前只有 SRAM-only 的 5.67%下降，加入解码器可能归零；机制又主要由本平台规则 L/S 地址产生。它达不到足以抵抗审稿人“只是 A 上加 delta”的证据强度。

可以把 D 保留为 1–2 周 kill test，但不应直接投入 3–4 个月完整实现。继续进入主线至少要同时满足：

  • 真实工艺库 + SRAM compiler 或一致的 PPA 流程中，总 instruction-front-end 面积相对 A 至少下降 15%；
  • 计入解码器、时钟和路由后，总取指/恢复动态能耗至少下降 15%；
  • 1 GHz 或目标频率无停顿，连续例外、inactive bubble、程序切换全部 cycle-exact；
  • 除本项目 12/28 条 trace 外，至少加入一组独立 VLIW/CGRA/static-accelerator 指令流仍有稳定收益。

当前数据四项均未满足，所以正确的科学判断不是继续包装 8.77%，而是承认 D 只是一项局部优化。

10. 是否应承认普通纵向压缩已经最优

不能说“信息论最优”。C 的 16.211%和 field oracle 的约 10.02%已经证明 A 后面还有可压缩信息。更准确的表述是：

在当前约束下——压缩态片上常驻、五类异构槽、每周期精确恢复、稳态一拍一条、统一格式、很小解码器——Candidate A 已接近当前 trace 与 32 nm 估算中的物理 Pareto 前沿。后续压缩率收益会迅速换成 SRAM 取整、例外 Bank、状态寄存器或变长抽取逻辑，尚未找到稳定超越 A 的通用 codec。

这是一个有价值的否定性结论，但单独写“我们试了很多，A 最好”通常不足以构成第四篇论文。若继续 VLIW 方向，必须调整问题定义。

11. 推荐的问题重定义与下一步

11.1 首选：物理成本驱动的稀疏 VLIW 指令供给综合

把论文问题从“发明一个永远优于 A 的 codec”改成：

给定静态 VLIW ISA、调度 trace、目标 SRAM 编译器和吞吐约束，如何在设计时为每个槽自动选择 RAW vertical、fixed field predictor 或不压缩，并共同确定 Bank 宽深、例外容量和流水级，使总面积/能耗最小且周期精确？

这里 A 是默认最优点，D 是某些长内存槽的可选原语，C 是不可实现的软件上界。生成器在硬件设计/综合时选择并删除不用的 codec，不是在每个 workload 运行时携带所有解码器，因此避免“通用菜单硬件全付费”。真正可能的创新应是物理成本模型、break-even 推导、自动生成 RTL/SRAM 配置和跨 ISA 验证，而不是 delta 本身。

风险：必须加入独立静态 VLIW/CGRA trace，否则仍会被认为是为第三篇 ISA 定制；还要证明自动选择比固定 A 有显著平均收益。若无法获得独立 trace，这条路不宜投稿。

11.2 更强但工作量更高：instruction-capacity-aware scheduling / R-tile 协同

第三篇已经在 R/tile、展开和执行周期之间做选择。新问题可以把“压缩后真实 SRAM 宏面积/容量”加入调度目标：不是保持原论文每一周期完全不变，而是重新生成一个功能等价但在性能—指令容量—取指能耗上更优的 schedule。压缩可能允许更大展开、更少分块或更多函数常驻；即使 A 已是最佳 codec，也可能产生系统级收益。

这比“再省 A 的 8%”更可能形成论文，但它与 compression-aware scheduling / modulo scheduling 的已有工作更接近，必须重新做文献边界，而且会改变当前“逐周期对拍原 trace”的硬约束。它是明确的问题重定义，不是 D 的延伸补丁。

11.3 Go/No-Go 安排

  1. 第 1 周：完成 A 与 D 的同一套 cycle RTL、真实 SRAM latency wrapper、切换/例外测试；拿到可信增量逻辑与功耗，不再只用 GE。
  2. 第 2 周：在 Softmax/LayerNorm/GELU 上做 Bank 深度 sweep，画出 D 相对 A 的 break-even 曲线；若目标工艺总收益仍 <15%，正式停止“D 独立 codec”路线。
  3. 第 3–4 周：选择“设计时 codec synthesis”或“容量感知 scheduling”之一做最小闭环；同时获取至少一套独立 trace。没有独立 trace 时直接 No-Go。
  4. 第 4 周决策：只有在独立数据上出现可重复的 ≥15% 总面积/能耗或明确系统 Pareto 改善，才投入余下 8–10 周论文实现。

13. 公开模型与数据边界

  • HP CACTI 官方仓库：SRAM 宏面积、访问时间、泄漏和单次读取能耗的分析模型。
  • SAED 32/28 nm 标准单元文档：NAND2X1 公开面积量级。
  • Base-Delta-Immediate, PACT 2012：低动态范围和并行 base+delta 解码的思想来源。
  • PForDelta 相关工作：定宽正常值与例外流的思想边界。

CACTI 不是目标 foundry SRAM compiler；GE×NAND2 面积也不是 place-and-route。所有面积数字只适合方向筛选，不适合论文最终 PPA 表或流片判断。最终报告必须补真实 liberty/memory compiler、综合、STA、功耗和布线裕量。

最终建议给导师的一句话：普通纵向压缩 A 不是信息论最优，但在当前“压缩驻留 + 周期精确 + 一拍一条 + 小解码器”约束下已接近物理最优；D 的固定字段预测只在长规则内存流上过 break-even，现有不到 10%的全套粗面积优势且在两个代表程序上反向，不足以独立成文。继续 VLIW 方向必须把核心问题升级为“物理成本驱动的指令供给综合”或“压缩容量感知调度”，否则应及时停止该路线。
