阅读前先看：本文术语和缩写是什么意思

本文保留少量英文，是为了能与代码变量和已有论文对应。第一次阅读时可先看本节； 后文中的“Bank”“Lane”等词都只取下面定义，不含其他隐含意思。

术语本文中的通俗含义
VLIW超长指令字。一条指令同时包含多个功能槽，规定这一拍哪些功能单元执行什么操作。
槽（slot）VLIW中固定分给某类功能单元的位置。本文有LOAD、STORE、VECTOR、SCALAR、SFU五个功能槽。
LOAD / STORE分别把数据从片上数据存储器读入计算通路、以及把结果写回数据存储器。
VECTOR / VE向量计算槽/向量执行单元，一条操作同时处理一组数据。
SCALAR标量计算槽，一条操作处理单个普通数值或控制量。
SFU特殊函数单元，用于指数、倒数等普通加减乘之外的非线性操作。
GPR通用寄存器（General-Purpose Register），保存普通中间数值或地址。
mem_addrLOAD/STORE操作中的片上存储地址字段，指出要访问哪一行向量数据。
发射宽度（issue width）一拍最多能同时启动多少个有效操作。“2-wide”或“双发射”就是一拍最多两个。
Lane（物理通道）保存并输出有效操作的共享34-bit通道。它不是新的功能单元；Lane中的操作还要按配置码送回五类功能槽之一。
Bank（独立存储块）一块可独立寻址和读取的SRAM。五槽方案有五块操作Bank，双Lane方案只有两块共享操作Bank。
SRAM片上静态随机存储器，本文用来常驻保存压缩后的程序指令。
Configuration / Calendar每拍的5-bit配置记录，说明本拍哪些Lane有效、分别送往哪个功能槽，以及程序是否结束。
mask（有效位图）用若干bit直接标记哪些功能槽有效。例如五位中的第3位为1，表示对应槽本拍有操作。
payload（操作内容）真正的34-bit有效操作内容，包括操作码、寄存器和地址等；不包含“送往哪个槽”的配置信息。
NOP空操作。该槽本拍什么也不执行，通常用操作码为0表示。
EOP程序结束标志（End Of Program），通知取指电路不再继续读取本函数。
Trace（指令轨迹）调度器生成的一整条逐周期指令记录；每一行对应一个执行周期。
workload（测试任务）被编译和测试的函数及输入规模，例如GELU X64或Softmax X32。
X32 / X64同一函数分别使用X=32或X=64的输入/分块规模，不表示32-bit或64-bit数据类型。
mode（调度模式）原调度器针对功能单元虚拟化等资源配置提供的候选设置；实验会为每个任务比较不同mode。
schedule（调度结果）编译器决定每个操作在哪一拍、哪个功能槽执行后形成的逐周期安排。
DAG有向无环依赖图。节点是操作，边表示一个操作必须等待另一个操作产生结果。
依赖/资源冲突依赖是后一个操作必须等待前一个结果；资源冲突是同一拍有多个操作争用同一个功能单元、端口或存储Bank。
active state调度器正在跟踪的尚未完成或仍占用资源的数据/操作状态；过早发射可能让它们存活更久。
编码—解码往返验证（roundtrip）先把原数据编码，再解码回来，逐项核对是否完全一致。它证明软件格式正确，不等于RTL硬件已经验证。
bit-exact逐bit完全相同，包括所有有效字段和要求为零的无效字段。
行为等价每拍真正执行的操作及结果相同；不影响执行的无效字段允许保持旧值以降低翻转。
编码/解码格式（codec）规定指令如何缩短保存、又如何恢复的规则。后文不再用“codec路线”代替这一完整含义。
RAW / DICT / DELTA三种保存字段的方法：RAW原值直存；DICT用字典编号代替常见值；DELTA保存与前值的差。
CONST / STRIDECONST表示一组值恒定；STRIDE表示按固定步长变化，可用起点和步长恢复。
oracle（软件理想上界）软件事后查看完整数据，为每个字段挑最省位数的方法。真实硬件事前不知道答案，因此该结果只代表理论参考。
exception / RAW escape预测或差分无法表示某个值时，额外保存一次完整原值的补救记录。
template（指令模板）预先规定哪些槽可以省略的指令格式。匹配不同模板时，已有工作的一条指令可有不同长度。
fallback（保底完整格式）短模板装不下时，退回可以容纳所有槽的完整宽指令，程序仍然可以执行，只是占空间更大。
post-pass（调度后优化）主调度完成后再运行的一次整理，不从头生成整个schedule。
slack（可移动余量）在不违反前后依赖、也不延长程序的条件下，一个操作最早和最晚执行周期之间的空间。
priority / importance（优先级）多个操作同拍都可以发射时，调度器用来决定先选谁的分数。
critical path / fanout / age分别表示最长依赖路径、一个节点能解锁多少后继、节点已经等待多久，都是构造优先级的候选指标。
bottom-level从当前节点走到程序末尾的估计最长剩余延迟，用来近似该节点是否位于关键依赖路径。
latency（延迟）一个操作发射后，要经过多少拍才能产生可供后续操作使用的结果。
pair-aware不只给单个节点打分，还估计两个节点放在同一拍是否合适。
beam search（有限候选搜索）每一步只保留少量最有希望的调度方案继续尝试，在质量与软件运行时间之间折中。
Bank folding（存储块折叠）让多条逻辑操作流共用更少的物理SRAM Bank。本文是五条功能槽流共用两个Lane Bank。
代码池（code pool）一块统一容量的片上指令存储区域，可同时装入多个函数，也允许以后卸载旧函数、换入新函数。
base / length / descriptor程序描述符中的起始地址、有效长度和其他元数据，用于找到某个函数在代码池中的位置。
header（头部元数据）放在程序开头、不是功能操作本身的信息，例如各流长度、起始地址和版本。
padding（填充浪费）为了让Bank深度或程序块形状整齐而保留、但没有存放有效操作的空间。
2次幂取整所需深度不是1024、2048、4096等常见规格时，向上配置到可实现容量，产生额外空余空间。
sub-bank（子存储块）把一个深Bank拆成几个较浅、可分别关闭的Bank，以降低单次读取能耗，但会增加外围电路。
FIFO / Reservoir先进先出队列/暂存池，用来提前缓存未来操作。当前双Lane方案不需要它们。
demux / router分流器/路由器。根据配置码把一条Lane输出送到五个功能槽中的指定位置。
scoreboard / interlock运行时检查依赖或资源未就绪并暂停发射的硬件。本文目标是由静态调度避免需要这种动态纠错。
RTL寄存器传输级硬件代码，例如Verilog；比Python格式模拟更接近真实电路。
STA静态时序分析，用来检查电路在目标时钟频率下能否按时完成信号传播。
SAIF / VCD记录硬件信号翻转活动的文件，用于估算动态功耗。
CACTI公开的存储器估算工具，根据Bank宽度、深度和工艺粗估SRAM面积、延迟和能量；不是代工厂最终数据。
SRAM宏（memory macro）按固定字宽、字深实现的一整块存储器硬件，例如34×4096表示4096行、每行34 bit。
foundry SRAM compiler芯片代工厂提供的存储器生成工具；它给出的目标工艺面积和时序比CACTI粗估更可信。
GE门等效数量，把逻辑规模折算成若干个基本逻辑门，仅用于早期粗估。
PPA性能、功耗、面积三项硬件指标的合称。
Pareto点无法在不牺牲其他指标的情况下继续改善某一指标的折中方案；例如更小面积但更高能耗。
EDA电子设计自动化，即自动搜索硬件结构、生成电路并评估实现结果的一类工具流程。
消融实验逐个关闭或替换方案组成部分，确认最终收益究竟来自哪一项，而不是只报告总结果。

1. A/B/C/D详细重判给出的直接起点

基准文档对四类候选完成了真实编码/解码、编码后再解码并逐周期核对、SRAM物理组织粗估和逻辑规模粗估。 本文不是从“已经选定双Lane”开始，而是从以下结论继续寻找可在四个月内完成的新问题。

候选机制基准文档结论对本文的影响
Candidate A 每拍保存5-bit槽有效记录，五类槽各自把原始34-bit有效操作依次存入独立SRAM；有效位控制各自读指针。 定宽、无需补救记录、无需缓存队列，已接近面积—能耗折中前沿；但接近Li式纵向删除NOP，创新不足。 保留为所有新方案必须击败的强基线。
Candidate B 把各类记录装入固定256-bit数据包，包头用3 bit标明流类型；用六条先进先出队列提前缓存。 全部SRAM只比A小约6.49%，尚未加入队列和分流电路；逐程序Softmax/LayerNorm甚至已经更差。 “用数据包和队列把六个Bank合成一个Bank”的方案淘汰；后续双Lane明确不使用队列。
Candidate C 每16个有效操作为一组，在原值直存、常数、固定步长、相邻差值之间选最短表示，并从变长比特流中提取。 逻辑容量可到16.211%，但简化恢复器已约1.08万个基本门等效，加入逻辑后的总面积反而更大。 只证明A之后仍有信息冗余；不作为硬件格式。
Candidate D LOAD/STORE的存储地址和通用寄存器地址优先保存相邻差值；表示不了时另存完整原值。 最大配置粗面积约−8.77%，但GELU X32为−10.1%，LayerNorm X32为+13.5%，Softmax X32为+35.1%。 只保留为后期局部地址优化，不作为通用核心。

1.1 为什么不继续只寻找传统编码/解码压缩格式

  • 软件事后为每条指令轨迹、每个字段自由挑选“原值、字典编号或相邻差值”的理想结果约为10.02%，但真实固定硬件无法事先知道每个字段该选哪一种。
  • 普通值字典无法跨不同非线性测试任务稳定复用；静态乱序发射也会打乱简单的地址差值规律。
  • 间隔字典、有效槽组合模板和重复周期片段的额外收益，不足以覆盖字典编号、历史状态和解码电路成本。
  • A并非理论上再也不能压缩，但在“压缩格式直接驻留片上、每拍持续供给、所有任务使用同一格式、解码器很小”的约束下，传统编码/解码方法已很难稳定超过A。

1.2 基准文档给出的两个问题重定义

11.1 物理成本驱动供给综合

设计时共同搜索编码方法、SRAM宽度和深度、完整原值补救区容量及流水级数。后续讨论认为它更像自动硬件设计工具研究，还需要外部VLIW/CGRA指令数据和自动生成硬件代码，四个月风险较高，因此未选为主线。

11.2 容量感知调度/R-tile协同

允许重新生成一个功能结果相同的逐周期调度，把执行周期、指令容量和取指存储器成本共同考虑。本文的“每拍最多两个操作+两个共享物理通道”正是沿这条路线形成。

1.3 152-bit过渡阶段（中间文档已作废，但结果保留）

首先把mem_addr从28 bit缩到12 bit，使LOAD/STORE从42 bit降到26 bit，形成 26/26/34/31/31+4=152 bit的过渡ISA。随后进行第一轮index-first双发射调度：

  • 相对旧五槽调度总周期增加1.66%，证明每拍最多双发射在这些指令轨迹上有现实性能潜力。
  • 双34-bit Lane因26/31→34 bit补宽，逻辑容量比A增加9.49%。
  • 旧“对12条指令轨迹的每条流分别取最大深度”存储器估算中，分段SRAM面积−6.41%，加入约337个基本门等效的逻辑后仅−4.80%。
  • 旧模型累计读能量+21.41%，说明减少Bank数量不保证降低动态能耗。

这些结果直接触发了后续等宽174-bit ISA、复杂importance、强五槽调度基线和可替换代码池讨论。

3. 从152 bit改为174 bit的等宽ISA

历史152-bit格式

LOAD       26
STORE      26
VECTOR     34
SCALAR     31
SFU        31
CONTROL     4
=          152 bit

当前174-bit格式

LOAD       34
STORE      34
VECTOR     34
SCALAR     34
SFU        34
CONTROL     4
=          174 bit

LOAD/STORE将12-bit mem_addr扩展为20 bit，使其达到34 bit；SCALAR/SFU使用34-bit槽容器。 等宽槽可简化取指接口、路由、解码和SRAM宏比较，也消除了双Lane对窄槽的额外填充损失。

必须向审稿人解释20-bit mem_addr： 若一个地址直接对应256×16-bit向量行，则220行等价于512 MiB，不应声称全部一次性物理实现为片上SRAM。 更合理的语义是“12-bit本地行地址 + 8-bit bank/tile/region”，或明确它是架构地址空间。 174-bit是正式ISA决定，不能仅以“外界不知道实现”为依据。

4. 所有方案的清晰定义

4.1 未压缩174-bit横向VLIW

每周期完整保存五个34-bit功能槽与4-bit CONTROL，无论槽是否有效都占据174 bit。

4.2 Candidate A：5-bit Configuration + 五条纵向槽流

Configuration每周期给出五槽有效mask；EOP可由长度隐式产生。每个34-bit槽流只保存该槽的有效操作。 每个槽有独立读指针，mask=1时读取并递增，mask=0时保持。

A logical bits = header + 5×configuration cycles + 34×(Nload+Nstore+Nvector+Nscalar+Nsfu)

4.3 A-trace-fitted / A-compact

五个槽Bank分别按照当前三条已知Trace的总事件数紧凑定容。它容量小，但SCALAR等Bank可能只需要1024深， 无法保证未来替换程序具有不同槽分布时仍可装入；每个函数还需要五组独立base/length和五Bank空间管理。 它保留为容量优先的下界，不作为最终固定硬件主基线。

4.4 A-simple-rectangular

每个函数在五个槽Bank中使用相同payload base，函数块高度取该函数最高槽列，其余槽补齐。 程序替换最简单，但padding最大。当前三函数相加后每个Bank需4096深。

4.5 A-symmetric：当前主Baseline

为支持未来程序替换，五个34-bit槽Bank都固定为2048深。它不依赖当前SCALAR只需1024的偶然统计， 并定义产品级容量契约：任一槽类型在整个代码池中的事件总数不得超过2048。

4.6 双Lane固定横向格式

5-bit Configuration + 34-bit Lane0 + 34-bit Lane1 = 73 bit/cycle

每周期固定占73 bit，空Lane也占位。硬件简单，但没有纵向去除空Lane，因而不作为最终格式。

4.7 双Lane纵向格式：当前方案

Configuration逐周期保存，Lane 0/1只保存有效事件。每周期最多两个功能操作； 单操作放入较短Lane以平衡深度。当前三函数代码池中两条Lane均配置为34×4096。

4.8 34+31-bit非对称Lane

由于只有VECTOR需要34 bit，曾提出一条34-bit全功能Lane和一条31-bit非VECTOR Lane。 它可以降低旧152-bit ISA下的填充和读能量，但与“所有功能槽统一34 bit”的新架构决定冲突，当前不继续。

5. 如何决定一拍内优先发射哪些操作

5.1 为什么不能只优先选择长延迟操作

长延迟操作提前发射有机会隐藏等待时间，但只有它位于决定总周期数的最长依赖路径上时才有价值； 过早发射LOAD可能让更多未完成数据同时存活，SFU/向量操作可能长期占用共享资源， STORE则可能释放正在使用的向量。因此只看操作自身延迟并不足以作出选择。

7. 双Lane编码格式

7.1 5-bit码本为什么刚好

两Lane都无效：1 单Lane有效：5种slot × 2个Lane = 10 双Lane有效且slot类型不同：5×4 = 20 正常状态总计：31 EOP：1 总计：32 = 2^5

Configuration同时编码Lane valid、Lane到功能槽的映射和EOP。两条Lane不会映射到同一功能槽。 `(None,None)`表示正常空周期，码31保留给EOP。

7.2 Lane构造

  1. 逐周期读取最多两个有效功能槽。
  2. 双操作按合法映射分别写Lane 0/1。
  3. 单操作写入当前较短Lane，使最终深度尽量平衡。
  4. 空周期只写Configuration，不写Lane。
  5. 解码时按Configuration使能对应Lane指针并路由回五槽。

8. 能否逐周期精确恢复，以及需要哪些硬件

可以恢复的对象： 双Lane能够逐周期、逐bit恢复“重新调度后每拍最多双发射的五槽指令轨迹”。它不能恢复原来某周期含3–5个操作的旧五槽轨迹， 因为重新调度已经改变了发射周期。当前12条最终轨迹的软件编码—解码往返检查全部通过。

8.1 核心硬件

  • Configuration SRAM：5×8192。
  • Lane 0/1 SRAM：各34×4096。
  • 13-bit Configuration PC和两个12-bit Lane指针。
  • 5-bit组合译码器，生成两个Lane valid、slot select和EOP。
  • 两路34-bit到五个34-bit槽的路由网络。
  • 五槽输出寄存器、NOP生成与OP门控。

不需要先进先出缓存队列、时间间隔字典、差值恢复加法器、固定数据包重组或变长比特解析。运行时没有动态调度； 所有节点选择均在编译期完成，硬件只执行固定码本译码、顺序读和定宽路由。

8.2 每周期恢复过程

读取Config[t] → 解码Lane0/Lane1是否有效及目标slot → 有效Lane读取payload[ptr] → 路由到LOAD/STORE/VECTOR/SCALAR/SFU → 有效Lane指针+1，无效Lane保持 → 未选槽输出NOP → EOP结束

Lane流按原周期顺序追加事件；指针只在该Lane有效时递增，因此第t周期读出的事件与编码时第t周期压入的事件一一对应。 同步SRAM可使用Config读取、Lane读取、路由输出的固定流水；流水只增加固定启动延迟，吞吐仍为一恢复周期/拍，无FIFO。

8.3 Bit-exact与低翻转的区别

  • bit-exact模式：无效槽34 bit全部输出零，可与新调度逐bit一致。
  • 行为等价低翻转模式：无效槽payload保持前值，只把OP清零；执行行为逐周期一致，但无关字段不再逐bit相同。

13. 无效槽保持前值的低翻转讨论

无效槽可以保持上一次payload，仅把OP清零，从而避免地址和操作数字段反复在有效值与零之间切换。 它不要求把历史payload重复写入SRAM，只需要五个带使能输出寄存器。

selected[s] = 1：payload_reg[s] ← new payload selected[s] = 0：payload_reg[s]保持，output_op[s] ← 0

该优化保持逐周期执行行为，但不保持无效字段逐bit相同。更重要的是A也可以使用相同机制， 因此它是正交低功耗优化，不能独占计为双Lane收益。最终功耗应让A和双Lane都启用相同保持策略后生成SAIF/VCD。

15.2 一句话核心创新

候选核心： 不再为五类互不等价的功能槽各配置一条物理指令Bank，而是在编译期施加“每拍最多两个原子操作”的硬供给约束， 将五条逻辑槽流折叠到两条同宽共享Lane；编译目标进一步面向多程序代码池的实际SRAM深度、Lane事件分配和2次幂取整， 以固定5-bit配置和简单2-to-5路由实现无FIFO、无变长抽取、无需运行时互锁的逐拍确定性发射。

这里“无需运行时互锁”指依赖、固定操作延迟、功能单元占用和片上资源冲突全部由编译器排定； 硬件在正常片上执行条件下每拍接受下一条新schedule的VLIW。它不表示要保持旧五槽Trace的周期位置， 也不表示异常、复位或外部非确定事件永远不能暂停流水线。

15.3 论文价值

  • 物理价值：不只统计“删除空操作后还剩多少bit”，而是计算这些bit实际应放进几块、多宽、多深的SRAM；对称2×4096工作点相对五个对称槽Bank的粗总面积为−19.67%，池级深度感知4096+2048工作点为−34.93%。
  • 性能价值：硬件虽然每拍最多发射两个操作，周期数却没有按五槽变两槽的最坏比例放大；12条指令轨迹公平比较平均仅+2.03%，最坏+5.58%。
  • 确定性价值：没有运行时调度器、依赖检查表、先进先出缓存下溢或变长数据边界；恢复端只需固定配置译码和把两个输入送到五个输出的路由器。
  • 可替换价值：两个共享操作Bank比五个按功能类型分裂的Bank更容易容纳槽分布不同的新函数；研究目标是固定总容量下有多少新程序能够成功装入，以及浪费多少零散空间。
  • 研究价值：说明即使有效操作携带的信息量相同，SRAM块数、深度向上取整和多个程序的摆放方法仍会造成显著面积差异。

代价必须正面报告：平衡双Lane三程序累计SRAM读能量为+28.52%，深度感知版本仍为+19.97%；因此本文首先是面积/容量论文， 不是“面积、性能、能耗全部更优”的论文。把深Bank拆成可分别关闭的浅子Bank，必须作为后续面积—能耗折中实验。

15.6 四Lane对照实验：同样最多双发射，换用四个浅操作Bank

15.6.1 这不是把发射宽度改成4

每周期仍最多两个有效功能操作，因此DAG依赖、资源冲突和总周期数完全沿用已验证的双发射schedule。 “四Lane”仅表示把有效操作存进四条较浅的34-bit物理事件流；它是新的存储映射和供给组织，不是4-issue VLIW。 三条X64程序的周期数仍为5,475行、有效事件仍为5,766个。

15.6.2 最简硬件：四Lane固定成两组

Group 0 = (Lane0, Lane1) Group 1 = (Lane2, Lane3) 6-bit Config： bit[5] = 本周期选择哪一组 bit[4:0] = 沿用原31种“局部Lane0/1 → 五类slot”映射 6'b111111 = EOP 6'b011111 = 保留/非法 6'b100000 = 非规范的第二个空周期编码，保留/非法 6'b000000 = 唯一合法空周期编码

每周期只允许一个Lane组工作，因此最多读取两块payload SRAM。被选组的两个34-bit输出先经过两个 2:1组选择器，再进入原有2-to-5路由器。所需辅助逻辑为：6-bit配置译码、四个Lane地址计数器、 四路Bank使能、两个34-bit 2:1选择器和原有2-to-5路由；不需要FIFO、运行时依赖检查或4-to-5全交叉开关。 语义状态数为1个空周期 + 4×5个单操作映射 + 2×5×4个双操作映射 = 61； 再加1个EOP共62种状态，因此6 bit仍是最小位宽。两个组的“空周期”语义重复，必须统一使用Group 0， 所以code 32不能作为第二个正常空周期。

15.7 自适应四Lane：从1/2/4容量设想到0–4个直接mask

15.7.1 最可行定义：不设置独立mode字段

如果严格禁止一拍出现3个有效操作，调度器在尝试第3、第4个节点时必须支持资源状态回滚； 否则发出第3个节点后发现第4个不合法，就无法恢复为2操作周期。该限制会增加软件复杂度并损失性能。 最简硬件因此不再保存单独的1/2/4 mode，而是让5-bit mask直接表示0–4个有效操作： 1、2和4操作满足原设想；3操作周期也直接执行，但只开启三块payload SRAM，第四条Lane保持无效并关闭读取。

15.7.2 5-bit mask + 循环Lane相位

Config[4:0] = 五类目标功能槽的有效mask 00000 = 空周期 11111 = EOP（五槽同时发射已被禁止） 本周期payload按LOAD→STORE→VECTOR→SCALAR→SFU的槽号顺序排列 physical_lane = (phase + payload_rank) mod 4 phase_next = (phase + 有效操作数) mod 4

五槽mask除11111外共有31种正常状态，正好加上EOP占满5-bit码空间。 2-bit phase使连续事件循环写入四条Lane，所以三函数池深度自动成为1442/1442/1441/1441。 对任一有效目标槽s，其物理Lane严格为 (phase + popcount(mask中所有低于s的bit)) mod 4。 EOP优先于popcount，禁止所有payload读取和状态更新。

流水与控制流契约： 状态只能在ready/valid接受事件上前进。暂停不仅要冻结Config PC、phase和四个Lane指针， 还必须保持流水中的valid、mask、phase、SRAM使能和输出寄存器。 当前实验是线性指令流；每个函数入口规定phase=0并从描述符装入四个Lane base/limit。 若以后加入分支或循环跳转，必须同时保存/恢复{Config PC, phase, 四个payload位置}。

程序替换的容量判断也必须按Lane进行：每个函数分别从phase=0编码后，把四个Lane长度加入池中， 要求每列累计不超过2048。单看总事件数N≤8192只是必要条件； 多函数分别取整、base对齐和碎片可能使某一Lane先溢出，后续装入实验必须使用四个独立深度约束。

15.7.4 指令生成与确定性恢复

  • 每个选中schedule生成一条5-bit Config流和四条34-bit payload流。
  • 四条Lane总事件数仍为N；循环相位只改变事件归属，不复制payload。
  • 12/12条schedule全部逐周期、逐bit解码回原174-bit五槽行。
  • 三函数池仍需4×2048 payload容量；与前一节分组四Lane具有相同总payload容量，差异在调度宽度和路由。
  • 总逻辑容量为319,488 bit，与通用双Lane相同，比A-symmetric低17.89%，比分组四Lane的327,680 bit低2.50%；若配置SRAM都按8-bit物理字实现，最后一项容量差会消失。

15.7.5 最简辅助逻辑

  • 5×8192 Config SRAM、四个34×2048 payload SRAM。
  • 一个13-bit Config PC、四个11-bit Lane指针和一个2-bit phase状态。
  • 5-bit mask译码、有效位计数及四路独立Bank读使能。
  • 根据mask前缀计数和phase控制的“四路旋转+mask散布”结构；为避免低估，当前按等效4-to-5网络上界估算1530 GE。
  • 总配套逻辑约2064 GE，其中译码/使能180 GE、路由1530 GE、计数器与phase 354 GE。
  • 不需要FIFO、动态依赖判断、变长bit解析或运行时发射仲裁。

15.8 最大风险

  • Kultala 2016已经直接研究“面向变长编码的静态VLIW调度”；本文若没有真实SRAM Bank成本目标和复现实验，会被视为只是增加了“每拍最多两个操作”限制的模板调度。
  • 当前面积来自CACTI和GE粗估，不是目标SRAM compiler与RTL综合。
  • 读能量在平衡/深度感知版本中分别增加28.52%/19.97%，不能宣称全面PPA更优。
  • 每workload选择策略可能在12例上过拟合，需要更多函数与shape验证。
  • 联合调度不再保持旧五槽Trace原周期，问题已从纯后处理压缩变成ISA/调度/代码存储协同设计。

当前方向已达到“继续做RTL/真实宏kill test”的门槛，但尚未达到“核心创新已经成立”的门槛。 最稳妥主张是容量、面积和可替换布局；能耗必须作为明确代价或后续优化目标。

16. 下一步工作与判定标准

  1. 目标SRAM compiler：获得5×8192、34×1024、34×2048、34×4096及可分Bank版本的真实面积、延迟、泄漏和读能量。
  2. 参数化RTL：实现A-symmetric、双Lane、分组四Lane和自适应四Lane；重点综合5-bit mask、phase、4-to-5路由与逐Lane读使能。
  3. 周期对拍：同步SRAM固定流水下逐周期比较新调度五槽输出，并验证无下溢、无同槽冲突。
  4. 完整功能验证：新调度与旧五槽设计最终数值输出一致。
  5. 能耗Pareto：优先对拍本轮四Lane工作点；原计划的单Lane内部拆成2048+1024子Bank方案按当前决定暂缓。
  6. 调度升级：将pair-aware改为可回滚资源试发射或小宽度beam search，显式计入Bank冲突、active-state和后继解锁。
  7. Kultala适配基线：目标函数级复现已完成；若投稿需要完整算法对拍，应让调度器导出node-to-cycle映射，再实现ASAP/ALAP移动与全部资源合法性重放。
  8. 物理成本入环：先把单操作事件的Lane选择、两条Lane各自深度和2次幂取整放入池布局目标；只有当DAG调度能改变T或双操作周期数时，再加入复杂调度搜索。
  9. 高利用率与程序替换实验：增加每拍3/4操作占比明显更高的DAG，并模拟函数装入/移除，比较A、双Lane、分组四Lane和自适应四Lane的性能、碎片与成功装入率。
  10. 继续查新：重点搜索replaceable VLIW code store、physical bank-depth-aware scheduling、bank folding和deterministic instruction supply。

继续条件

  • 真实SRAM+RTL面积仍下降至少15%。
  • 平均周期损失≤3%，最坏≤6%。
  • 更多workload上无需每条Trace人工调参。
  • 能耗得到明显改善，或系统级面积—能耗权衡可接受。

停止条件

  • 目标宏下面积收益低于10%。
  • 路由/时钟功耗进一步放大能耗劣势。
  • 新颖性退化为普通2-wide VLIW。
  • 程序替换需求无法成为可信应用场景。
